# 자바 컬렉션 프레임워크 실습

**학습 목표:** 자바가 제공하는 대표적인 컬렉션의 종류와 계보를 파악하고, 그 컬렉션들이 제공하는 서비스의 차이를 이해하며 간단히 사용해본다. 모든 컬렉션을 다 다루는 게 아니라, 계보 속에서 대표적인 몇 가지만 실습하며 식견을 넓히는 시간이다.

## 1. 컬렉션 프레임워크 계보

자바 컬렉션은 크게 단일 원소들의 집합을 다루는 **Collection 계열**과, 키-값 쌍을 다루는 **Map 계열** 두 축으로 나뉜다.

```
Iterable
 └── Collection
      ├── List (순서 O, 중복 O)
      │    ├── ArrayList
      │    └── LinkedList
      ├── Set (순서 X, 중복 X)
      │    ├── HashSet
      │    └── TreeSet
      └── Queue (FIFO 순서 관리)
           ├── LinkedList
           ├── PriorityQueue
           └── ArrayDeque (Deque)

Map (Key-Value 매핑 / 독립 계열)
 ├── HashMap
 ├── LinkedHashMap
 └── TreeMap
```

**Map은 `Collection`을 상속받지 않는 독립적인 구조**라는 점이 중요하다 — List·Set·Queue는 전부 `Collection`의 자식이지만, Map은 Key-Value 쌍(Entry)을 다루는 별개의 최상위 인터페이스다.

## 2. Collection 계열의 공통 기반 — `Iterable`

`Collection`은 최상위로 `java.lang.Iterable`을 상속받아 `iterator()`를 통한 순회가 가능한 구조다. iterator/iterable이 정확히 뭔지는 나중에 스레드를 다룰 때 자세히 설명하고, 지금은 "컬렉션에 담긴 요소를 순회하는 데 쓰이는 역할 객체" 정도로만 이해하면 된다.

모든 컬렉션은 iterator 객체를 반환하도록 구현되어 있어서, 다음과 같은 `foreach` 문으로 아이템을 쉽게 꺼낼 수 있다.

```java
for (아이템 : iterator 객체를 반환하는 컬렉션)
    아이템 사용
```

```java
List<String> items = new ArrayList<>();
items.add("Hello");

for (String item : items) {
    System.out.println(item); // 인덱스가 없는 Set도 동일한 방식으로 순회 가능
}
```

## 3. List 인터페이스 — 순서 유지, 중복 허용

**핵심 특징:** 원소의 저장 순서가 유지되며, 동일한 원소의 중복 저장을 허용한다. 인덱스(Index)로 각 요소에 접근한다.

- **`ArrayList`**: 내부적으로 배열을 이용하며 공간이 부족하면 동적으로 늘려준다. 인덱스로 검색할 때는 빠르지만, 중간 데이터 추가/삭제 시 오버헤드가 발생한다.
- **`LinkedList`**: 이중 연결 리스트 구조. 데이터 추가/삭제가 빠르지만, 인덱스 검색이 느리다.

## 4. Set 인터페이스 — 순서 미보장, 중복 불허

**핵심 특징:** 원소의 저장 순서를 보장하지 않으며, 수학적 집합과 같이 중복 저장을 허용하지 않는다.

- **`HashSet`**: 해시 테이블 기반. 가장 빠르며 순서를 전혀 보장하지 않는다.
- **`LinkedHashSet`**: 해시 테이블 + 이중 연결 리스트. 중복을 배제하면서도 삽입 순서를 유지한다.
- **`TreeSet`**: 이진 탐색 트리(Red-Black Tree) 기반. 원소를 정렬된 순서(오름차순/내림차순)로 보관한다.

## 5. Queue 인터페이스 — 선입선출(FIFO)

**핵심 특징:** 데이터의 선입선출(FIFO, First-In-First-Out) 처리를 기본 목적으로 한다.

- **`ArrayDeque`**: 원형 배열 기반 양방향 큐(Deque). 스택(Stack)과 큐 양쪽 용도 모두에서 `LinkedList`보다 메모리 효율과 속도가 뛰어나다.
- **`PriorityQueue`**: 힙(Heap) 구조 기반. 들어간 순서와 상관없이 우선순위가 높은 데이터가 먼저 나온다.

## 6. Map 인터페이스 — 독립 계열, Key-Value 매핑

`Collection`을 상속받지 않는 독립적인 구조로, Key(키)와 Value(값)의 쌍(Entry)으로 데이터를 관리한다.

**핵심 특징:**
- Key는 중복 불가 (내부적으로 Set 구조를 이룬다)
- Value는 중복 허용

주요 구현체:
- **`HashMap`**: 해시 테이블 기반. Key-Value 검색/삽입이 빠르다. 순서 보장 없음.
- **`LinkedHashMap`**: 해시 테이블 + 링크드 리스트. Key-Value의 삽입 순서를 유지한다.
- **`TreeMap`**: Red-Black Tree 기반. Key를 기준으로 자동 정렬되어 저장된다.

## 7. 계보별 기술적 특성 비교

| 계열 | 최상위 인터페이스 | 순서 보장 | 중복 허용 | 인덱스 접근 | 대표 사용 목적 |
|---|---|---|---|---|---|
| List | Collection | 보장 (인덱스 기반) | 허용 | 가능 | 순차적 데이터 저장, 조회 위주 |
| Set | Collection | 미보장 (구현체별 상이) | 불가 | 불가 | 고유 식별자 관리, 중복 필터링 |
| Queue | Collection | FIFO 순서 | 허용 | 불가 | 순차 대기열, 비동기 작업 버퍼 |
| Map | Map | 미보장 (구현체별 상이) | Key 불가 / Value 허용 | Key로 접근 | 속성 매핑, 집계 및 캐싱 |

## Step 1. List(`ArrayList`) — 순서가 있는 목록 관리

**필요성:** 사용자가 상품을 장바구니에 담는 순서대로 유지해야 하고, 동일한 상품을 여러 번 담는(중복 허용) 동작이 가능해야 한다.

```java
import java.util.ArrayList;
import java.util.List;

public class Step1_ListExample {
    public static void main(String[] args) {
        // 1. List 생성 및 요소 추가
        List<String> cart = new ArrayList<>();
        cart.add("키보드");
        cart.add("마우스");
        cart.add("모니터");
        cart.add("마우스"); // 중복 데이터 허용

        // 2. 데이터 순회 출력
        System.out.println("=== 장바구니 목록 ===");
        for (int i = 0; i < cart.size(); i++) {
            System.out.println((i + 1) + ". " + cart.get(i));
        }

        // 3. 요소 삭제
        cart.remove("마우스"); // 첫 번째 발견된 마우스 삭제
        System.out.println("\n마우스 1개 삭제 후 크기: " + cart.size());
    }
}
```

**기술적 특징:** 내부적으로 배열을 사용하여 인덱스 기반의 빠른 접근을 지원한다. 요소의 추가/삭제가 빈번할 경우 데이터 이동 오버헤드가 발생한다.

## Step 2. Set(`HashSet`) — 중복 제거 및 고유값 관리

**필요성:** 장바구니에 담긴 품목 중 중복을 제거한 순수 주문 품목 종류를 추출해야 하고, 이벤트 쿠폰 코드 적용 시 1인 1회 제한 같은 유일성을 보장해야 한다.

```java
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Set;

public class Step2_SetExample {
    public static void main(String[] args) {
        // 1. 중복이 포함된 리스트 준비
        List<String> cart = new ArrayList<>();
        cart.add("키보드");
        cart.add("마우스");
        cart.add("키보드");

        // 2. Set 변환을 통한 중복 제거
        Set<String> uniqueItems = new HashSet<>(cart);

        // 3. 출력 (순서 보장되지 않음)
        System.out.println("=== 고유 주문 품목 ===");
        for (String item : uniqueItems) {
            System.out.println("- " + item);
        }

        // 4. 중복 추가 시도 검증
        boolean isAdded = uniqueItems.add("키보드");
        System.out.println("\n키보드 재추가 성공 여부: " + isAdded); // false 반환
    }
}
```

**기술적 특징:** 해시 알고리즘 기반으로 중복을 허용하지 않는다. 순서를 유지하지 않으며, `hashCode()`와 `equals()` 메서드를 통해 동등성 비교를 수행한다.

## Step 3. Map(`HashMap`) — Key-Value 매핑 관리

**필요성:** 단순히 상품명만 나열하는 게 아니라 "상품명(Key) : 수량(Value)" 구조로 데이터를 집계해야 하고, 상품 고유 식별자를 통한 빠른 데이터 조회가 필요하다.

```java
import java.util.HashMap;
import java.util.Map;

public class Step3_MapExample {
    public static void main(String[] args) {
        // 1. Map 생성 (상품명 : 수량)
        Map<String, Integer> itemCounts = new HashMap<>();

        // 2. 데이터 추가 및 수정
        itemCounts.put("키보드", 1);
        itemCounts.put("마우스", 2);

        // 3. 수량 누적 갱신 (getOrDefault 활용)
        itemCounts.put("키보드", itemCounts.getOrDefault("키보드", 0) + 1);

        // 4. Map 데이터 순회
        System.out.println("=== 상품별 주문 수량 ===");
        for (Map.Entry<String, Integer> entry : itemCounts.entrySet()) {
            System.out.println("상품: " + entry.getKey() + ", 수량: " + entry.getValue());
        }

        // 5. 단일 조회
        System.out.println("\n키보드 총 수량: " + itemCounts.get("키보드"));
    }
}
```

**기술적 특징:** Key는 중복 불가(Set 구조), Value는 중복 허용이다. Key 해시 충돌 시 내부적으로 `LinkedList` 또는 Red-Black Tree 형태로 노드를 관리한다.

## Step 4. Queue(`LinkedList`) — 선착순 처리

**필요성:** 한정 수량 특가 상품에 대해 먼저 결제를 요청한 사용자를 순서대로 처리(FIFO, First-In-First-Out)해야 한다.

```java
import java.util.LinkedList;
import java.util.Queue;

public class Step4_QueueExample {
    public static void main(String[] args) {
        // 1. Queue 생성
        Queue<String> orderQueue = new LinkedList<>();

        // 2. 주문 요청 인입 (offer)
        orderQueue.offer("주문-001 (UserA)");
        orderQueue.offer("주문-002 (UserB)");
        orderQueue.offer("주문-003 (UserC)");

        // 3. 순차 처리 (poll)
        System.out.println("=== 결제 대기열 처리 ===");
        while (!orderQueue.isEmpty()) {
            String currentOrder = orderQueue.poll();
            System.out.println("처리 완료: " + currentOrder);
        }
    }
}
```

**기술적 특징:** FIFO 구조를 보장한다. `offer()`, `poll()`, `peek()` 메서드를 사용해 예외 발생 대신 `null` 또는 `false`를 반환하는 방식으로 제어한다.

## 8. 핵심 인터페이스 비교 요약

| 인터페이스 | 중복 허용 | 순서 유지 | 주요 구현체 | 사용 사례 |
|---|---|---|---|---|
| List | 허용 | 유지 | ArrayList, LinkedList | 일반 목록, 순서가 중요한 시퀀스 |
| Set | 불가 | 미유지 | HashSet, TreeSet | 중복 제거, 고유 식별자 집합 |
| Map | Key 불가, Value 허용 | 미유지 | HashMap, TreeMap | 속성 매핑, 집계 및 캐싱 |
| Queue | 허용 | 선입선출 (FIFO) | LinkedList, ArrayDeque | 순차 대기열, 비동기 작업 처리 |
