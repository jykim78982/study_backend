# 자바 8 스트림 연재 1편: 람다 표현식과 함수형 인터페이스

## 1. 자바 8: 시대 변화에 따른 자바 언어의 변화

데이터의 규모가 커지고 데이터를 분석해야 할 필요성이 커지면서 그런 API의 중요성이 높아졌습니다. 그러나 기존 자바(Java 8 이전)에는 이러한 데이터 처리를 위한 언어적 장치가 매우 빈약했습니다. 반복문(`for`, `while`)과 조건문(`if`)으로 모든 로직을 구현해야 했으며, "이 데이터를 이렇게 변환해 줘"라는 의도를 코드에 직접 표현하기 어려웠습니다.

그래서 자바는 그런 것들을 지원하기 위해 메이저 버전의 변화를 가지게 되었는데, 그 버전이 바로 자바 8입니다. 자바 8에서의 주요 변화는 데이터 처리를 전문으로 하는 스트림 API를 추가한 부분이 가장 주요하며 그것을 지원하기 위해 추가적인 변화가 있었습니다.

스트림 API는 데이터 분석을 쉽게 처리할 수 있도록 일련의 연산(필터링, 변환, 집계 등)을 파이프라인 방식을 채택하고 있어서, 반복문 대신 선언적 코드로 의도를 명확히 표현할 수 있도록 하고 있습니다.

예를 들어, 정수 배열에서 20 이상인 값만 골라 2배로 변환하는 작업을 스트림으로 표현하면 코드는 다음처럼 작성할 수 있습니다.

```java
int[] numbers = {10, 25, 15, 30, 5};

int[] result = Arrays.stream(numbers)
    .filter(n -> n >= 20)   // 20 이상인 값만 필터링
    .map(n -> n * 2)        // 각 값에 2를 곱함
    .toArray();             // 결과 배열로 변환

// 결과: [50, 60]
```

이를 통해 "데이터를 이렇게 변환해 줘"라는 의도가 반복문과 조건문의 나열 대신, 읽기 쉬운 연산의 연속으로 표현됩니다.

자바 8에서 이런 방식의 코드를 가능하게 하는 스트림 API를 효과적으로 활용할 수 있도록 다음과 같은 주요 기능들이 함께 도입되었습니다.

- **람다 표현식(Lambda Expression)**: 반복문이나 익명 클래스 대신, 짧은 코드 블록으로 로직을 표현하고 전달할 수 있게 합니다.
- **메서드 참조(Method Reference)**: 기존에 존재하는 메서드를 람다 표현식처럼 인자로 전달할 수 있게 하여 코드를 더 간결하게 만듭니다.
- **함수형 인터페이스(Functional Interface)**: 추상 메서드가 하나인 인터페이스로, 람다 표현식이 구현할 대상이 됩니다. `Predicate`, `Function`, `Comparator` 등 스트림 연산에 사용되는 표준 함수형 인터페이스들이 이 범주에 포함됩니다.
- **옵셔널(Optional)**: `null`을 반환하는 대신, 값이 존재하는지 여부를 명시적으로 표현하는 객체를 제공하여 `NullPointerException`을 방지하고 코드의 가독성을 높입니다.
- **디폴트 메서드(Default Method)**: 인터페이스에 구현체가 있는 메서드를 정의할 수 있게 하여, 기존 인터페이스에 새 메서드를 추가할 때 하위 호환성을 유지할 수 있게 합니다.
- **새로운 날짜 및 시간 API**: 기존 `java.util.Date`와 `Calendar`의 한계를 보완하고, 더 직관적이고 일관된 날짜·시간 처리를 위한 `java.time` 패키지를 제공합니다.
- **반복자(Iterator) 개선**: `forEach`와 `spliterator` 메서드를 추가하여 컬렉션의 요소를 더 유연하게 순회할 수 있게 합니다.

이번 노트에서는 스트림 API를 효과적으로 활용하기 위해 자바 8에서 함께 도입된 기능 중 람다 표현식, 메서드 참조, 함수형 인터페이스 세 가지에 대해 자세히 살펴보겠습니다.

## 2. 자바 언어의 한계

자바에는 데이터를 정렬하는 `Arrays.sort` 메서드가 존재합니다. `Integer[]` 배열을 오름차순으로 정렬하는 것은 매우 간단합니다.

```java
Integer[] ages = {23, 19, 30, 21};
Arrays.sort(ages);
// 결과: [19, 21, 23, 30]
```

하지만 만약 내림차순으로 정렬하고 싶다면 `Arrays.sort`에는 "내림차순으로 해줘"라고 말하는 매개변수가 없고, 그 대신, 어떻게 비교할지 알려주는 코드(operation)를 넘겨야 합니다. 이 순간, 우리는 "비교하는 로직" 자체를 메서드에 전달해야 하는 벽에 부딪힙니다. 왜냐하면 자바에는 연산식을 전달하는 비용이 비싸기 때문입니다.

## 3. 함수를 넘길 수 없는 자바의 제약

만약에 두 값을 전달 받아서 그것을 비교하는 다음과 같은 코드를 `Arrays.sort`에 전달해야 한다면, 다른 언어에서는 `Arrays.sort(ages, compare);`처럼 값을 비교하는 함수를 전달할 수 있었을 겁니다.

```java
public int compare(Integer o1, Integer o2) {
    return o2 - o1; // 내림차순: 큰 값이 앞에 오도록
}
```

하지만 자바에서는 완전한 객체지향을 표방하기 때문에 메서드가 클래스 밖에서 독단적으로 존재할 수가 없습니다. 그래서 함수 자체가 독단적으로 전달될 수도 없습니다.

"비교하는 로직"을 전달하려면, 그 로직을 포함하는 객체를 만들어야 합니다. 그리고 자바에서는 객체를 전달할 때는 그것을 받는 쪽에서 그 객체를 참조할 수 있는 형식으로 선언되어 있어야만 합니다.

만약에 위와 같은 `compare` 함수를 전달하려면 그 함수를 약속으로 정의한 인터페이스가 중계자 역할을 해야만 합니다. 실제로 `Arrays.sort` 메소드에도 정렬을 위한 연산 함수를 약속으로 정의한 `Comparator` 인터페이스를 가지고 있고 내가 원하는 정렬을 하려면 그것을 구현하는 클래스를 만들어야만 합니다.

```java
public class DescendingComparator implements Comparator<Integer> {
    @Override
    public int compare(Integer o1, Integer o2) {
        return o2 - o1; // 내림차순: 큰 값이 앞에 오도록
    }
}

// 사용
Arrays.sort(ages, new DescendingComparator());
```

여기서 핵심적인 비용은 의미 있는 코드는 `return o2 - o1;` 한 줄뿐인데, 그것을 감싸기 위해 클래스를 하나 새로 만들어야 한다는 점입니다.

## 4. 익명 클래스: 포장을 한 겹 줄여도 여전히 부담

물론 클래스를 따로 만들지 않고, 사용하는 자리에서 바로 정의하는 익명 클래스(Anonymous Class)를 사용할 수 있기는 합니다.

```java
Arrays.sort(ages, new Comparator<Integer>() {
    @Override
    public int compare(Integer o1, Integer o2) {
        return o2 - o1;
    }
});
```

이렇게 하면 클래스 파일을 하나 만들 필요는 없지만, 여전히 `new Comparator<Integer>() { ... }`라는 긴 문법과 `@Override`, `public int compare` 같은 불필요한 선언이 눈앞에 놓여 있습니다. 정작 우리가 전달하고 싶은 것은 `o2 - o1`이라는 동작뿐인데, 자바는 그것을 객체로 포장해서 전달하게 합니다.

## 5. 역사적 맥락: 람다 대수에서 자바 8까지

"단순한 동작을 전달하는 짧은 표현"은 자바만의 발명이 아닙니다.

- **1930년대**: 수학자 알론조 처치(Alonzo Church)가 람다 대수(Lambda Calculus)를 제안하며 함수를 일급 시민(First-class Citizen)으로 다루는 이론적 기반을 마련했습니다.
- **1958년**: 리스프(Lisp)가 람다 대수의 개념을 프로그래밍 언어로 구현하며 함수형 프로그래밍의 시대를 열었습니다.
- **2009년**: 자바는 Project Lambda를 통해 이 흐름에 합류했습니다. 자바는 새로운 함수 타입을 만들지 않고, 기존에 있던 `Runnable`, `Comparator` 같은 인터페이스를 그대로 살리되, 그 구현을 훨씬 간결하게 표현할 수 있는 문법을 도입했습니다.
- **2014년**: Java 8에 람다 표현식(Lambda Expression)이 정식 도입되었습니다.

자바의 람다는 본질적으로 객체를 넘기되, 함수를 넘기는 것처럼 보이게 한 표현식입니다.

## 6. 람다 표현식: 불필요한 것을 걷어내다

익명 클래스에서 타입 선언, `new` 키워드, 메서드 시그니처를 차례로 제거하면 람다 표현식이 됩니다.

**변화 과정:**

1. `new Comparator<Integer>() { public int compare(Integer o1, Integer o2) { return o2 - o1; } }`
2. `(Integer o1, Integer o2) -> { return o2 - o1; }` (타입은 컴파일러가 추론 가능하므로 생략 가능)
3. `(o1, o2) -> o2 - o1`

**최종 코드:**

```java
Arrays.sort(ages, (o1, o2) -> o2 - o1);
```

이제 우리는 `Comparator` 객체를 만드는 과정 없이, 오직 비교 로직만 전달합니다.

## 7. 람다 축약 규칙

람다 표현식은 다음과 같은 규칙으로 축약될 수 있습니다.

- **매개변수 타입 생략**: 인터페이스의 추상 메서드 시그니처를 통해 타입을 추론할 수 있으므로 생략 가능합니다.
- **괄호 생략**: 매개변수가 하나일 경우, 괄호를 생략할 수 있습니다. (예: `x -> x * 2`)
- **중괄호 및 `return` 생략**: 본문이 한 줄의 표현식일 경우, 중괄호 `{}`와 `return` 키워드를 생략할 수 있습니다.

## 8. 문자열 정렬과 오버플로 문제

`Integer[]`에서는 `o2 - o1`로 비교할 수 있었지만, `String[]`에서는 뺄셈 연산자가 없습니다. 문자열은 `compareTo` 메서드를 사용해야 합니다.

```java
String[] names = {"Banana", "Apple", "Cherry"};
Arrays.sort(names, (a, b) -> b.compareTo(a)); // 내림차순
```

여기서 중요한 점은 비교는 연산자가 아니라 함수라는 것입니다. 또한, `Integer`의 `o2 - o1` 방식은 값이 매우 크거나 작을 경우 오버플로로 인해 부호가 뒤집혀 잘못된 정렬 결과를 낼 수 있습니다. `Integer.compare(o2, o1)` 또는 람다 내부에서 `Integer.compare`를 호출하는 것이 더 안전합니다.

## 9. 메서드 참조: 이름만 넘기기

람다 본문이 이미 존재하는 메서드를 그대로 호출하기만 한다면, 메서드 참조(Method Reference)로 더 짧게 줄일 수 있습니다.

```java
String[] names = {"Banana", "Apple", "Cherry"};

// 람다 표현식 사용
Arrays.sort(names, (a, b) -> a.compareTo(b));

// 메서드 참조 사용
Arrays.sort(names, String::compareTo);
```

이 구조는 첫 번째 매개변수(`a`)가 객체(인스턴스)가 되고, 두 번째 매개변수(`b`)가 그 객체의 메서드 파라미터로 전달되는 형태입니다. 즉, `String` 클래스의 특정 인스턴스 메서드를 호출하되, 그 대상(임의의 객체)을 람다의 첫 번째 인자로 지정하겠다는 의미입니다. 이를 "임의 객체의 인스턴스 메서드 참조"라고 부릅니다.

메서드 참조는 람다 표현식의 특수한 형태로, 특정 메서드를 참조하는 객체를 생성합니다.

## 10. Exam 클래스: 직접 정의한 비교 기준

`Exam` 클래스를 데이터로 사용할 경우에는 객체가 가지는 어떤 속성을 기반으로 정렬하게 할지가 중요합니다.

```java
public class Exam {
    private int kor;
    private int eng;
    private int math;

    public Exam(int kor, int eng, int math) {
        this.kor = kor;
        this.eng = eng;
        this.math = math;
    }

    public int getTotal() {
        return kor + eng + math;
    }
}
```

만약에 총점을 기준으로 정렬하고 싶다면, 람다에서 `getTotal()`을 호출하면 됩니다.

```java
Exam[] exams = { new Exam(90, 80, 70), new Exam(100, 90, 80) };
Arrays.sort(exams, (e1, e2) -> e2.getTotal() - e1.getTotal());
```

또한, `Exam` 클래스에 비교 로직을 구현하는 메서드를 직접 포함해 둔다면, 다음처럼 `Comparator`를 거치지 않고 메서드 참조로 더 깔끔하게 구현할 수도 있습니다.

```java
public class Exam {
    // ... 기존 필드와 생성자, getTotal() 메서드 ...

    // 총점 기준으로 내림차순 비교를 수행하는 메서드
    public int compareByTotal(Exam other) {
        return Integer.compare(other.getTotal(), this.getTotal());
    }
}

// 사용: Exam::compareByTotal은 Comparator<Exam>와 동일한 시그니처를 가지므로 메서드 참조로 전달 가능
Arrays.sort(exams, Exam::compareByTotal);
```

## 11. 함수형 인터페이스의 조건: 추상 메서드 하나

스트림 API는 사용자의 결정이 필요한 경우 넘겨 받기 위한 수많은 인터페이스를 정의해 놓고 있습니다. 그 인터페이스는 람다식을 이용해서 함수 스타일(Functional Style)의 객체로 변화를 갖게 되는데요.

만약에 람다식으로 사용할 목적으로 인터페이스를 작성하는 경우라면 반드시 지켜야 할 규약이 있습니다. 바로 람다식을 위한 인터페이스는 하나의 함수만 정의해야 한다는 것입니다.

그런데 가끔 그것을 어기는 경우가 종종 있어 왔는데요. 그것을 미연에 방지할 수 있도록 하는 기능이 자바 8에 추가되었는데, 그것을 함수형 인터페이스(Functional Interface)라고 합니다.

만약 람다식으로 사용할 인터페이스를 정의하면서 다음처럼 두 개 이상의 함수를 정의한다면 바로 오류를 만나지 않고 나중에 람다식으로 사용할 때 오류를 만나게 됩니다.

```java
// 에러 예시
interface BadFunctional {
    void method1();
    void method2();
}

// BadFunctional f = () -> { }; // 컴파일 에러: 어떤 메서드를 구현하는지 모호함
```

## 12. @FunctionalInterface: 안전장치

하지만 람다식으로 표현할 함수형 인터페이스에 `@FunctionalInterface` 애노테이션을 붙이면, 컴파일러가 추상 메서드가 하나인지 바로 검증해 줍니다.

```java
@FunctionalInterface
interface GoodFunctional {
    void method1();
    // void method2(); // 이 줄을 주석 해제하면 컴파일 에러 발생
}
```

이 애노테이션이 없으면, 나중에 인터페이스에 추상 메서드가 하나 더 추가될 때, 기존에 람다로 사용하던 코드는 깨지지만, 애노테이션이 없으면 컴파일 에러가 나지 않아 버그가 생길 수 있습니다. `@FunctionalInterface`는 이러한 위험을 선언부에서 막아주는 안전장치입니다.

## 13. 람다를 변수에 담고 전달하기

람다 표현식은 변수에 담을 수 있으며, 메서드의 인자로 전달할 수 있습니다.

```java
Comparator<Integer> descComparator = (o1, o2) -> o2 - o1;
Arrays.sort(ages, descComparator);
```

이러한 방식이 가능해야만, 스트림 API의 `filter`, `map`, `sorted` 같은 메서드들이 동작할 수 있습니다. 스트림의 각 연산은 내부적으로 함수형 인터페이스(`Predicate`, `Function`, `Comparator` 등)를 인자로 받으며, 우리는 람다 표현식으로 그 로직을 전달합니다.

- `Predicate<T>`: `boolean`을 반환하는 함수형 인터페이스 (`filter`에 사용)
- `Function<T, R>`: `T`를 받아 `R`을 반환하는 함수형 인터페이스 (`map`에 사용)

이러한 표준 함수형 인터페이스들의 구체적인 사용법은 2편에서 다룹니다.
