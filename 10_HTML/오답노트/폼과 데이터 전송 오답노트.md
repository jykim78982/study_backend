# 폼과 데이터 전송 오답노트

### 1. 같은 name을 가진 체크박스 여러 개는 서버에 어떻게 전달되는가

**문제**: 같은 name을 가진 체크박스 여러 개를 사용하면 서버에는 어떻게 전달되는가?

1. 각 체크박스마다 name이 자동으로 변경되어 전송된다.
2. 동일한 키로 여러 값(배열) 형태로 전송된다.
3. 서버로는 전송되지 않는다.
4. 가장 먼저 체크된 값만 전송된다.

**정답: 2번**

- 폼 전송은 `name=value` 쌍의 나열이다. 여러 요소가 같은 `name`을 쓰면 브라우저는 이름을 자동으로 바꾸지 않고, 체크된 항목 각각의 값을 같은 키로 그대로 실어 보낸다.
  ```html
  <input type="checkbox" name="hobby" value="sports">
  <input type="checkbox" name="hobby" value="music">
  ```
  두 개 다 체크하면 요청 본문은 `hobby=sports&hobby=music`처럼 같은 키가 반복되는 형태가 된다.
- 이 "같은 키가 여러 번 오는" 형태를 배열/리스트(`String[]`, `List<String>` 등)로 조립하는 건 **서버(백엔드 프레임워크)의 파싱 책임**이지, HTTP 자체가 배열이라는 자료구조를 갖고 있는 게 아니다 — 브라우저는 그냥 같은 이름의 쌍을 여러 개 나열해서 보낼 뿐이다.

### 2. `<button>` 요소의 name·value는 언제 전송되는가

**문제**: 버튼 요소에 name과 value를 주고 제출하면 어떤 경우에 그 값이 서버로 전송되는가?

1. 자바스크립트가 있어야만 전송된다.
2. 사용자가 그 버튼으로 폼을 제출했을 때만 전송된다.
3. 버튼은 데이터를 전송하지 못한다.
4. 항상 모든 버튼의 name/value가 전송된다.

**정답: 2번**

- [[044_HTML 폼 요소 다루기]] 6절에서 정리했듯 `<button type="submit">`도 폼을 전송하는 인라인 태그다. 여기에 `name`/`value`를 주면, 그 버튼은 단순히 "제출 트리거" 역할을 넘어서 **"어느 버튼으로 제출했는지"까지 폼 데이터의 일부로 함께 보낼 수 있다.**
  ```html
  <button name="action" value="save">저장</button>
  <button name="action" value="delete">삭제</button>
  ```
- 한 폼 안에 제출 버튼이 여러 개 있어도, 실제로 **클릭해서 제출을 발생시킨 버튼 하나의 `name=value`만** 전송된다. 클릭되지 않은 다른 버튼의 `name`/`value`는 애초에 폼 데이터에 포함되지 않는다 — 하나의 폼으로 "저장"과 "삭제"처럼 서로 다른 동작을 구분해서 처리하고 싶을 때 쓰는 방식이다.

### 3. `<option>`의 value가 빈 문자열이면 서버에는 무엇이 전송되는가

**문제**: select 요소에서 option의 value가 비어있으면 서버에는 무엇이 전송되는가?

1. 브라우저마다 무작위 값이 전송된다.
2. 해당 옵션은 전송되지 않는다.
3. 표시 텍스트가 자동으로 전송된다.
4. 빈 문자열("")이 전송된다.

**정답: 4번**

- [[044_HTML 폼 요소 다루기]] 10절·12절에서 다룬 "화면에 보이는 텍스트와 실제 전송값은 다르다"는 원칙이 여기서도 그대로 적용된다. `value`를 **명시적으로 빈 문자열로 지정**하면(`<option value="">선택하세요</option>`) 그 옵션이 선택된 채 제출됐을 때 서버에는 `키=` 형태로 빈 문자열이 그대로 전송된다.
- 헷갈리기 쉬운 지점: `value` 속성을 아예 생략한 경우(`<option>선택하세요</option>`)는 다르다 — 12절에서 정리한 select `required` 우회 함정과 같은 원리로, 이때는 `<option>` 태그 안의 **텍스트 자체가 value로 채워져** 전송된다. 즉 "value를 빈 문자열로 명시"와 "value를 아예 생략"은 결과가 다르므로, "미선택" 상태를 서버가 빈 문자열로 판단하게 하려면 `value=""`를 반드시 명시해야 한다.

### 4. 파일 입력(`<input type="file">`)의 실제 데이터는 어떻게 전달되는가

**문제**: 파일 입력의 실제 파일 데이터는 name=value 형태로 서버에 어떻게 전달되는가?

1. 파일은 전송되지 않고 서버에서 직접 읽는다.
2. `multipart/form-data` 본문에서 해당 name으로 파일 바이트가 전송된다.
3. GET 쿼리 문자열로 인코딩되어 전송된다.
4. 파일 경로 문자열만 name으로 전송된다.

**정답: 2번**

- 텍스트값은 `key=value`를 `&`로 이어 붙이는 방식(`application/x-www-form-urlencoded`)으로도 충분하지만, 파일은 대용량 바이너리 데이터라 이 방식으로 표현할 수 없다. 그래서 파일을 보내는 폼은 `enctype="multipart/form-data"`를 지정해야 한다.
  ```html
  <form method="post" enctype="multipart/form-data">
    <input type="file" name="img-src">
  </form>
  ```
- `multipart/form-data`는 요청 본문을 여러 "파트(part)"로 나누는 형식이고, 각 파트에는 어떤 필드인지 식별하는 이름이 붙는다 — 이때 그 식별자가 바로 `input`의 `name` 속성이다. 서버는 이 `name`을 키로 삼아 해당 파트의 실제 바이트 스트림(파일 내용)을 읽어들인다.
- [[013_servlet 실습 — 메뉴 등록(Create) 기능과 퍼블리싱 연동]] 2·3절에서 다룬 `create.jsp`의 이미지 입력은 실제로는 `type="file"`이 아니라 `type="text" name="img-src"`(파일 경로 문자열만 받는 방식)로 단순화되어 있었다 — 실제 파일 업로드(`multipart/form-data`)를 구현하려면 폼의 `enctype`부터 바꿔야 한다는 걸 짚어주는 사례다.

### 5. 같은 name을 가진 텍스트 input과 select가 함께 있으면 서버에는 어떻게 보이는가

**문제**: 같은 폼 내에서 동일한 name을 가진 텍스트 input과 select가 동시에 있으면 서버에는 어떻게 보이는가?

1. 브라우저가 충돌을 방지해 둘 다 전송하지 않는다.
2. 서버에서 값의 덮어쓰기 순서가 보장되지 않아 에러가 발생한다.
3. 둘 중 하나만 무작위로 전송된다.
4. 둘 다 같은 키로 전송되어 서버 파싱에 따라 처리된다.

**정답: 4번**

- 1번 문제(체크박스)와 원리가 동일하다 — 브라우저는 **태그 종류(`input`인지 `select`인지)를 구분해서 걸러내지 않는다.** 폼 데이터를 모을 때는 오직 `name`이 있는지, 그 요소가 값을 갖고 있는지만 본다. 태그 종류가 서로 달라도 `name`이 같으면 둘 다 같은 키로 전송된다.
- 에러가 나거나(2번) 무작위로 하나만 뽑히는(3번) 게 아니라, 1번 문제와 마찬가지로 "같은 키가 여러 번 온 요청"이 그대로 서버에 도달하고, 이를 배열로 모을지 마지막 값으로 덮어쓸지는 **서버 쪽 프레임워크의 파싱 규칙**에 달려 있다.
- 그래서 실무에서는 의도치 않게 같은 `name`이 겹치지 않도록 폼 안의 `name` 값을 고유하게 설계하는 게 중요하다 — [[044_HTML 폼 요소 다루기]] 9절에서 정리한 "`name`은 서버와 클라이언트가 공유하는 계약"이라는 원칙과 이어지는 지점이다.
