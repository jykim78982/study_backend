# 인라인 태그 27종 — 쓰임과 예문

인라인 태그 27개를 실제 문장(경고문, 가격 표시, 코드 안내, 다국어 텍스트 등) 안에 넣어보면서, 겉보기 렌더링은 비슷해도 태그마다 의도가 다르다는 걸 확인한 정리다.

## 1. 텍스트 강조·의미 부여 태그

| 태그 | 용도 | 예문 |
|---|---|---|
| `<span>` | 특정 텍스트 구간을 묶어 CSS/JS를 적용하는 범용 인라인 컨테이너. 의미는 없다. | `프로그래밍 언어에는 Python, <span style="color: blue; font-weight: bold;">Java</span>, C++이 있습니다.` |
| `<strong>` | 내용의 중요성·심각성·긴급성을 **의미론적으로** 강조(스크린 리더도 강조해서 읽음). | `<strong>경고:</strong> 작업 중 전원을 끄지 마세요.` |
| `<b>` | 의미상 중요성 없이 **시각적으로만** 굵게 표시(제품명, 키워드 요약 등). | `이번 분기 베스트셀러는 <b>자바스크립트 완벽 가이드</b>입니다.` |
| `<em>` | 문장의 어조·특정 단어의 강조(발화 시 억양이 강해지는 지점). | `회의 시간은 <em>오전</em> 10시입니다. (오후가 아님)` |
| `<i>` | 전문 용어·외국어 관용구·생각의 표현 등, 일반 텍스트와 결이 다른 부분을 표기. | `그의 좌우명은 <i>Carpe Diem</i>이다.` |
| `<mark>` | 검색 결과 매칭이나 참조 목적으로 특정 텍스트를 형광펜처럼 하이라이트. | `검색 결과 중 <mark>Spring Boot</mark> 키워드가 발견되었습니다.` |
| `<small>` | 부가 설명·법적 고지·저작권 안내 등 본문보다 작은 텍스트. | `결제 금액 10,000원 <small>(부가세 포함)</small>` |

- `strong`/`b`, `em`/`i` 쌍은 렌더링 결과(굵게/기울임)는 같지만, `strong`·`em`은 **의미**(중요도·강조)를 전달하고 `b`·`i`는 **순수 시각 효과**만 준다는 차이가 예문에서도 드러난다 — 경고문에는 `strong`, 책 제목 강조에는 `b`를 쓴 식이다.

## 2. 편집 표시 태그

| 태그 | 용도 | 예문 |
|---|---|---|
| `<del>` | 문서에서 삭제·취소된 텍스트(취소선). `datetime` 속성으로 삭제 일시를 남길 수 있다. | `정상가: <del datetime="2026-01-01">50,000원</del>` |
| `<ins>` | 문서에 새로 추가·교체된 텍스트(밑줄). `datetime` 속성으로 추가 일시를 남길 수 있다. | `할인가: <ins datetime="2026-01-01">35,000원</ins>` |
| `<s>` | 더 이상 유효하지 않은 정보를 단순 취소선으로 표기(편집 이력 의미는 없음). | `재고 상태: <s>품절</s> 즉시 배송 가능` |
| `<u>` | 오타 지적, 고유명사 표시처럼 밑줄이 필요하지만 링크는 아닌 텍스트. | `단어 철자 오류: <u>recieve</u> (올바른 표기: receive)` |

- `del`/`ins`는 "언제, 왜 바뀌었는지"를 `datetime`으로 기록할 수 있는 **편집 이력용** 태그이고, `s`는 그냥 "지금은 유효하지 않다"는 표시일 뿐이라 이력 속성이 없다는 차이를 예문(정상가→할인가 vs 품절 표시)으로 구분해볼 수 있다.

## 3. 첨자 태그

| 태그 | 용도 | 예문 |
|---|---|---|
| `<sub>` | 화학식·수학 지수 밑단 등 아래 첨자. | `물의 화학식은 H<sub>2</sub>O 입니다.` |
| `<sup>` | 거듭제곱·서수·주석 번호 등 위 첨자. | `2의 10승은 2<sup>10</sup> = 1024 입니다.` |

## 4. 인용·정의 태그

| 태그 | 용도 | 예문 |
|---|---|---|
| `<abbr>` | 줄임말을 정의하고, `title` 속성으로 전체 명칭을 툴팁으로 제공. | `<abbr title="HyperText Markup Language">HTML</abbr>은 웹 표준입니다.` |
| `<cite>` | 책·논문·영화·웹사이트 등 저작물의 제목을 인용/표기. | `이 내용은 <cite>클린 코드</cite> 3장에서 발췌했습니다.` |
| `<q>` | 줄바꿈 없는 짧은 인라인 인용문(브라우저가 자동으로 큰따옴표를 붙여준다). `cite` 속성으로 출처 URL을 남길 수 있다. | `스티브 잡스는 <q cite="https://example.com">늘 갈망하고 우직하게 나아가라</q>고 말했습니다.` |
| `<dfn>` | 문맥 내에서 특정 용어의 최초 정의·핵심 정의 대상을 지정. | `<dfn>API</dfn>란 애플리케이션 간에 데이터를 주고받기 위한 인터페이스입니다.` |

- `q`의 `cite` 속성과 `dfn`의 `title` 속성은 화면에 직접 드러나지 않는 **메타데이터**라는 공통점이 있다 — 사람 눈에는 안 보여도 검색엔진·스크린 리더·브라우저 툴팁이 활용한다.

## 5. 데이터·시간 태그

| 태그 | 용도 | 예문 |
|---|---|---|
| `<time>` | 기계가 파싱할 수 있는 날짜/시간(`datetime`, ISO 8601 형식)을 사람이 읽는 텍스트와 매핑. | `세미나 일정: <time datetime="2026-10-15T14:00">2026년 10월 15일 오후 2시</time>` |
| `<var>` | 수학 수식의 변수 또는 프로그래밍 코드의 변수 표기(기울임꼴). | `직선의 방정식은 <var>y</var> = <var>a</var><var>x</var> + <var>b</var> 형태입니다.` |
| `<data>` | 화면에 보이는 텍스트에 기계 판독용 원시 값(`value`)을 바인딩. | `현재 주문 품목: <data value="PROD-9812">무선 기계식 키보드</data>` |

- 세 태그 모두 "사람이 읽는 표현"과 "기계가 처리하는 값"을 한 요소 안에 같이 담는다는 공통 패턴이다 — `time`은 `datetime`, `data`는 `value`에 기계용 값을 넣는다.

## 6. 코드 관련 태그

| 태그 | 용도 | 예문 |
|---|---|---|
| `<code>` | 단일 단어 또는 짧은 인라인 코드/명령어 표기(고정폭 글꼴). | `현재 상태를 보려면 <code>git status</code> 명령을 실행하세요.` |
| `<kbd>` | 키보드 입력·단축키 등 사용자가 직접 입력해야 하는 키 표기. | `복사하려면 <kbd>Ctrl</kbd> + <kbd>C</kbd>를 누르세요.` |
| `<samp>` | 프로그램·콘솔의 실행 결과(Sample Output) 표기. | `서버 응답 결과: <samp>200 OK - Request Succeeded</samp>` |

- `code`(작성한 코드)·`kbd`(사용자가 입력할 키)·`samp`(그 결과로 나온 출력)로 역할이 명확히 나뉜다 — 튜토리얼 문서에서 "명령어 입력 → 실행 결과"를 보여줄 때 이 세 태그를 조합해서 쓰면 된다.

## 7. 줄바꿈 태그

| 태그 | 용도 | 예문 |
|---|---|---|
| `<br>` | 텍스트 흐름 안에서 강제 줄바꿈을 수행하는 빈(empty) 태그. | `서울특별시 강남구 테헤란로<br>10층 개발팀` |
| `<wbr>` | 긴 단어·URL이 줄을 벗어날 때, 줄바꿈이 **허용되는 지점**만 지정(강제 줄바꿈은 아님). | `https://verylongdomainname<wbr>.example.com/<wbr>subfolder/<wbr>test` |

- `br`은 "여기서 무조건 줄바꿈"이고 `wbr`은 "필요하면 여기서 줄바꿈해도 된다"는 차이다 — CSS 이전 시절 스타일 태그가 의미로 재정의된 것과 같은 흐름으로, `br`은 Line **Br**eak, `wbr`은 **W**ord **Br**eak Opportunity라는 약어 의미를 갖는다.

## 8. 양방향 텍스트(bidi) 태그

| 태그 | 용도 | 예문 |
|---|---|---|
| `<bdi>` | 주위 텍스트의 쓰기 방향(LTR/RTL)과 상관없이, 내부 텍스트의 방향을 독립적으로 격리 처리. | `사용자 <bdi>إيان</bdi>: 1등 (아랍어 텍스트와 숫자가 섞여도 순서 왜곡 방지)` |
| `<bdo>` | `dir` 속성으로 내부 텍스트의 출력 방향을 강제로 덮어써서 좌우를 반전 표기. | `원래 텍스트: <bdo dir="rtl">Hello World</bdo>` |

- 아랍어·히브리어처럼 오른쪽에서 왼쪽으로 쓰는 언어가 한글·영어 같은 왼쪽에서 오른쪽 텍스트와 한 문장에 섞일 때, `bdi`는 "이 부분은 그 자체의 방향대로 안전하게 격리해서 보여줘"이고 `bdo`는 "이 부분은 원래 방향과 상관없이 강제로 반대로 보여줘"라는 차이다.

## 9. 정리

- 27개 태그를 실제 문장 안에서 써보면, 겉보기 렌더링(굵게/기울임/밑줄/취소선)이 같아 보이는 태그들도 **왜 그 태그를 골랐는지 의미가 각각 다르다**는 게 문맥 안에서 훨씬 명확하게 드러난다 — `strong`과 `b`, `em`과 `i`, `del`과 `s`처럼 겉모습이 겹치는 쌍일수록 문맥이 그 차이를 보여준다.
- `title`, `datetime`, `cite`, `value`, `dir`처럼 화면에 안 보이는 속성들이 각 태그의 "기계가 읽는 정보"를 담당한다는 공통 패턴도 눈여겨볼 만하다.
