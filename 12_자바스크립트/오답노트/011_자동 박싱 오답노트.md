# 자동 박싱 오답노트

### 1. JavaScript의 자동 박싱(autoboxing)에 대한 설명으로 옳은 것은?

**문제**: JavaScript의 자동 박싱(autoboxing)에 대한 설명으로 옳은 것은?

1. 문자열 같은 원시값은 필요할 때 임시 래퍼 객체가 생성되어 메서드를 사용할 수 있다
2. 숫자 원시값은 메서드를 전혀 사용할 수 없다
3. 자동 박싱을 사용하면 `new String()`과 같은 생성자를 반드시 사용해야 한다
4. 원시값은 항상 객체로 저장되며 `typeof`는 `'object'`를 반환한다

**정답: 1번**

- 문자열·숫자·불리언 같은 원시값은 원래 속성이나 메서드를 갖지 않는 단순한 값이다. 하지만 `.length`나 `.toUpperCase()`처럼 점을 찍어 메서드를 호출하는 순간, 자바스크립트 엔진이 그 원시값을 임시로 래퍼 객체(`String`, `Number`, `Boolean`)로 감싸서(박싱) 메서드를 실행한 뒤 곧바로 그 임시 객체를 버린다. 이 과정이 자동 박싱이다.
- **2번이 오답인 이유**: 숫자도 문자열과 똑같이 자동 박싱을 거쳐 메서드를 쓸 수 있다.

  ```js
  console.log((123.456).toFixed(2)); // "123.46"
  ```

  숫자 리터럴에 바로 점을 찍으면 `123.toFixed`처럼 소수점으로 오해되어 문법 오류가 나기 때문에 괄호로 감싸거나 `123..toFixed(2)`처럼 점을 두 번 써야 하는 것일 뿐, 숫자에 메서드를 못 쓴다는 뜻은 아니다.
- **3번이 오답인 이유**: 자동 박싱은 개발자가 `new String()`을 직접 호출하지 않아도 엔진이 알아서 처리해주는 것이 핵심이다. 오히려 `new String("hello")`처럼 명시적으로 생성자를 쓰면 그건 자동 박싱이 아니라 개발자가 직접 만든 래퍼 객체가 된다.
- **4번이 오답인 이유**: 원시값은 평소에 객체가 아니라 원시값 그대로 저장된다. `typeof "hello"`는 언제나 `"string"`이며, 메서드를 호출하는 그 찰나에만 임시로 객체가 되었다가 곧바로 원래의 원시값으로 돌아온다(언박싱).
