# var 호이스팅 오답노트

### 1. var로 선언한 변수의 호이스팅 특성에 대한 올바른 설명은?

**문제**: `var`로 선언한 변수의 호이스팅 특성에 대한 올바른 설명은?

1. `let`과 `const`와 동일하게 선언 전에 접근하면 일시적 사각지대가 발생한다
2. `var`는 블록 스코프를 가지므로 함수 외부에서는 사용할 수 없다
3. `var` 선언은 호이스팅되어 선언문이 끌어올려진 것처럼 동작해 선언 전에 접근하면 `undefined`가 나온다
4. `var` 선언은 전혀 호이스팅되지 않고 선언 전에 접근하면 `ReferenceError`가 발생한다

**정답: 3번**

- `var`로 선언된 변수는 코드에서 실제로 등장하는 위치와 무관하게 그 선언이 스코프 맨 위로 끌어올려지고, 이때 `undefined`로 미리 초기화된다. 그래서 선언문보다 먼저 그 변수를 참조해도 오류 없이 `undefined`가 나온다.

  ```js
  console.log(a); // undefined — 오류가 아니다
  var a = 1;
  ```

- **1번, 4번이 오답인 이유**: 선언 전에 접근했을 때 일시적 사각지대(TDZ)에 걸려 `ReferenceError`를 던지는 것은 `let`/`const`의 특징이다. `let`/`const`도 선언 자체는 호이스팅되지만, `var`처럼 곧바로 `undefined`로 초기화되지 않고 선언문에 도달하기 전까지는 접근이 금지된 상태로 남아있다는 차이가 있다.
- **2번이 오답인 이유**: `var`는 **함수 스코프**를 가지지 **블록 스코프**를 가지지 않는다. `if`나 `for` 같은 중괄호 블록은 `var`에게는 스코프 경계가 되지 못하므로, 블록 안에서 선언해도 그 블록을 둘러싼 함수 전체(또는 함수가 없다면 전역)에서 접근할 수 있다.

  ```js
  function check() {
      if (true) {
          var x = 10; // 블록 안에서 선언했지만
      }
      console.log(x); // 10 — 함수 스코프라서 블록 밖에서도 접근된다
  }
  check();
  ```

  같은 코드를 `let`으로 쓰면 `if` 블록이 곧 스코프 경계가 되어, 블록 밖에서 `x`를 참조하면 `ReferenceError`가 난다 — 이것이 실무에서 `var` 대신 `let`/`const`를 권장하는 이유 중 하나다.

**`var` vs `let`/`const` 호이스팅 비교**

| | 선언 자체의 호이스팅 | 선언 전 접근 시 |
|---|---|---|
| `var` | 됨, `undefined`로 초기화 | `undefined` 반환 |
| `let`/`const` | 됨, 하지만 초기화는 안 됨(TDZ) | `ReferenceError` |
