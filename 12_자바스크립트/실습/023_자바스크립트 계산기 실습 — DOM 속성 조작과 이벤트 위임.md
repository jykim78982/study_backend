# 자바스크립트 계산기 실습 — DOM 속성 조작과 이벤트 위임

[실습 34] 간단한 덧셈 계산기, [실습 35] 이벤트 객체와 버블링 실습. 텍스트 입력 방식의 첫 계산기를 만들어보고, 그 한계를 겪은 뒤 이벤트 버블링과 이벤트 객체로 버튼식 계산기를 개선하는 흐름을 정리했다.

## 1. 덧셈 계산기 — `defer`와 범위를 좁힌 DOM 탐색

`calculator.html`, `calculator.js` 두 파일로 처음 만들어보는 이벤트 기반 프로그램이다.

```html
<script src="calculator.js" defer></script>
...
<section id="s2">
    <h1>2. DOM 속성 다루기 : 계산기</h1>
    <div>
        <input class="x-input" type="text" value="0">
        <input class="y-input" type="text" value="0">
        <input class="button" type="button" value="덧셈">
        <span class="result">계산결과 : 0</span>
    </div>
</section>
```

`<script>`에 `defer`를 붙였기 때문에 `<head>`에 있어도 HTML 파싱을 막지 않고, DOM 트리가 완성된 직후에 실행되어 아래쪽 `<section>` 요소들을 문제없이 찾을 수 있다.

```js
// 기준이 되는 부모 엘리먼트 선택
const section = document.querySelector("#s2");
// 부모 엘리먼트 내부에서 필요한 객체만 재탐색
const xInput = section.querySelector(".x-input");
const yInput = section.querySelector(".y-input");
const btnAdd = section.querySelector(".button");
const resultSpan = section.querySelector(".result");
```

`document` 전체가 아니라 `#s2` 섹션을 먼저 확보한 뒤 그 안에서만 재탐색한다 — 다른 섹션에 같은 클래스명이 있어도 충돌하지 않고, 탐색 범위도 좁아진다.

## 2. 문자열 결합 함정과 `parseInt`

버튼 클릭 이벤트는 `onclick` 대신 `addEventListener`로 등록했다.

```js
btnAdd.addEventListener("click", function () {
    const x = xInput.value;
    const y = yInput.value;
    console.log("x:", x, "y:", y);
    console.log("x + y =", x + y);
});
```

`onclick`은 함수 하나만 대입할 수 있는 반면 `addEventListener`는 같은 이벤트에 여러 핸들러를 추가로 등록할 수 있다는 차이가 있다. 다만 `input.value`는 항상 문자열이라서 `3`과 `4`를 입력해도 `x + y`는 `7`이 아니라 `"34"`가 된다 — `+` 연산자가 숫자가 아닌 문자열 결합으로 동작하기 때문이다.

이를 해결하려면 값을 숫자로 명시적으로 변환해야 한다.

```js
const x = parseInt(xInput.value, 10) || 0;
const y = parseInt(yInput.value, 10) || 0;
const sum = x + y;
```

`parseInt(value, 10)`으로 10진수 정수로 변환하고, 뒤에 붙인 `|| 0`은 빈 문자열이나 숫자가 아닌 값이 들어와 `NaN`이 나올 때를 대비한 기본값 처리다.

## 3. 결과를 화면에 반영 — `textContent`

계산 결과는 콘솔이 아니라 화면의 `span`에 반영해야 실제로 쓸 수 있다.

```js
resultSpan.textContent = "계산결과 : " + sum;
```

텍스트를 대입할 때는 `innerHTML`이 아니라 `textContent`를 쓴다. `innerHTML`은 문자열을 HTML로 해석해서 대입하기 때문에 불필요한 파싱 오버헤드가 생기고, 사용자 입력이 섞여 들어가면 XSS(악성 스크립트 삽입) 취약점으로 이어질 수 있다. 단순 텍스트 교체에는 `textContent`가 안전하고 적합하다.

## 4. 버튼식 계산기 — 반복 바인딩의 한계

두 번째 실습은 숫자·연산자 버튼을 눌러 입력하는 UI다.

```html
<section id="s3">
    <h1>3. 이벤트 객체 : 개선된 계산기</h1>
    <input type="text" value="0" readonly>
    <div class="box">
        <input class="num" type="button" value="1">
        <input class="num" type="button" value="2">
        <!-- ... 8까지, 그리고 +, -, *, /, = -->
    </div>
</section>
```

가장 먼저 떠올릴 수 있는 구현은 버튼 하나하나에 개별로 핸들러를 붙이는 방식이다.

```js
numButtons[0].onclick = function() { txtInput.value += 1; };
numButtons[1].onclick = function() { txtInput.value += 2; };
numButtons[2].onclick = function() { txtInput.value += 3; };
```

동작은 하지만 세 가지 문제가 있다. 첫째, 수행하는 본질(`txtInput.value += 자기 값`)이 완전히 같은데 버튼 수만큼 똑같은 구조를 반복해서 나열해야 한다. 둘째, 버튼이 늘어날 때마다 새 익명 함수 객체가 하나씩 계속 생성되어 메모리를 불필요하게 점유한다. 셋째, 나중에 자바스크립트로 새 버튼(`9`)을 화면에 동적으로 추가하면 그 버튼은 동작하지 않는다 — 코드가 실행되는 시점에 이미 존재하던 요소에만 핸들러가 묶였기 때문이다.

## 5. 이벤트 버블링과 이벤트 객체(`e.target`)

이 한계는 브라우저의 두 가지 동작 원리를 조합해서 해결한다.

**이벤트 버블링**: 버튼을 클릭했을 때 이벤트는 그 버튼에서 끝나지 않고, 물속 거품이 표면으로 올라오듯 부모(`div.box`) → 조상(`section`) → 최상위(`document`)까지 순차적으로 신호가 타고 올라간다. 그래서 자식 버튼마다 감시자를 둘 필요 없이, 부모인 `.box` 컨테이너 한 곳에만 핸들러를 걸어도 자식들의 클릭을 모두 받아낼 수 있다.

**이벤트 객체와 `e.target`**: `.box`에서 클릭 이벤트를 받았을 때, 그것이 `.box` 자신을 직접 클릭한 것인지 자식 버튼이 클릭되어 버블링된 것인지 구분해야 할 때가 있다. 모든 이벤트 핸들러는 현재 이벤트 정보를 담은 객체(관례상 `e`)를 매개변수로 받는데, 이 객체의 `e.target`이 실제로 클릭당한 가장 안쪽의 원본 엘리먼트를 가리킨다. 마우스 이벤트라면 좌표나 함께 눌린 키보드 정보도 이 객체에 담겨 있다.

```js
box.onclick = function(e) {
    // 버튼과 버튼 사이 빈 여백(div 영역)을 눌렀을 때는 무시
    if (e.target.type !== "button") {
        return;
    }

    var value = txtInput.value;

    // 초기값 '0'은 누적되지 않도록 지운다
    if (value === "0") {
        value = "";
    }

    // e.target은 실제 클릭된 버튼 요소이므로, 그 value(글자)를 가져와 누적한다
    value += e.target.value;
    txtInput.value = value;
};
```

이렇게 부모 `.box`에 딱 하나의 핸들러만 등록하면, 코드를 따로 작성하지 않은 `+`, `-`, `*`, `/`, `=` 기호 버튼까지도 자동으로 입력창에 반영된다. 개발자 도구에서 버튼을 하나 더 만들어 `.box` 안에 넣어도 JS 코드 수정 없이 즉시 클릭이 처리되는 것도 이벤트 위임 방식의 확장성 덕분이다. (이 실습에서는 실제 사칙연산 처리까지는 구현하지 않았다.)
