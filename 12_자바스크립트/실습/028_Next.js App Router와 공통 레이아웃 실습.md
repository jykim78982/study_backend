# Next.js App Router와 공통 레이아웃 실습

`ncafe/frontend/`에 App Router 기반 Next.js 프로젝트를 만들고, AI 코딩 도우미로 카페 랜딩 페이지를 완성한 뒤, 페이지가 두 개(`/`, `/menus`)로 늘어나면서 생기는 중복 문제를 `layout.js`의 공통 머리글·바닥글, `Link` 컴포넌트, `components/` 폴더 분리, `metadata`로 해결해 나간 실습이다.

## 1. App Router 기반 프로젝트 생성

[[027_Next.js 프로젝트 생성 실습]]과 달리 이번에는 `--no-app`을 빼서 **App Router**(`app/` 디렉터리 기반) 구조로 만든다.

```
mkdir ncafe
cd ncafe
npx create-next-app@latest frontend --no-typescript --no-tailwind --no-src-dir --use-npm
```

`--no-typescript`로 JavaScript, `--no-tailwind`로 Tailwind 없이, `--no-src-dir`로 `src/` 없이 `app/`이 프로젝트 루트에 바로 오게, `--use-npm`으로 npm을 명시한다. 설치가 끝나면 `frontend/app/` 안에 `layout.js`, `page.js`, `globals.css`가 `.js` 확장자로 생긴다(TypeScript였다면 `.tsx`).

```
cd frontend
npm run dev
```

`http://localhost:3000`에 접속하면 아직 Next.js 기본 화면이 보인다. `app/page.js`를 아래처럼 바꾸면 화면이 바뀐다.

```jsx
export default function Home() {
  return (
    <div style={{ display: 'flex', alignItems: 'center', justifyContent: 'center', minHeight: '100vh' }}>
      <h1 style={{ fontSize: '2rem', fontWeight: 'bold' }}>
        ncafe에 오신 것을 환영합니다.
      </h1>
    </div>
  );
}
```

아직 Tailwind나 CSS Modules를 배우기 전이라 인라인 스타일로 임시 처리한다.

## 2. AI 코딩 도우미로 랜딩 페이지 만들기

이 단계에는 "정답 코드"가 없다. AI(Copilot, Cursor 등)에게 색상·구조·문구를 구체적으로 지정한 프롬프트를 주고, 마음에 들 때까지 프롬프트를 다듬어 결과를 반복 수정하는 것 자체가 목표다.

프롬프트는 구체적일수록(배경색 값, 카드 개수, 여백, 문구까지) 재현 가능한 결과를 준다. 다만 "재현 가능"한 결과가 "최고"의 결과는 아니므로, 그 결과를 출발점 삼아 "이건 아닌데" 싶은 부분을 한 번에 다시 만들지 말고 부분적으로("여기만 바꿔줘") 계속 다듬어 간다.

완성된 `app/page.js`는 하나의 React 컴포넌트(`export default function Home()`)이며, 이 컴포넌트가 반환하는 JSX가 `/` 경로의 HTML로 렌더링된다. 아직 개념을 배우지 않았지만 이 `page.js`는 서버에서 실행되어 HTML을 만들어내는 **서버 컴포넌트**다.

같은 방식으로 메뉴 조회 페이지도 만든다 — 라우팅을 아직 배우지 않았으므로 `http://localhost:3000/menus`로 접근할 수 있도록 `app/menus/page.js` 파일을 만들면 된다. App Router는 폴더 경로가 곧 URL이 되고, 그 폴더의 `page.js`가 해당 경로를 담당한다.

## 3. 페이지가 둘이 되면 생기는 문제

`/`와 `/menus` 두 페이지를 각각 만들고 나면 두 가지 문제가 드러난다.

- 머리글(로고, 메뉴 링크)을 두 페이지에 각각 직접 넣으면 같은 코드가 두 벌 생긴다. 페이지가 열 개가 되면 열 벌이 된다.
- 두 페이지는 서로를 모른다. 랜딩의 "메뉴 보기" 버튼을 눌러도 메뉴 페이지로 이동하는 기능이 없다.

Next.js는 페이지들이 공유하는 부분을 두는 자리를 `app/layout.js`로 마련해 뒀다.

## 4. `layout.js`의 `{children}` — 공통 머리글 배치

`app/layout.js`는 모든 페이지를 감싸는 껍데기다. 기본 생성 상태는 대략 이렇다.

```jsx
import "./globals.css";

export const metadata = {
  title: "Create Next App",
  description: "Generated by create next app",
};

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

`{children}` 자리에 요청 경로에 맞는 `page.js`가 끼워진다 — `/`면 `app/page.js`가, `/menus`면 `app/menus/page.js`가 들어온다. 이 자리 바깥에 쓴 것은 어느 페이지에서나 공통으로 보인다.

```jsx
export default function RootLayout({ children }) {
  return (
    <html lang="ko">
      <body>
        {/* 모든 페이지 위에 공통으로 보이는 머리글 */}
        <header className="site-header">
          <a href="/" className="brand">ncafe</a>
          <nav>
            <a href="/">홈</a>
            <a href="/menus">메뉴</a>
          </nav>
        </header>

        {children}
      </body>
    </html>
  );
}
```

`app/globals.css` 맨 아래에 머리글 스타일을 추가한다.

```css
.site-header {
  display: flex;
  justify-content: space-between;
  align-items: center;
  padding: 16px 40px;
  background: #3d2c1e;
}

.site-header a {
  color: #fff;
  text-decoration: none;
}

.site-header .brand {
  font-size: 1.8rem;
  font-weight: bold;
}

.site-header nav {
  display: flex;
  gap: 24px;
}

.site-header nav a:hover {
  color: #c8956c;
}
```

이제 랜딩 페이지에는 머리글이 두 개(레이아웃의 것 + 자신이 만든 것) 보이므로, `app/page.js`에 직접 만들어 둔 머리글 부분은 삭제한다.

`layout.js`의 `{children}`이 핵심이다 — Next.js가 주소에 맞는 `page.js`를 찾아 이 자리에 끼워 넣으므로, `children` 바깥에 쓴 것은 사이트의 머리글·바닥글·사이드 메뉴처럼 모든 페이지에 공통으로 필요한 요소를 두는 자리가 된다.

## 5. `<a>` 대신 `Link` — 화면 깜빡임 없이 이동하기

지금 머리글의 `<a>`는 누를 때마다 브라우저가 서버에서 HTML 문서를 통째로 다시 받아온다. 개발자 도구 Network 탭에서 Doc 필터를 켠 채 링크를 클릭해 보면 새 문서 요청이 생기는 것으로 확인할 수 있다.

`next/link`의 `Link`로 바꾸면 Next.js가 클릭을 가로채 바뀌는 부분만 서버에 요청하고, `layout.js`는 그대로 둔 채 `{children}`만 갈아 끼운다.

```jsx
import Link from "next/link";
import "./globals.css";

export default function RootLayout({ children }) {
  return (
    <html lang="ko">
      <body>
        <header className="site-header">
          <Link href="/" className="brand">ncafe</Link>
          <nav>
            <Link href="/">홈</Link>
            <Link href="/menus">메뉴</Link>
          </nav>
        </header>

        {children}
      </body>
    </html>
  );
}
```

랜딩 페이지의 "메뉴 둘러보기" 버튼처럼 페이지 이동을 담당하던 `<button>`도 `Link`로 바꾼다.

```jsx
<Link
  href="/menus"
  style={{
    background: "#c8956c",
    color: "#fff",
    padding: "12px 32px",
    borderRadius: "999px",
    fontSize: "1rem",
    textDecoration: "none",
  }}
>
  메뉴 둘러보기
</Link>
```

`<button>`은 누를 곳(이동할 주소)이 없는 요소이므로 `Link`로 바꾸면서 `border`·`cursor` 속성은 빼고, 링크 밑줄을 없애는 `textDecoration: "none"`을 넣는다.

`<a>`는 "이 주소로 새로 가라"는 뜻이라 브라우저가 화면을 버리고 처음부터 다시 그리지만, `Link`는 바뀌는 부분만 갈아 끼우기 때문에 깜빡이지 않는다. 덤으로 `Link`는 화면에 보이는 순간 다음 페이지를 미리 받아두는 prefetch도 수행한다. **앱 안에서 이동할 땐 `Link`, 바깥 사이트로 나갈 땐 `<a>`**로 구분한다.

## 6. 바닥글 추가

머리글과 같은 원리로 바닥글도 `{children}` 아래에 둔다.

```jsx
{children}

<footer className="site-footer">
  <p>© 2026 ncafe. 신선한 원두로 매일 아침을.</p>
</footer>
```

```css
.site-footer {
  padding: 24px;
  text-align: center;
  color: #7a6b5d;
  font-size: 0.85rem;
  background: #f9f5f0;
}
```

랜딩 페이지 바깥 컨테이너에 `minHeight: "100vh"`가 남아 있으면 페이지 자체가 화면 높이를 다 차지해 바닥글을 보려면 스크롤을 내려야 한다 — 그 줄을 지우거나 머리글·바닥글 높이만큼 뺀 값으로 조정한다.

## 7. `components/` 폴더로 분리하기

`layout.js`가 길어지기 시작하면 머리글·바닥글을 각각 컴포넌트 파일로 분리해, `layout.js`에는 "어디에 무엇을 놓는지" 구조만 남긴다. `components/`는 `app/`과 나란히, `app/` **밖에** 만든다 — `app/` 안의 폴더는 Next.js가 주소(라우트)로 해석하려 들기 때문에, 페이지가 아닌 부품은 밖에 두는 것이 안전하다.

```jsx
// components/Header.js
import Link from "next/link";

export default function Header() {
  return (
    <header className="site-header">
      <Link href="/" className="brand">ncafe</Link>
      <nav>
        <Link href="/">홈</Link>
        <Link href="/menus">메뉴</Link>
      </nav>
    </header>
  );
}
```

```jsx
// components/Footer.js
export default function Footer() {
  return (
    <footer className="site-footer">
      <p>© 2026 ncafe. 신선한 원두로 매일 아침을.</p>
    </footer>
  );
}
```

```jsx
// app/layout.js
import "./globals.css";
import Header from "../components/Header";
import Footer from "../components/Footer";

export default function RootLayout({ children }) {
  return (
    <html lang="ko">
      <body>
        <Header />
        {children}
        <Footer />
      </body>
    </html>
  );
}
```

화면은 이전과 완전히 같지만, 이제 `layout.js`를 열면 머리글·페이지·바닥글이라는 구조가 한눈에 보이고, 머리글 색을 바꾸고 싶으면 `Header.js`만 열면 된다 — "무엇을 놓을지"(layout.js)와 "그게 어떻게 생겼는지"(각 컴포넌트)를 떼어놓는 것이 목적이다.

## 8. `metadata`로 탭 제목 관리하기

`layout.js`의 `metadata`가 브라우저 탭 제목(`<title>`)의 정체다. `default`는 페이지가 제목을 따로 정하지 않았을 때, `template`은 페이지가 제목을 정했을 때 `%s` 자리에 그 제목을 끼워 넣는 틀이다.

```jsx
// app/layout.js
export const metadata = {
  title: {
    default: "ncafe",
    template: "%s | ncafe",
  },
  description: "신선한 원두로 매일 아침을 시작하는 동네 카페",
};
```

```jsx
// app/menus/page.js — 파일 맨 위
export const metadata = {
  title: "메뉴",
};
```

이렇게 하면 `/`의 탭 제목은 `ncafe`, `/menus`의 탭 제목은 `메뉴 | ncafe`가 된다. `metadata`는 `<head>`에 들어갈 정보를 적는 자리이며, 레이아웃과 페이지가 각자 적은 값을 Next.js가 합쳐준다 — 지금은 제목 하나지만, 이후 미리보기 이미지나 설명(OG 태그) 같은 정보도 같은 자리에 추가된다.

## 9. 전체 흐름 정리

| 단계 | 내용 |
|---|---|
| 1 | `create-next-app`(App Router)으로 `ncafe/frontend/` 생성 |
| 2 | AI 프롬프트로 랜딩 페이지(`/`)·메뉴 페이지(`/menus`) 제작, 부분 수정 반복 |
| 3 | 페이지가 늘면서 공통 부분 중복·페이지 간 이동 불가 문제 확인 |
| 4 | `layout.js`의 `{children}` 바깥에 공통 머리글 배치 |
| 5 | `<a>` 대신 `Link`로 전환해 화면 깜빡임 없는 이동 구현 |
| 6 | `{children}` 아래에 공통 바닥글 배치 |
| 7 | 머리글·바닥글을 `app/` 밖 `components/`로 분리 |
| 8 | `metadata`의 `title.default`·`title.template`으로 페이지별 탭 제목 관리 |
