# innerHTML 이어붙이기 오버헤드와 insertAdjacentHTML

## 1. `innerHTML +=`로 이어붙일 때의 문제

`innerHTML`은 문자열을 HTML로 해석해서 통째로 꽂아 넣는 방식이라, 기존 내용을 완전히 새로 그릴 때는 간단하고 편하다. 하지만 기존 내용에 뭔가를 "추가"하는 용도로 쓰면 이야기가 달라진다.

```js
span1.innerHTML += "<input>";
```

이렇게 기존 내용에 이어붙이는 코드는 겉보기와 달리 다음 세 단계를 매번 반복한다.

1. 기존 DOM(엘리먼트 트리)을 통째로 문자열로 직렬화한다.
2. 그 문자열에 새로 추가할 문자열을 결합한다.
3. 결합된 전체 문자열을 다시 파싱해서 DOM 객체로 재구성한다.

목록에 항목을 하나씩 추가하는 것처럼 "기존 내용은 그대로 두고 일부만 덧붙이는" 작업에서 이 방식은, 추가할 때마다 전체를 문자열로 바꿨다가 다시 객체로 만드는 불필요한 오버헤드가 계속 쌓인다. 항목 개수가 늘어날수록 매번 다시 만들어야 하는 문자열의 길이도 함께 길어지므로 비용이 더 커진다.

## 2. `insertAdjacentHTML` — 기존 DOM을 건드리지 않고 끼워 넣기

이 문제를 해결하는 것이 `insertAdjacentHTML(위치, 문자열)`이다. 기존 DOM을 문자열로 변환하는 과정 없이, 지정한 위치에 새 DOM 노드를 곧바로 만들어 꽂아 넣는다.

```js
span1.insertAdjacentHTML('beforeend', '<input>');
```

| 위치 값 | 의미 |
|---|---|
| `beforebegin` | 엘리먼트 자신의 앞(형제로 삽입) |
| `afterbegin` | 엘리먼트 내부의 맨 앞(첫 자식 앞) |
| `beforeend` | 엘리먼트 내부의 맨 뒤(마지막 자식 뒤) |
| `afterend` | 엘리먼트 자신의 뒤(형제로 삽입) |

겉보기엔 `innerHTML +=`과 결과가 비슷해 보이지만 내부 동작은 전혀 다르다 — 기존 자식들을 건드리지 않고 새 노드만 만들어 지정한 위치에 바로 붙이므로, 목록에 항목을 반복해서 추가하는 것처럼 기존 내용을 유지한 채 계속 덧붙이는 작업에서 `innerHTML`보다 훨씬 가볍다.

## 3. 정리

| | `innerHTML +=` | `insertAdjacentHTML` |
|---|---|---|
| 동작 방식 | 전체를 문자열화 → 결합 → 재파싱 | 새 노드만 만들어 바로 삽입 |
| 기존 자식 | 통째로 다시 만들어짐 | 그대로 유지됨 |
| 반복 추가 시 비용 | 누적될수록 커짐 | 매번 일정 |
| 적합한 상황 | 내용을 통째로 새로 그릴 때 | 기존 내용에 일부만 덧붙일 때 |
