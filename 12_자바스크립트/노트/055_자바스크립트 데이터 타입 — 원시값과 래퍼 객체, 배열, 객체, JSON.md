# 자바스크립트 데이터 타입 — 원시값과 래퍼 객체, 배열, 객체, JSON

## 1. Node.js 생태계의 성장 — npm, 사건사고, ES6 지원까지

Node.js가 등장한 뒤, 자바(JVM)나 닷넷처럼 실제로 쓸 만한 플랫폼이 되려면 그 위에서 동작하는 라이브러리들이 갖춰져야 했다. 초기 몇 년 사이에 웹 서버를 손쉽게 구성할 수 있는 **Express**, 실시간 통신을 위한 소켓 라이브러리 등이 잇달아 등장했고, 링크드인·우버 같은 실제 기업들이 Node.js 기반 서비스를 만들기 시작하면서 채택이 빠르게 확산됐다. 2015년 무렵에는 생태계가 충분히 성숙해 **OpenJS Foundation**(재단)이 만들어질 정도가 되었다.

**npm**(2011년경 등장)은 Node.js 생태계를 위한 패키지 저장소로, 자바의 Maven 저장소에 대응한다. 다만 초기에는 버전 관리 관행이 지금처럼 엄격하지 않아서 사고가 나기도 했다 — 대표적인 사례가 **"left-pad" 사건**이다. 어떤 개발자가 아주 작은 유틸리티 라이브러리(문자열 왼쪽 채우기 기능)를 수정해 올렸는데, 버그를 고친 변경사항인데도 버전 번호를 새로 올리지 않고 같은 버전 번호로 덮어써버렸다. 그 결과 어제까지 잘 동작하던 수많은 프로젝트가 갑자기 예상과 다르게 동작하며 장애를 일으켰다. 이 사건 이후로 "패키지를 수정해서 올릴 때는 반드시 버전 번호를 새로 올려야 한다"는 규칙이 npm 생태계에 확고히 자리 잡았다.

자바스크립트 문법이 크게 개편된 ES6(ES2015)를 Node.js가 정식으로 지원하기 시작한 것은 2018년이고, 지금처럼 안정적으로 쓸 수 있게 된 것은 2020년 이후다 — 즉 ES6이 발표된 시점과 실제 실행 환경(Node.js)에서 안정적으로 쓸 수 있게 된 시점 사이에는 상당한 간격이 있었다.

## 2. 실습 환경 준비 — 브라우저 없이 자바스크립트 실행하기

지금까지는 자바스크립트를 실습하려면 매번 HTML 파일을 만들고 브라우저를 띄워 콘솔을 확인해야 했다. Node.js를 설치하면 자바를 배울 때 콘솔에서 바로 실행했던 것처럼, HTML 없이 터미널에서 곧바로 자바스크립트 파일을 실행할 수 있다.

```
node ex1.js
```

## 3. 데이터 타입 개요 — 원시형 6가지

자바스크립트의 데이터 타입은 크게 다음과 같다.

- **Boolean**(불리언): `true`/`false`
- **Number**(숫자): 정수와 실수를 구분하지 않고 하나의 숫자 타입으로 통일해서 다룬다.
- **String**(문자열)
- **Undefined**: 변수는 선언했지만 아직 어떤 값도 할당(참조)한 적이 없을 때 자동으로 들어가는 기본값.
- **Null**: "값이 없다"는 것을 개발자가 직접 명시적으로 대입하는 값.

| 부울 | 정수 | 실수 | 문자 | 문자열 |
|---|---|---|---|---|
| `true`/`false` | `3` | `3.7` | `'A'` | `"Hello"` |

이 표는 값의 예시를 보여주기 위한 분류일 뿐, 실제 자바스크립트 타입 체계에서 "정수"와 "실수"는 둘 다 `Number` 하나로 통일되어 있고, "문자"와 "문자열"도 별도 타입 없이 전부 `String`으로 취급된다 — 작은따옴표로 감싼 한 글자(`'A'`)와 큰따옴표로 감싼 여러 글자(`"Hello"`)를 구분하는 자바 같은 언어와 달리, 자바스크립트는 글자 수와 무관하게 전부 문자열 타입 하나로 다룬다.

`undefined`와 `null`은 둘 다 "비어있음"을 나타내지만, 전자는 "아직 아무것도 대입한 적 없음(시스템이 자동으로 채운 값)"이고 후자는 "의도적으로 비웠음(개발자가 직접 대입한 값)"이라는 차이가 있다.

`undefined`는 문자열 `"undefined"`가 아니라 그 자체가 하나의 값이므로, 비교할 때도 문자열이 아니라 값 자체와 비교해야 한다.

```js
var x;
console.log(x);               // undefined
console.log(x === undefined); // true
```

이 둘을 혼동하면 정반대 결과가 나온다.

```js
var x;
console.log(x == "undefined"); // false — 문자열 "undefined"와 비교(거짓)
console.log(x == undefined);   // true  — undefined 값 자체와 비교(참)
```

`x`에는 `undefined`라는 **값**이 들어있는 것이지 `"undefined"`라는 **문자열**이 들어있는 게 아니므로, 따옴표로 감싼 문자열과 비교하면 항상 거짓이 된다.

## 4. 문자열 표기 — 작은따옴표와 큰따옴표

자바스크립트는 원칙적으로 작은따옴표(`'`)와 큰따옴표(`"`) 둘 다로 문자열을 표기할 수 있다. 이는 HTML 안에 `<script>` 태그를 통해 코드를 넣던 관행 때문이다 — HTML 속성값은 보통 큰따옴표로 감싸는데, 그 안에 자바스크립트 코드를 직접 쓸 경우 큰따옴표를 또 쓰면 충돌이 나므로 작은따옴표를 대신 쓰는 관례가 생겼다. 그래서 자바스크립트 자체는 원래 큰따옴표를 기본으로 여기지만, 상황에 따라 작은따옴표도 널리 섞어 쓴다. 다만 JSON처럼 더 엄격한 표준을 따르는 곳에서는 반드시 큰따옴표만 허용되므로, 문맥에 따라 구분해서 써야 한다.

## 5. 변수 선언과 "공간"이라는 개념의 함정

자바스크립트는 변수를 선언할 때 자료형을 명시하지 않는다 — `var x;`처럼 쓸 뿐, 정수인지 문자열인지 말하지 않는다. 다른 정적 타입 언어(자바 등)라면 변수는 "정해진 크기의 메모리 공간"이고, 선언 시점에 그 타입에 맞는 크기를 미리 확보한다. 그런데 자바스크립트는 같은 변수에 문자열도, 숫자도, 나중엔 아주 긴 문자열도 담을 수 있다 — 만약 변수가 "고정된 크기의 공간"이라면 이런 동작은 애초에 불가능하다.

이 모순은 자바스크립트에서 **모든 변수가 값 자체가 아니라 값에 대한 참조(주소)를 담기 때문에** 해결된다. 값을 직접 박아넣는 "값 변수"라는 개념 자체가 없고, 모든 변수는 크기가 똑같은 참조(주소)만 저장한다 — 그래서 어떤 값이 오든 변수 자체의 크기는 항상 동일하게 유지될 수 있는 것이다.

## 6. 원시값과 래퍼(Wrapper) 객체 — 자동 박싱

자바스크립트의 원시값(숫자·문자열·불리언)은 그 자체로는 속성이나 메서드를 갖지 않는 단순한 값이다. 그런데 실제로는 문자열에 `.length`나 여러 메서드를 자유롭게 쓸 수 있다.

```js
var s = "hello";
console.log(s.length); // 5
```

이것이 가능한 이유는, 원시값에 점(`.`)을 찍어 속성·메서드를 사용하려는 순간에 자바스크립트 엔진이 그 값을 임시로 **래퍼 객체**(`String`, `Number`, `Boolean` 같은 내장 클래스의 인스턴스)로 감싸서(**박싱**, boxing) 그 객체의 메서드를 실행한 뒤, 다시 원래의 원시값으로 되돌리기(**언박싱**) 때문이다. 원시값 자체는 객체가 아니지만, 필요한 그 순간에만 잠깐 객체로 둔갑했다가 다시 원시값으로 돌아가는 것이다.

이 관계를 직접 확인해볼 수도 있다.

```js
console.log(typeof 3);        // "number" — 원시값
var s1 = new String("hello");
console.log(typeof s1);       // "object" — 명시적으로 만든 래퍼 객체
console.log(s1.length);       // 5 (래퍼 객체이므로 당연히 메서드 사용 가능)

var s2 = "hello";             // 원시값으로 저장
console.log(s2.length);       // 5 (사용하는 순간에만 임시로 박싱됨)
```

`typeof`로 확인해보면 `3`이나 `"hello"`처럼 리터럴로 만든 값은 각각 `"number"`, `"string"`으로 나오지만, `new String(...)`처럼 명시적으로 생성자를 써서 만들면 `"object"`로 나온다 — 평소에는 원시값으로 가볍게 존재하다가, 메서드가 필요한 순간에만 래퍼 객체로 임시 변환되는 구조임을 보여준다.

## 7. 배열 — 자바스크립트에서는 배열이 곧 컬렉션이다

자바처럼 "배열"과 "컬렉션(ArrayList 등)"이 따로 존재하는 언어와 달리, 자바스크립트는 **배열 하나가 배열·스택·큐·덱의 역할을 모두 겸한다.** 별도의 컬렉션 라이브러리가 없고, 배열 자체에 이 모든 기능이 내장되어 있다.

### 7-1. 배열 생성과 인덱스의 함정

```js
var arr = new Array();
arr[0] = 5;
arr[1] = 10;
```

배열은 크기를 미리 정하지 않는다 — 어떤 인덱스에 값을 대입하든 그 인덱스를 담을 수 있을 만큼 자동으로 늘어난다. 이 특성은 실수로 큰 인덱스를 잘못 대입했을 때 위험할 수 있다.

```js
var nums = [];
nums[3] = 2;
console.log(nums); // [ <3 empty items>, 2 ]
```

인덱스 `0`, `1`, `2`를 건너뛰고 `3`에 값을 넣으면, 앞의 세 칸은 비어있는 상태로 배열의 길이만 늘어난다. 그래서 배열을 다룰 때 인덱스를 직접 계산해서 쓰는 방식은 되도록 피해야 한다 — 정말 세밀한 제어가 필요한 경우가 아니라면, 뒤에서 설명할 `push`/`shift` 등의 메서드나 `for...of` 순회를 쓰는 것이 안전하다.

배열을 초기화할 때 생성자에 인자를 하나만 주면 그 값은 **크기**로 해석되고, 두 개 이상을 주면 **초기값 목록**으로 해석된다.

```js
var a = new Array(5);       // 길이 5인 빈 배열
var b = new Array(1, 4, 6); // [1, 4, 6] — 3개의 초기값
```

또한 배열은 원소의 타입을 제한하지 않는다 — 숫자, 문자열, 객체가 한 배열 안에 섞여 있어도 문제없다. 이 때문에 `typeof`로 배열 원소를 검사하면, 원시값이 아닌 모든 것은 뭉뚱그려 `"object"`로만 나와서 정확한 타입 구분에는 한계가 있다.

### 7-2. 인덱스 없이 순회하기 — `for...of`

```js
var nums = [1, 2, 3];
for (const n of nums) {
    console.log(n);
}
```

인덱스로 `nums[i]`를 꺼내는 전통적인 `for`문 대신, `for...of`를 쓰면 배열 원소를 인덱스 없이 하나씩 순회할 수 있다. 배열을 다룰 때 인덱스 계산에 의존하는 습관은 실수를 만들기 쉬우므로, 인덱스가 굳이 필요하지 않다면 이 방식을 우선적으로 쓰는 것이 좋다.

### 7-3. 앞뒤로 넣고 빼기 — `push` / `shift` / `unshift` / `pop`

배열을 스택이나 큐, 버퍼처럼 쓸 때 자주 쓰는 4가지 메서드가 있다.

| 메서드 | 위치 | 동작 |
|---|---|---|
| `push(값)` | 뒤 | 값을 뒤쪽에 추가한다 |
| `shift()` | 앞 | 앞쪽 값을 꺼내서 제거하고 반환한다 |
| `unshift(값)` | 앞 | 값을 앞쪽에 끼워 넣는다 |
| `pop()` | 뒤 | 뒤쪽 값을 꺼내서 제거하고 반환한다 |

```js
var nums = [];
nums.push(1);
nums.push(5);
console.log(nums);        // [1, 5]

var first = nums.shift(); // 1을 꺼내면서 제거
console.log(first);       // 1
console.log(nums);        // [5]
```

`shift`/`pop`은 단순히 값을 조회만 하는 게 아니라, 그 값을 배열에서 실제로 **제거**하면서 반환한다는 점이 핵심이다. 앞으로 넣고 뒤로 빼거나(큐), 뒤로 넣고 뒤로 빼거나(스택), 양쪽 다 자유롭게 넣고 뺄 수 있어서(덱) 다양한 자료구조 형태를 이 4개 메서드 조합만으로 구현할 수 있다.

### 7-4. 중간 위치 조작 — `splice`

배열 중간에서 원소를 지우거나 끼워 넣을 때는 `splice`를 쓴다.

```js
var nums = [2, 4, 6, 8, 10];

// 삭제: splice(시작 인덱스, 지울 개수)
var removed = nums.splice(2, 1);
console.log(removed); // [6] — 잘려나간 값이 반환된다
console.log(nums);    // [2, 4, 8, 10]

// 삽입: splice(시작 인덱스, 0, 넣을값1, 넣을값2, ...)
nums.splice(2, 0, 11, 12);
console.log(nums);    // [2, 4, 11, 12, 8, 10]
```

`splice`의 두 번째 인자를 `0`으로 주면 아무것도 지우지 않고 그 위치에 값만 밀어 넣어서 삽입 효과를 낸다. 지울 개수를 `0`보다 크게 주면 그만큼 잘라내고, 잘려나간 부분이 결과값으로 반환된다.

`splice`는 세 번째 인자부터를 함께 써서 **삭제와 삽입을 한 번에** 처리할 수도 있다 — 지운 자리에 새 값을 끼워 넣는 "치환"이 가능하다는 뜻이다.

```js
var nums = [2, 4, 6, 8, 10];
var removed = nums.splice(2, 1, 11, 22);
console.log(nums);    // [2, 4, 11, 22, 8, 10] — 인덱스 2의 6이 지워지고 그 자리에 11, 22가 들어감
console.log(removed); // [6] — 실제로 잘려나간 값만 반환된다
```

`splice`는 원본 배열(`nums`)을 그 자리에서 직접 바꾸고(원본이 변형된다), 반환값은 어디까지나 "잘려나간(지워진) 값들"이라는 점을 기억해야 한다 — 새로 끼워 넣은 값이 반환되는 게 아니다.

앞뒤 조작(`push`/`pop`/`shift`/`unshift`)과 중간 조작(`splice`)을 조합하면, 배열을 다룰 때 인덱스를 직접 계산해야 하는 상황은 거의 없어진다.

## 8. 객체 — 정의 없이 속성을 그때그때 붙이는 방식

자바스크립트는 태생적으로 클래스 상속 개념이 없었다(ES6에서 `class` 문법이 흉내내기 형태로 추가되긴 했다). 그래서 "이 객체는 어떤 속성을 가질 것이다"라는 **정의(타입)** 자체가 없고, 객체를 일단 텅 빈 상태로 만든 뒤 필요할 때마다 속성을 하나씩 붙여나가는 방식으로 쓴다.

```js
var obj = new Object();
obj.korean = 30;
obj.english = 20;
console.log(obj.korean + obj.english); // 50
```

`korean`이라는 속성은 미리 정의되어 있던 게 아니라, `obj.korean = 30`이라고 대입하는 그 순간 생겨난다. 이 방식은 키(key)와 값(value)의 쌍을 자유롭게 담는 맵(Map) 컬렉션과 비슷한 역할을 한다.

**주의할 점**: 속성 이름은 대소문자를 엄격히 구분한다. `obj.Korean = 20;`처럼 오타로 대문자를 섞으면, 기존 `korean` 속성을 덮어쓰는 게 아니라 `Korean`이라는 **완전히 새로운 속성**이 추가되어버린다 — 계산 결과가 이상하게 나오는데 아무리 코드를 봐도 오류가 안 보이는 전형적인 원인 중 하나다.

### 8-1. 대괄호 표기법

속성 이름에 공백이나 하이픈처럼 변수명으로 쓸 수 없는 문자가 들어가야 할 때는, 점(`.`) 표기 대신 대괄호와 문자열을 쓴다.

```js
obj["background-color"] = "red";
```

이 방식은 CSS의 `style` 객체를 다룰 때도 똑같이 쓰였던 방식이다. 점 표기와 대괄호 표기는 완전히 동일한 의미이므로, 상황에 맞게 골라 쓸 수 있다.

### 8-2. 속성 삭제 — `delete`

```js
delete obj.english;
console.log(obj); // { korean: 30 }
```

배열에 값을 넣고 빼듯이, 객체도 `delete` 연산자로 속성 자체를 없앨 수 있다.

## 9. JSON — 객체를 직접 생성하지 않고 표기법으로 대신하기

`new String(...)`, `new Array()`, `new Object()`처럼 매번 생성자를 호출해서 값을 만드는 방식은 번거롭다. 자바스크립트는 이를 해결하기 위해, 값을 리터럴(literal) 형태로 그냥 표기하면 엔진이 알아서 해당 타입의 객체로 자동 박싱해주는 방식을 기본으로 제공한다.

| 타입 | 생성자를 쓰는 방식(JavaScript Object) | 리터럴 표기(JSON) |
|---|---|---|
| Boolean | `var n = new Boolean(true);` | `var n = true;` |
| Number | `var n = new Number(3);` | `var n = 3;` |
| String | `var s = new String("hello");` | `var s = "hello";` |
| Array | `var ar = new Array();` | `var ar = [];` |
| Object | `var ob = new Object();` | `var ob = {};` |

```js
var arr = [1, 2, 3];              // new Array() 없이 배열 리터럴
var obj = { korean: 30, english: 20 }; // new Object() 없이 객체 리터럴
```

이렇게 `new` 없이 값을 직접 표기하는 방식을 **JSON(JavaScript Object Notation)**이라 부른다 — 이름 그대로 "자바스크립트에서 객체를 표기하는 방법"일 뿐이다. 배열 리터럴(`[]`)이나 객체 리터럴(`{}`)을 쓰는 것이 `new Array()`/`new Object()`를 직접 호출하는 것보다 훨씬 자연스럽고 권장되는 방식이다.

객체 리터럴에서 속성명(키)은 원칙적으로 큰따옴표로 감싸야 하지만, 그 이름이 자바스크립트 변수명 규칙을 위배하지 않는다면(공백·하이픈 등이 없다면) 따옴표를 생략할 수 있다.

```js
var user = { "name": "김철수", age: 25 };
```

이런 객체·배열 리터럴을 중첩해서 쓰면, 계층 구조를 가진 데이터를 아주 간결하게 표현할 수 있다.

```js
var notices = [
    { title: "공지1", views: 10 },
    { title: "공지2", views: 20 }
];
console.log(notices[1].title); // "공지2"
```

이 간결함 때문에 JSON은 원래 자바스크립트 전용 표기법이었음에도, XML이나 CSV보다 데이터를 표현하기 간결하다는 장점 덕분에 특정 언어에 종속되지 않는 **범용 데이터 교환 표기법**으로 널리 채택되었다 — 지금은 자바, C# 등 다른 언어의 API에서도 데이터를 주고받는 표준 형식으로 JSON을 흔히 쓴다.

한 가지 주의할 점은, 서버에서 네트워크를 통해 JSON을 받아오면 그 데이터는 이미 완성된 자바스크립트 객체가 아니라 **하나의 문자열**로 전달된다는 것이다. 이 문자열을 실제 객체로 다루려면 별도의 파싱(`JSON.parse`) 과정이 필요하다.
