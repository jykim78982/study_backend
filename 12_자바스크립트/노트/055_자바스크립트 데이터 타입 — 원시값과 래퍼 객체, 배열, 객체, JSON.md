# 자바스크립트 데이터 타입 — 원시값과 래퍼 객체, 배열, 객체, JSON

## 1. Node.js 생태계의 성장 — npm, 사건사고, ES6 지원까지

Node.js가 등장한 뒤, 자바(JVM)나 닷넷처럼 실제로 쓸 만한 플랫폼이 되려면 그 위에서 동작하는 라이브러리들이 갖춰져야 했다. 초기 몇 년 사이에 웹 서버를 손쉽게 구성할 수 있는 **Express**, 실시간 통신을 위한 소켓 라이브러리 등이 잇달아 등장했고, 링크드인·우버 같은 실제 기업들이 Node.js 기반 서비스를 만들기 시작하면서 채택이 빠르게 확산됐다. 2015년 무렵에는 생태계가 충분히 성숙해 **OpenJS Foundation**(재단)이 만들어질 정도가 되었다.

**npm**(2011년경 등장)은 Node.js 생태계를 위한 패키지 저장소로, 자바의 Maven 저장소에 대응한다. 다만 초기에는 버전 관리 관행이 지금처럼 엄격하지 않아서 사고가 나기도 했다 — 대표적인 사례가 **"left-pad" 사건**이다. 어떤 개발자가 아주 작은 유틸리티 라이브러리(문자열 왼쪽 채우기 기능)를 수정해 올렸는데, 버그를 고친 변경사항인데도 버전 번호를 새로 올리지 않고 같은 버전 번호로 덮어써버렸다. 그 결과 어제까지 잘 동작하던 수많은 프로젝트가 갑자기 예상과 다르게 동작하며 장애를 일으켰다. 이 사건 이후로 "패키지를 수정해서 올릴 때는 반드시 버전 번호를 새로 올려야 한다"는 규칙이 npm 생태계에 확고히 자리 잡았다.

자바스크립트 문법이 크게 개편된 ES6(ES2015)를 Node.js가 정식으로 지원하기 시작한 것은 2018년이고, 지금처럼 안정적으로 쓸 수 있게 된 것은 2020년 이후다 — 즉 ES6이 발표된 시점과 실제 실행 환경(Node.js)에서 안정적으로 쓸 수 있게 된 시점 사이에는 상당한 간격이 있었다.

패키지를 다룰 때 `npm`과 함께 자주 쓰이는 것이 `npx`다. `npm install`이 라이브러리를 프로젝트의 의존성으로 **설치**하는 명령이라면, `npx`는 그 패키지를 전역으로 설치하지 않고도 **실행**만 해보거나, 이미 프로젝트에 설치되어 있는 CLI 도구를 실행할 때 쓴다 — 매번 전역 설치 여부를 신경 쓰지 않고 일회성으로 도구를 실행할 수 있게 해주는 역할이다.

## 2. 실습 환경 준비 — 브라우저 없이 자바스크립트 실행하기

지금까지는 자바스크립트를 실습하려면 매번 HTML 파일을 만들고 브라우저를 띄워 콘솔을 확인해야 했다. Node.js를 설치하면 자바를 배울 때 콘솔에서 바로 실행했던 것처럼, HTML 없이 터미널에서 곧바로 자바스크립트 파일을 실행할 수 있다.

```
node ex1.js
```

## 3. 데이터 타입 개요 — 원시형 6가지

자바스크립트의 데이터 타입은 크게 다음과 같다.

- **Boolean**(불리언): `true`/`false`
- **Number**(숫자): 정수와 실수를 구분하지 않고 하나의 숫자 타입으로 통일해서 다룬다.
- **String**(문자열)
- **Undefined**: 변수는 선언했지만 아직 어떤 값도 할당(참조)한 적이 없을 때 자동으로 들어가는 기본값.
- **Null**: "값이 없다"는 것을 개발자가 직접 명시적으로 대입하는 값.

| 부울 | 정수 | 실수 | 문자 | 문자열 |
|---|---|---|---|---|
| `true`/`false` | `3` | `3.7` | `'A'` | `"Hello"` |

이 표는 값의 예시를 보여주기 위한 분류일 뿐, 실제 자바스크립트 타입 체계에서 "정수"와 "실수"는 둘 다 `Number` 하나로 통일되어 있고, "문자"와 "문자열"도 별도 타입 없이 전부 `String`으로 취급된다 — 작은따옴표로 감싼 한 글자(`'A'`)와 큰따옴표로 감싼 여러 글자(`"Hello"`)를 구분하는 자바 같은 언어와 달리, 자바스크립트는 글자 수와 무관하게 전부 문자열 타입 하나로 다룬다.

`undefined`와 `null`은 둘 다 "비어있음"을 나타내지만, 전자는 "아직 아무것도 대입한 적 없음(시스템이 자동으로 채운 값)"이고 후자는 "의도적으로 비웠음(개발자가 직접 대입한 값)"이라는 차이가 있다.

`undefined`는 문자열 `"undefined"`가 아니라 그 자체가 하나의 값이므로, 비교할 때도 문자열이 아니라 값 자체와 비교해야 한다.

```js
var x;
console.log(x);               // undefined
console.log(x === undefined); // true
```

이 둘을 혼동하면 정반대 결과가 나온다.

```js
var x;
console.log(x == "undefined"); // false — 문자열 "undefined"와 비교(거짓)
console.log(x == undefined);   // true  — undefined 값 자체와 비교(참)
```

`x`에는 `undefined`라는 **값**이 들어있는 것이지 `"undefined"`라는 **문자열**이 들어있는 게 아니므로, 따옴표로 감싼 문자열과 비교하면 항상 거짓이 된다.

## 4. 문자열 표기 — 작은따옴표와 큰따옴표

자바스크립트는 원칙적으로 작은따옴표(`'`)와 큰따옴표(`"`) 둘 다로 문자열을 표기할 수 있다. 이는 HTML 안에 `<script>` 태그를 통해 코드를 넣던 관행 때문이다 — HTML 속성값은 보통 큰따옴표로 감싸는데, 그 안에 자바스크립트 코드를 직접 쓸 경우 큰따옴표를 또 쓰면 충돌이 나므로 작은따옴표를 대신 쓰는 관례가 생겼다. 그래서 자바스크립트 자체는 원래 큰따옴표를 기본으로 여기지만, 상황에 따라 작은따옴표도 널리 섞어 쓴다. 다만 JSON처럼 더 엄격한 표준을 따르는 곳에서는 반드시 큰따옴표만 허용되므로, 문맥에 따라 구분해서 써야 한다.

## 5. 변수 선언과 "공간"이라는 개념의 함정

자바스크립트는 변수를 선언할 때 자료형을 명시하지 않는다 — `var x;`처럼 쓸 뿐, 정수인지 문자열인지 말하지 않는다. 다른 정적 타입 언어(자바 등)라면 변수는 "정해진 크기의 메모리 공간"이고, 선언 시점에 그 타입에 맞는 크기를 미리 확보한다. 그런데 자바스크립트는 같은 변수에 문자열도, 숫자도, 나중엔 아주 긴 문자열도 담을 수 있다 — 만약 변수가 "고정된 크기의 공간"이라면 이런 동작은 애초에 불가능하다.

이 모순은 자바스크립트에서 **모든 변수가 값 자체가 아니라 값에 대한 참조(주소)를 담기 때문에** 해결된다. 값을 직접 박아넣는 "값 변수"라는 개념 자체가 없고, 모든 변수는 크기가 똑같은 참조(주소)만 저장한다 — 그래서 어떤 값이 오든 변수 자체의 크기는 항상 동일하게 유지될 수 있는 것이다.

## 6. 원시값과 래퍼(Wrapper) 객체 — 자동 박싱

자바스크립트의 원시값(숫자·문자열·불리언)은 그 자체로는 속성이나 메서드를 갖지 않는 단순한 값이다. 그런데 실제로는 문자열에 `.length`나 여러 메서드를 자유롭게 쓸 수 있다.

```js
var s = "hello";
console.log(s.length); // 5
```

이것이 가능한 이유는, 원시값에 점(`.`)을 찍어 속성·메서드를 사용하려는 순간에 자바스크립트 엔진이 그 값을 임시로 **래퍼 객체**(`String`, `Number`, `Boolean` 같은 내장 클래스의 인스턴스)로 감싸서(**박싱**, boxing) 그 객체의 메서드를 실행한 뒤, 다시 원래의 원시값으로 되돌리기(**언박싱**) 때문이다. 원시값 자체는 객체가 아니지만, 필요한 그 순간에만 잠깐 객체로 둔갑했다가 다시 원시값으로 돌아가는 것이다.

이 관계를 직접 확인해볼 수도 있다.

```js
console.log(typeof 3);        // "number" — 원시값
var s1 = new String("hello");
console.log(typeof s1);       // "object" — 명시적으로 만든 래퍼 객체
console.log(s1.length);       // 5 (래퍼 객체이므로 당연히 메서드 사용 가능)

var s2 = "hello";             // 원시값으로 저장
console.log(s2.length);       // 5 (사용하는 순간에만 임시로 박싱됨)
```

`typeof`로 확인해보면 `3`이나 `"hello"`처럼 리터럴로 만든 값은 각각 `"number"`, `"string"`으로 나오지만, `new String(...)`처럼 명시적으로 생성자를 써서 만들면 `"object"`로 나온다 — 평소에는 원시값으로 가볍게 존재하다가, 메서드가 필요한 순간에만 래퍼 객체로 임시 변환되는 구조임을 보여준다.

## 7. 배열 — 자바스크립트에서는 배열이 곧 컬렉션이다

자바처럼 "배열"과 "컬렉션(ArrayList 등)"이 따로 존재하는 언어와 달리, 자바스크립트는 **배열 하나가 배열·스택·큐·덱의 역할을 모두 겸한다.** 별도의 컬렉션 라이브러리가 없고, 배열 자체에 이 모든 기능이 내장되어 있다.

### 7-1. 배열 생성과 인덱스의 함정

```js
var arr = new Array();
arr[0] = 5;
arr[1] = 10;
```

배열은 크기를 미리 정하지 않는다 — 어떤 인덱스에 값을 대입하든 그 인덱스를 담을 수 있을 만큼 자동으로 늘어난다. 이 특성은 실수로 큰 인덱스를 잘못 대입했을 때 위험할 수 있다.

```js
var nums = [];
nums[3] = 2;
console.log(nums); // [ <3 empty items>, 2 ]
```

인덱스 `0`, `1`, `2`를 건너뛰고 `3`에 값을 넣으면, 앞의 세 칸은 비어있는 상태로 배열의 길이만 늘어난다. 그래서 배열을 다룰 때 인덱스를 직접 계산해서 쓰는 방식은 되도록 피해야 한다 — 정말 세밀한 제어가 필요한 경우가 아니라면, 뒤에서 설명할 `push`/`shift` 등의 메서드나 `for...of` 순회를 쓰는 것이 안전하다.

배열을 초기화할 때 생성자에 인자를 하나만 주면 그 값은 **크기**로 해석되고, 두 개 이상을 주면 **초기값 목록**으로 해석된다.

```js
var a = new Array(5);       // 길이 5인 빈 배열
var b = new Array(1, 4, 6); // [1, 4, 6] — 3개의 초기값
```

또한 배열은 원소의 타입을 제한하지 않는다 — 숫자, 문자열, 객체가 한 배열 안에 섞여 있어도 문제없다. 이 때문에 `typeof`로 배열 원소를 검사하면, 원시값이 아닌 모든 것은 뭉뚱그려 `"object"`로만 나와서 정확한 타입 구분에는 한계가 있다.

### 7-2. 인덱스 없이 순회하기 — `for...of`

```js
var nums = [1, 2, 3];
for (const n of nums) {
    console.log(n);
}
```

인덱스로 `nums[i]`를 꺼내는 전통적인 `for`문 대신, `for...of`를 쓰면 배열 원소를 인덱스 없이 하나씩 순회할 수 있다. 배열을 다룰 때 인덱스 계산에 의존하는 습관은 실수를 만들기 쉬우므로, 인덱스가 굳이 필요하지 않다면 이 방식을 우선적으로 쓰는 것이 좋다.

### 7-3. 앞뒤로 넣고 빼기 — `push` / `shift` / `unshift` / `pop`

배열을 스택이나 큐, 버퍼처럼 쓸 때 자주 쓰는 4가지 메서드가 있다.

| 메서드 | 위치 | 동작 |
|---|---|---|
| `push(값)` | 뒤 | 값을 뒤쪽에 추가한다 |
| `shift()` | 앞 | 앞쪽 값을 꺼내서 제거하고 반환한다 |
| `unshift(값)` | 앞 | 값을 앞쪽에 끼워 넣는다 |
| `pop()` | 뒤 | 뒤쪽 값을 꺼내서 제거하고 반환한다 |

```js
var nums = [];
nums.push(1);
nums.push(5);
console.log(nums);        // [1, 5]

var first = nums.shift(); // 1을 꺼내면서 제거
console.log(first);       // 1
console.log(nums);        // [5]
```

`shift`/`pop`은 단순히 값을 조회만 하는 게 아니라, 그 값을 배열에서 실제로 **제거**하면서 반환한다는 점이 핵심이다. 앞으로 넣고 뒤로 빼거나(큐), 뒤로 넣고 뒤로 빼거나(스택), 양쪽 다 자유롭게 넣고 뺄 수 있어서(덱) 다양한 자료구조 형태를 이 4개 메서드 조합만으로 구현할 수 있다.

### 7-4. 중간 위치 조작 — `splice`

배열 중간에서 원소를 지우거나 끼워 넣을 때는 `splice`를 쓴다.

```js
var nums = [2, 4, 6, 8, 10];

// 삭제: splice(시작 인덱스, 지울 개수)
var removed = nums.splice(2, 1);
console.log(removed); // [6] — 잘려나간 값이 반환된다
console.log(nums);    // [2, 4, 8, 10]

// 삽입: splice(시작 인덱스, 0, 넣을값1, 넣을값2, ...)
nums.splice(2, 0, 11, 12);
console.log(nums);    // [2, 4, 11, 12, 8, 10]
```

`splice`의 두 번째 인자를 `0`으로 주면 아무것도 지우지 않고 그 위치에 값만 밀어 넣어서 삽입 효과를 낸다. 지울 개수를 `0`보다 크게 주면 그만큼 잘라내고, 잘려나간 부분이 결과값으로 반환된다.

`splice`는 세 번째 인자부터를 함께 써서 **삭제와 삽입을 한 번에** 처리할 수도 있다 — 지운 자리에 새 값을 끼워 넣는 "치환"이 가능하다는 뜻이다.

```js
var nums = [2, 4, 6, 8, 10];
var removed = nums.splice(2, 1, 11, 22);
console.log(nums);    // [2, 4, 11, 22, 8, 10] — 인덱스 2의 6이 지워지고 그 자리에 11, 22가 들어감
console.log(removed); // [6] — 실제로 잘려나간 값만 반환된다
```

`splice`는 원본 배열(`nums`)을 그 자리에서 직접 바꾸고(원본이 변형된다), 반환값은 어디까지나 "잘려나간(지워진) 값들"이라는 점을 기억해야 한다 — 새로 끼워 넣은 값이 반환되는 게 아니다.

앞뒤 조작(`push`/`pop`/`shift`/`unshift`)과 중간 조작(`splice`)을 조합하면, 배열을 다룰 때 인덱스를 직접 계산해야 하는 상황은 거의 없어진다.

## 8. 객체 — 정의 없이 속성을 그때그때 붙이는 방식

자바스크립트는 태생적으로 클래스 상속 개념이 없었다(ES6에서 `class` 문법이 흉내내기 형태로 추가되긴 했다). 그래서 "이 객체는 어떤 속성을 가질 것이다"라는 **정의(타입)** 자체가 없고, 객체를 일단 텅 빈 상태로 만든 뒤 필요할 때마다 속성을 하나씩 붙여나가는 방식으로 쓴다.

```js
var obj = new Object();
obj.korean = 30;
obj.english = 20;
console.log(obj.korean + obj.english); // 50
```

`korean`이라는 속성은 미리 정의되어 있던 게 아니라, `obj.korean = 30`이라고 대입하는 그 순간 생겨난다. 이 방식은 키(key)와 값(value)의 쌍을 자유롭게 담는 맵(Map) 컬렉션과 비슷한 역할을 한다.

**주의할 점**: 속성 이름은 대소문자를 엄격히 구분한다. `obj.Korean = 20;`처럼 오타로 대문자를 섞으면, 기존 `korean` 속성을 덮어쓰는 게 아니라 `Korean`이라는 **완전히 새로운 속성**이 추가되어버린다 — 계산 결과가 이상하게 나오는데 아무리 코드를 봐도 오류가 안 보이는 전형적인 원인 중 하나다.

### 8-1. 대괄호 표기법

속성 이름에 공백이나 하이픈처럼 변수명으로 쓸 수 없는 문자가 들어가야 할 때는, 점(`.`) 표기 대신 대괄호와 문자열을 쓴다.

```js
obj["background-color"] = "red";
```

이 방식은 CSS의 `style` 객체를 다룰 때도 똑같이 쓰였던 방식이다. 점 표기와 대괄호 표기는 완전히 동일한 의미이므로, 상황에 맞게 골라 쓸 수 있다.

### 8-2. 속성 삭제 — `delete`

```js
delete obj.english;
console.log(obj); // { korean: 30 }
```

배열에 값을 넣고 빼듯이, 객체도 `delete` 연산자로 속성 자체를 없앨 수 있다.

## 9. JSON — 객체를 직접 생성하지 않고 표기법으로 대신하기

`new String(...)`, `new Array()`, `new Object()`처럼 매번 생성자를 호출해서 값을 만드는 방식은 번거롭다. 자바스크립트는 이를 해결하기 위해, 값을 리터럴(literal) 형태로 그냥 표기하면 엔진이 알아서 해당 타입의 객체로 자동 박싱해주는 방식을 기본으로 제공한다.

| 타입 | 생성자를 쓰는 방식(JavaScript Object) | 리터럴 표기(JSON) |
|---|---|---|
| Boolean | `var n = new Boolean(true);` | `var n = true;` |
| Number | `var n = new Number(3);` | `var n = 3;` |
| String | `var s = new String("hello");` | `var s = "hello";` |
| Array | `var ar = new Array();` | `var ar = [];` |
| Object | `var ob = new Object();` | `var ob = {};` |

```js
var arr = [1, 2, 3];              // new Array() 없이 배열 리터럴
var obj = { korean: 30, english: 20 }; // new Object() 없이 객체 리터럴
```

이렇게 `new` 없이 값을 직접 표기하는 방식을 **JSON(JavaScript Object Notation)**이라 부른다 — 이름 그대로 "자바스크립트에서 객체를 표기하는 방법"일 뿐이다. 배열 리터럴(`[]`)이나 객체 리터럴(`{}`)을 쓰는 것이 `new Array()`/`new Object()`를 직접 호출하는 것보다 훨씬 자연스럽고 권장되는 방식이다.

객체 리터럴에서 속성명(키)은 원칙적으로 큰따옴표로 감싸야 하지만, 그 이름이 자바스크립트 변수명 규칙을 위배하지 않는다면(공백·하이픈 등이 없다면) 따옴표를 생략할 수 있다.

```js
var user = { "name": "김철수", age: 25 };
```

이런 객체·배열 리터럴을 중첩해서 쓰면, 계층 구조를 가진 데이터를 아주 간결하게 표현할 수 있다.

```js
var notices = [
    { title: "공지1", views: 10 },
    { title: "공지2", views: 20 }
];
console.log(notices[1].title); // "공지2"
```

이 간결함 때문에 JSON은 원래 자바스크립트 전용 표기법이었음에도, XML이나 CSV보다 데이터를 표현하기 간결하다는 장점 덕분에 특정 언어에 종속되지 않는 **범용 데이터 교환 표기법**으로 널리 채택되었다 — 지금은 자바, C# 등 다른 언어의 API에서도 데이터를 주고받는 표준 형식으로 JSON을 흔히 쓴다.

한 가지 주의할 점은, 서버에서 네트워크를 통해 JSON을 받아오면 그 데이터는 이미 완성된 자바스크립트 객체가 아니라 **하나의 문자열**로 전달된다는 것이다. 이 문자열을 실제 객체로 다루려면 별도의 파싱(`JSON.parse`) 과정이 필요하다.

### 9-1. `eval` 대신 `JSON.parse` — 그리고 반대 방향 `JSON.stringify`

문자열로 전달된 JSON을 객체로 되돌리는 가장 원초적인 방법은 그 문자열을 그냥 코드처럼 실행해버리는 `eval`이었다. 하지만 `eval`은 전달받은 문자열을 통째로 코드로 실행하기 때문에, 그 문자열 안에 악의적인 코드가 섞여 있으면 그대로 실행되어버리는 보안 위험이 있다. 그래서 JSON을 다루는 환경에서는 `eval`을 쓰지 않고, JSON 전용 파서인 `JSON.parse`를 쓴다.

```js
var text = '{"id":1, "korName":"아메리카노"}';
var menu = JSON.parse(text);
console.log(menu.korName); // "아메리카노" — 문자열이 진짜 객체로 변환됨
```

반대로, 객체를 서버로 전송(POST 등)하려면 거꾸로 객체를 문자열로 바꿔야 한다. 이때는 `JSON.stringify`를 쓴다.

```js
var menu = { id: 1, korName: "아메리카노" };
var text = JSON.stringify(menu);
console.log(text); // '{"id":1,"korName":"아메리카노"}' — 겉보기엔 객체 같아도 실제로는 문자열이다
```

결국 자바스크립트에서 네트워크로 오가는 데이터는 항상 JSON 문자열로 시작해서 JSON 문자열로 끝난다 — 받을 때는 `JSON.parse`로 객체로 풀고, 보낼 때는 `JSON.stringify`로 문자열로 감싸는 왕복 작업이 기본이다.

## 10. 제어구조 — 배열을 순회하는 `for-in`과 `for-of`

반복문에는 익숙한 `while`, `for` 외에 배열(또는 객체)을 순회하기 위한 `for-in`과 `for-of`가 있다.

```js
var ar = ["철수", "영희", "맹구", "동천"];

for (var i in ar) {
    console.log(ar[i]);
}
// 철수
// 영희
// 맹구
// 동천

for (var v of ar) {
    console.log(v);
}
// 철수
// 영희
// 맹구
// 동천
```

두 문법의 결과가 같아 보이지만 순회하면서 실제로 꺼내주는 것이 다르다.

- **`for-in`**: 배열의 **인덱스(키)**를 하나씩 꺼내준다. 그래서 값을 쓰려면 `ar[i]`처럼 한 번 더 꺼내야 한다.
- **`for-of`**: 값 자체를 바로 꺼내준다. 인덱스가 필요 없다면 이쪽이 훨씬 간결하다.

객체(`Object`)에도 같은 문법을 적용하면 차이가 명확해진다.

```js
var menu = { id: 1, korName: "아메리카노" };

for (var key in menu) {
    console.log(key); // "id", "korName" — 키를 꺼내준다
}

for (var v of menu) {
    console.log(v); // 오류! 일반 객체는 for-of로 순회할 수 없다
}
```

일반 객체는 내부적으로 값을 순서 있는 목록 형태로 쌓아두는 컬렉션 구조가 아니라서 `for-of`로 순회할 수 없다. 반면 `Map` 같은 컬렉션은 내부적으로 `[키, 값]` 쌍(entry)을 배열처럼 순서대로 쌓아두는 구조라서 `for-of`로 순회할 수 있는데, 이때 꺼내지는 것은 값 하나가 아니라 **키와 값이 한 쌍으로 묶인 entry**다.

## 11. 값 비교 — `==`과 `===`이 둘 다 있는 이유

원시값을 담을 때 자바스크립트는 필요한 순간에만 래퍼 객체로 임시 박싱한다는 것을 앞서 봤는데, 이렇게 값이 "박스(객체)"에 담기는 상황에서는 비교할 대상이 두 가지로 나뉜다 — 박스(참조) 자체가 같은지, 아니면 박스 안에 든 값이 같은지. 두 종류의 비교가 필요한데 이를 매번 함수 호출로 구분해서 표현하면 번거로우므로, 자바스크립트는 이를 기호 하나로 구분해서 연산자로 제공한다.

- **`==`**: 타입이 다르면 먼저 타입을 맞추도록 변환한 뒤, **값**이 같은지 비교한다.
- **`===`**: 타입 변환 없이 타입과 값이 **모두** 같아야 참이다.

```js
console.log(1 == "1");   // true  — 문자열 "1"을 숫자로 바꿔서 값만 비교
console.log(1 === "1");  // false — 타입(number vs string)이 다르므로 거짓
console.log(1 === 1);    // true  — 타입도 값도 같음
```

값 비교(`==`)가 일상적으로 훨씬 자주 쓰이는 비교이기 때문에 더 짧고 단순한 기호(`==`)가 배정되었고, 타입까지 엄격하게 따지는 비교(`===`)는 상대적으로 덜 쓰이는 만큼 조금 더 긴 기호(`===`)가 배정되었다고 이해하면 된다.

객체를 `===`로 비교할 때는 이 기준이 그대로 "참조가 같은가"로 이어진다 — 객체는 원시값과 달리 변수에 값 자체가 아니라 참조(주소)가 저장되므로, 내용이 완전히 같은 객체라도 서로 다른 메모리 위치에 만들어졌다면 `===`는 거짓을 반환한다.

```js
var a = { id: 1 };
var b = { id: 1 };
console.log(a === b); // false — 내용은 같지만 서로 다른 객체(참조가 다름)
console.log(a === a); // true  — 같은 객체를 가리키는 참조끼리 비교
```

## 12. 참 같은 값과 거짓 같은 값 — Truthy / Falsy

자바스크립트는 `if` 조건식 자리에 불리언 값만 오도록 강제하지 않는다. 숫자든 객체든 배열이든 무엇이든 올 수 있고, 그 값을 불리언으로 변환했을 때의 결과에 따라 조건이 참/거짓으로 갈린다.

이 변환 규칙을 전부 외울 필요는 없다 — **거짓(Falsy)으로 취급되는 값만** 기억하면, 그 외 나머지는 전부 참(Truthy)이라고 보면 된다.

| 거짓(Falsy)으로 취급되는 값 |
|---|
| `false` |
| `0`, `-0` |
| `""` (빈 문자열) |
| `null` |
| `undefined` |
| `NaN` |
| `0n` (BigInt 0) |

이 목록에 없는 값은 전부 참(Truthy)으로 취급된다 — `"0"`이나 `"false"`처럼 거짓처럼 보이는 문자열도 빈 문자열이 아닌 이상 참이고, `{}`나 `[]`처럼 비어있는 객체·배열도 참이며, 음수(`-42`)나 `Infinity`, `-Infinity`도 모두 참이다.

## 13. 단락 평가(Short-circuit evaluation) — `||`와 `&&`

`||`(OR)와 `&&`(AND)는 두 값을 비교해서 불리언 결과를 만들어내는 연산이 아니라, **둘 중 한쪽 값을 그대로 반환하는 연산**이다.

### 13-1. `||` — 앞이 참이면 앞을, 거짓이면 뒤를 반환

```js
var o1 = true  || true;      // t || t → true
var o2 = false || true;      // f || t → true
var o4 = false || (3 == 4);  // f || f → false
var o6 = false || 'Cat';     // f || t → "Cat"
var o7 = 'Cat'  || false;    // t || f → "Cat" (뒤를 보지도 않고 앞을 그대로 반환)
var o9 = false  || '';       // f || f → ""
```

앞의 값이 참(truthy)이면 뒤는 아예 평가하지 않고 앞의 값을 그대로 반환하고, 앞의 값이 거짓(falsy)이면 뒤의 값을 그대로 반환한다 — 뒤의 값이 참인지 거짓인지는 따지지 않고 뒤의 값 자체를 반환한다.

이 특성을 이용하면 여러 후보값 중 처음 나오는 참값을 찾아낼 수 있다.

```js
var result = null || 0 || undefined || '' || ' ' || 2 || 'hello';
console.log(result); // " " (공백 한 칸) — 앞에서부터 순서대로 처음 만나는 참값에서 멈춘다
```

`null`, `0`, `undefined`, `""`는 모두 거짓이라 차례로 건너뛰고, 공백 한 칸(`' '`)은 빈 문자열이 아니므로 참이 되어 그 값에서 평가가 멈춘다.

### 13-2. `&&` — 앞이 거짓이면 앞을, 참이면 뒤를 반환

`&&`는 반대로 동작한다.

```js
var o3 = true  && false;     // t && f → false
var o5 = 'Cat' && 'Dog';     // t && t → "Dog" (앞이 참이므로 뒤를 반환)
var o6 = false && 'Cat';     // f && t → false (앞이 거짓이므로 뒤를 보지도 않고 앞을 반환)
```

앞의 값이 거짓이면 뒤는 평가하지 않고 앞의 값을 그대로 반환하고, 앞의 값이 참이면 뒤의 값을 그대로 반환한다.

### 13-3. 실전 활용 — `||`를 이용한 기본값 대입

```js
function printScore(score) {
    score = score || 0;
    console.log("당신의 성적은 " + score + "입니다.");
}
```

`score`에 `null`이나 `undefined`처럼 값이 안 들어온 경우 앞의 값이 거짓이 되어 뒤의 `0`이 기본값으로 대입된다. 다만 이 방식에는 허점이 있다 — 정말 점수가 `0`점이거나 빈 문자열인 경우조차 falsy로 취급되어 의도치 않게 기본값 `0`으로 덮어써진다. 값이 "아예 없는 것"(`null`/`undefined`)과 "0이나 빈 문자열 같은 정당한 값"을 구분하지 못하는 것이 문제다.

## 14. null 병합 연산자 — `??`

앞의 `||` 기본값 대입 방식의 허점을 보완하기 위해 등장한 것이 `??`(nullish coalescing) 연산자다. 이 연산자는 앞의 값이 `null` 또는 `undefined`일 때만 뒤의 값을 대입하고, 그 외의 falsy 값(`0`, `""` 등)은 정상적인 값으로 인정해서 그대로 둔다.

```js
function printScore(score) {
    score = score ?? 0;
    console.log("당신의 성적은 " + score + "입니다.");
}

printScore(0);  // "당신의 성적은 0입니다." — 0은 정당한 값이므로 유지된다
printScore();   // "당신의 성적은 0입니다." — undefined이므로 기본값 0이 대입된다
```

## 15. `NaN`과 `Infinity`

사칙연산에서 피연산자의 타입이 다르면 자바스크립트가 자동으로 타입을 맞추려고 시도한다.

```js
console.log("3" + "3"); // "33" — 문자열끼리는 이어붙이기(+)
console.log("3" + 3);   // "33" — 숫자를 문자열로 바꿔서 이어붙임
console.log("3" * "3"); // 9   — 곱셈은 숫자만의 연산이라 문자열을 숫자로 변환
console.log("3" * 3);   // 9
console.log("a" * 3);   // NaN — "a"는 숫자로 변환할 수 없음
```

곱셈처럼 숫자 연산에서만 의미 있는 연산자를 만나면, 문자열이라도 숫자로 바꿀 수 있는 형태(`"3"`)라면 변환해서 계산하지만, 숫자로 바꿀 수 없는 문자열(`"a"`)을 만나면 변환에 실패했다는 뜻으로 **`NaN`(Not a Number)** 을 반환한다. `NaN`은 앞서 정리한 falsy 값 중 하나이기도 하다.

`Infinity`는 자바스크립트가 다룰 수 있는 숫자 범위의 최댓값을 벗어났을 때 나오는 값이다 — 아주 큰 두 수를 곱하는 등으로 표현 가능한 범위를 넘어서면 오류 대신 `Infinity`(무한)라는 값으로 처리된다.

`NaN`을 검사할 때 `=== NaN`으로 비교하면 안 된다는 점도 함께 기억해야 한다 — `NaN`은 자기 자신과 비교해도 항상 거짓이 나오는 유일한 값이라서, 전역 함수 `isNaN()`이나 더 엄격한 `Number.isNaN()`으로 검사해야 한다. 반대로 값이 유한한 숫자인지 확인할 때는 `Number.isFinite()`를 쓴다.

```js
var result = 3 * "a";
console.log(result === NaN);      // false — NaN은 자기 자신과도 같지 않다
console.log(Number.isNaN(result)); // true
console.log(Number.isFinite(result)); // false — NaN은 유한한 숫자가 아니다
```

## 16. 함수를 만드는 여러 방법

자바스크립트에는 함수를 "정의"하는 문법이 따로 있는 게 아니라, 함수도 결국 객체를 만들고 그 객체를 변수에 대입하는 것일 뿐이다. 같은 함수를 만드는 방법이 여러 가지 있다.

```js
// 1) Function 생성자로 직접 만들기 — 실제로는 거의 쓰이지 않는다
var add = new Function("x, y", "return x+y;");

// 2) 함수 표현식 — 가장 일반적으로 쓰는 방식
var add = function (x, y) {
    return x + y;
};

// 3) 함수 선언문
function add(x, y) {
    return x + y;
}

console.log(add(3, 4)); // 7
```

`new Function(...)`처럼 생성자를 직접 호출하는 방식은 문법이 번거로워서 실무에서는 거의 쓰이지 않고, 그 대신 함수를 값처럼 변수에 대입하는 **함수 표현식** 형태가 널리 쓰인다.

ES6부터는 함수 표현식을 더 짧게 쓸 수 있는 **화살표 함수(arrow function)** 문법도 함께 쓰인다.

```js
var add = (a, b) => a + b;
console.log(add(3, 4)); // 7
```

화살표 함수는 리액트의 함수형 컴포넌트를 작성할 때도 함수 표현식과 함께 가장 널리 쓰이는 형태다.

### 16-1. 매개변수의 정체 — `arguments`

함수를 호출할 때 전달한 인자들은 사실 매개변수 이름을 거치지 않고도 **`arguments`** 라는 내장 컬렉션(유사 배열)에 순서대로 담긴다. 매개변수 이름(`x`, `y`처럼 선언하는 것)은 이 `arguments`의 각 위치에 붙이는 별칭일 뿐이다.

```js
function sum() {
    return arguments[0] + arguments[1];
}
console.log(sum(3, 5)); // 8 — 매개변수를 선언하지 않아도 인자는 arguments에 담긴다
```

매개변수를 선언해두면 `arguments[0]`, `arguments[1]`, ... 이 각각 자동으로 `x`, `y`, ... 라는 이름에 담기는 것뿐이므로, 선언한 매개변수 개수보다 더 많은 인자를 전달해도 오류가 나지 않는다 — 다만 선언된 이름 이상의 초과분은 이름으로는 접근할 수 없고 `arguments[n]`으로만 꺼낼 수 있다.

```js
function add(x, y) {
    return x + y;
}
var sum = add(2, 3, "hello", 3, 4, 5, 6, 7, 87);
console.log(sum); // 5 — 뒤에 넘긴 값들은 x, y로 받지 않으므로 그냥 무시된다
```

`arguments`는 배열이 아니라 배열을 흉내 낸 유사 배열 객체라서 `push`/`map` 같은 배열 메서드를 바로 쓸 수 없다는 한계가 있다. ES6부터는 이를 보완하기 위해 매개변수 앞에 `...`을 붙이는 **나머지 매개변수(rest parameter)** 문법이 추가되었는데, 이렇게 받으면 진짜 배열이므로 배열 메서드를 그대로 쓸 수 있다.

```js
function sumAll(...numbers) {
    return numbers.reduce((total, value) => total + value, 0);
}
console.log(sumAll(1, 2, 3)); // 6
```

## 17. 호이스팅과 선언되지 않은 변수

`var`로 선언한 변수는 코드에서 실제로 등장하는 위치와 무관하게, 그 변수가 속한 스코프의 맨 위로 선언 자체가 끌어올려진 뒤 실행된다 — 이를 **호이스팅(hoisting)** 이라 한다.

```js
console.log(x); // undefined (에러가 아니다!)
var x = 1;
```

`var x`라는 선언만 위로 끌어올려지고, `= 1`이라는 대입은 원래 코드에 쓰인 위치에서 그대로 실행되기 때문에, 선언보다 먼저 참조한 시점에는 "선언은 되어 있지만 아직 값이 대입되지 않은" 상태 — 즉 `undefined`가 나온다.

반면 아예 선언 자체가 없는 변수를 참조하면 호이스팅될 선언 자체가 없으므로 오류가 난다.

```js
console.log(y); // ReferenceError: y is not defined
```

그런데 `var` 선언 없이 그냥 값을 대입만 하면, 이때는 변수가 아니라 **전역 객체의 속성**이 새로 생기는 것이다 — 브라우저에서는 `window` 객체, Node.js에서는 `global` 객체가 이 역할을 한다.

```js
z = 3;            // var 없이 대입 → 전역 객체(window/global)의 속성으로 취급됨
console.log(z);   // 3
```

`var` 선언과 달리 이런 암묵적 전역 속성 생성은 호이스팅되지 않는다 — 대입문이 실제로 실행되기 전까지는 그 속성 자체가 존재하지 않으므로, 대입보다 먼저 참조하면 여전히 오류가 난다.

다만 함수 안에서는 얘기가 다르다 — `var` 선언이 그 **함수 전체 스코프**의 최상단으로 호이스팅되기 때문에, 선언 없이 값을 대입하는 코드보다 나중에 나오더라도 같은 함수 안에 `var`로 선언된 적이 있다면 그 대입은 전역이 아니라 그 지역 변수를 가리키게 된다.

```js
function f() {
    d = 3;              // 아래에 var d가 있으므로 전역이 아니라 지역 변수 d에 대입됨
    console.log(global.d); // undefined — 전역 객체를 오염시키지 않았다
    var d;
}
f();
```

즉 "선언 없이 대입하면 전역 객체 속성이 된다"는 규칙은 그 함수(또는 스코프) 안 어디에도 같은 이름의 `var` 선언이 없을 때만 적용된다. 이 때문에 실수로 전역을 오염시키는 문제를 막으려면, 값을 대입하기 전에 반드시 `var`(또는 `let`/`const`)로 선언하는 습관이 중요하다.

## 18. `let`/`const`와 일시적 사각지대(TDZ)

`var`의 함수 스코프·호이스팅·전역 오염 문제 때문에, ES6부터는 `let`과 `const`를 기본 선언 키워드로 쓰는 것이 권장된다.

- **`const`**: 다시 대입(재할당)할 필요가 없는 값에 쓴다.
- **`let`**: 나중에 값을 바꿔야 하는 변수에 쓴다.
- **`var`**: 함수 스코프와 중복 선언, 암묵적 전역 생성 문제가 있어 새 코드에서는 피하는 것이 좋다.

`let`/`const`도 `var`처럼 선언 자체는 호이스팅되지만, `var`처럼 곧바로 `undefined`로 초기화되지 않는다. 선언문에 도달하기 전까지는 그 변수가 존재는 하되 접근이 금지된 상태인데, 이 구간을 **일시적 사각지대(TDZ, Temporal Dead Zone)**라 부른다.

```js
console.log(a); // undefined — var는 선언과 동시에 undefined로 초기화됨
var a = 1;

console.log(b); // ReferenceError — TDZ 구간이라 아직 접근할 수 없음
let b = 1;
```

`var`는 선언 전에 참조해도 조용히 `undefined`를 내어주기 때문에 실수를 늦게 발견하게 되지만, `let`/`const`는 선언보다 먼저 참조하는 순간 바로 오류를 던져서 실수를 즉시 드러내준다는 점이 `let`/`const`를 기본으로 쓰는 것이 권장되는 이유 중 하나다.
