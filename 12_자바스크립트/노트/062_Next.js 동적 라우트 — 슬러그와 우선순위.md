# Next.js 동적 라우트 — 슬러그와 우선순위

메뉴 목록에서 항목을 눌러 상세 페이지로 이동할 때, `/menus/1`, `/menus/2`처럼 개수만큼 폴더를 만들 수 없는 문제를 Next.js가 어떻게 해결하는지를 다룬다.

## 1. 값마다 폴더를 만들 수는 없다

상세 페이지 URL은 `/menus/1`, `/menus/2`, `/menus/3`처럼 뒤에 식별자가 붙는 구조여야 한다. 하지만 이 식별자 하나하나를 실제 폴더로 만들어 대응시킬 수는 없다 — 데이터가 늘어날 때마다 폴더를 새로 만들어야 하기 때문이다.

## 2. 대괄호 폴더 — 동적 세그먼트

Next.js는 폴더 이름을 대괄호로 감싸는 방식으로 이 문제를 해결한다. `app/menus/[id]/page.js`처럼 만들면, `/menus/` 뒤에 오는 어떤 값이든 그 값을 `id`라는 이름의 파라미터로 받아 하나의 `page.js`가 처리한다.

```
app/menus/[id]/page.js
```

`/menus/1`, `/menus/2`, `/menus/아무값`이 모두 이 파일 하나로 들어오고, 그 "아무값"이 파라미터로 전달된다.

## 3. 슬러그(Slug)란

폴더 이름 자체는 자유롭게 지을 수 있으므로(`id`가 아니어도 됨) 관습적으로 이런 식별자를 **슬러그**라 부른다. 슬러그는 외부에 노출되는 콘텐츠 식별자로, 지켜야 할 조건은 하나다 — **동명이인처럼 겹치면 안 된다.** 같은 이름을 가진 글이 두 개 있으면 어떤 것을 가리키는지 알 수 없기 때문에, 슬러그는 절대 중복을 허용하지 않는 값(주로 숫자 ID)으로 관리한다.

## 4. 구체적인 라우트가 우선한다

동적 세그먼트 폴더와 일반 폴더가 같은 위치에 함께 있으면, **이름이 정해진 구체적인 라우트가 먼저 적용되고, 나머지 값은 동적 세그먼트가 받아간다.**

```
app/menus/new/page.js     ← "new"라는 구체적인 경로 전용
app/menus/[id]/page.js    ← 그 외 나머지 값(1, 2, 3, ...)
```

`/menus/new`로 들어오면 `new/page.js`가 그 요청을 그대로 가져가고, `/menus/1`처럼 `new`에 해당하지 않는 나머지 값들만 `[id]/page.js`가 처리한다. 스위치문에서 각 case에 해당하지 않는 나머지를 `default`가 받아가는 것과 같은 구조다.

## 5. 정리

| 상황 | 대응 |
|---|---|
| URL 끝에 가변적인 식별자가 붙어야 할 때 | 폴더 이름을 대괄호로 감싼 동적 세그먼트(`[id]`) 사용 |
| 식별자가 외부에 노출될 때 지켜야 할 조건 | 중복되지 않는 값(슬러그)이어야 함 |
| 동적 세그먼트와 구체적인 이름의 폴더가 겹칠 때 | 구체적인 이름의 폴더가 우선, 나머지는 동적 세그먼트가 처리 |
