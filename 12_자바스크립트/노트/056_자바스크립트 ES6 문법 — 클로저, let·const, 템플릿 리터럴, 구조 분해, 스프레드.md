# 자바스크립트 ES6 문법 — 클로저, let·const, 템플릿 리터럴, 구조 분해, 스프레드

## 1. 함수 중첩과 아우터(outer) 변수

자바스크립트를 포함한 최근 언어들은 함수 안에 함수를 중첩해서 정의할 수 있다. 이때 안쪽 함수(이너 함수)에서 자신에게는 없는 변수를 참조하면, 그 함수를 감싸고 있는 바깥쪽 함수(아우터 함수)의 변수를 대신 찾아서 쓴다.

```js
var x = 100; // 전역 변수

var f1 = function () {
    var x = 40;

    var f2 = function () {
        console.log(x); // 자신에게 없는 x를 아우터(f1)에서 찾아 씀
    };

    f2();
};
f1(); // 40 — 전역 x(100)가 아니라 f1의 x(40)를 씀
```

전역에 `x = 100`이 있어도, `f2`는 자신에게 `x`가 없으므로 자신을 감싸고 있는 가장 가까운 스코프부터 순서대로 찾아 올라간다 — 바로 위인 `f1`에 `x = 40`이 있으므로 거기서 멈추고, 더 바깥에 있는 전역 `x = 100`까지는 찾아가지 않는다. 즉 스코프 체인은 안쪽에서 바깥쪽으로 탐색하며, 더 가까운 스코프의 변수가 항상 우선한다.

원래 지역 변수는 함수가 호출될 때 만들어지고, 그 함수 호출이 끝나면 함께 사라지는 것이 정상이다. 이너 함수도 호출되어 실행이 끝나면 곧바로 사라지므로, 이 예시처럼 이너 함수가 아우터 함수 실행 도중에만 쓰이고 끝난다면 별다른 문제가 없다.

## 2. 클로저(Closure) — 아우터 변수를 붙잡고 있는 함수

문제는 이너 함수가 아우터 함수보다 더 오래 살아남는 경우다. 이너 함수를 외부(전역 변수 등)에 대입해서 아우터 함수가 끝난 뒤에도 그 이너 함수가 계속 존재하게 되면, 그 이너 함수가 참조하고 있는 아우터 변수도 함께 살아남아야 한다.

```js
var f3;
var x = 100;

var f1 = function () {
    var x = 40;

    f3 = function () {
        console.log(x);
    };
};

f1();
f3(); // 40 — f1은 이미 끝났지만, f3이 f1의 x를 붙잡고 있어서 살아있다
```

`f1`의 실행은 이미 끝났지만, 전역 변수 `f3`에 대입된 이너 함수가 `f1`의 지역 변수 `x`를 참조하고 있는 한 그 `x`는 사라지지 못한다. 이렇게 **자신을 둘러싼 함수보다 더 오래 살아남아 그 함수의 지역 변수를 계속 참조하는 함수**를 클로저(closure)라고 부른다.

클로저는 실수로 만들어지기도 하지만, 의도적으로 활용되는 경우도 많다. 아우터 함수의 변수를 여러 이너 함수가 공유하는 "상태 저장소"처럼 쓸 수 있기 때문이다 — 마치 객체지향에서 여러 메서드가 같은 인스턴스 속성을 공유하는 것과 비슷한 역할을 한다. 이 원리는 이후 다룰 리액트의 상태 관리 방식(후크 함수)에서도 그대로 쓰인다.

### 2-1. 반복문에서 클로저를 잘못 쓰면 생기는 문제

여러 함수를 배열에 담아 반복적으로 만들 때, 그 함수들이 전부 같은 아우터 변수를 참조하고 있으면 실행 시점에 예상과 다른 값이 나올 수 있다. 반복될 때마다 그 시점의 값을 각각 복사해서 갖는 게 아니라, 반복이 다 끝난 뒤의 **최종 값 하나**를 모든 함수가 공유해서 바라보기 때문이다. 함수를 만드는 시점의 값이 그대로 고정될 거라고 착각하지 않도록 주의해야 한다.

```js
var funcs = [];
for (var i = 0; i < 3; i++) {
    funcs.push(function () {
        console.log(i);
    });
}
funcs[0](); // 3
funcs[1](); // 3
funcs[2](); // 3 — 셋 다 반복이 끝난 뒤의 최종 값(3)을 바라봄
```

`var i`는 `for`문 전체에서 단 하나만 존재하는 변수라서, 세 함수 모두 같은 `i`를 참조하는 클로저가 된다. 반복이 다 끝난 시점 `i`의 값은 3이므로, 나중에 어느 함수를 호출하든 전부 3이 출력된다.

`let`으로 바꾸면 결과가 달라진다.

```js
var funcs2 = [];
for (let j = 0; j < 3; j++) {
    funcs2.push(function () {
        console.log(j);
    });
}
funcs2[0](); // 0
funcs2[1](); // 1
funcs2[2](); // 2 — 각 함수가 그 반복 차례의 j를 따로 붙잡고 있음
```

`let`은 반복마다 **새로운 지역 변수**를 만들어주기 때문에, 각 함수가 만들어질 당시의 `j` 값을 각각 따로 붙잡게 되어 의도한 대로 0, 1, 2가 순서대로 출력된다.

## 3. var의 문제와 let의 등장

기존 `var`에는 여러 문제가 있었다.

**문제 1 — 같은 이름으로 재선언해도 오류가 나지 않는다.**

```js
var x = 3;
var x = 4; // 오류 없이 그냥 덮어써짐 — 실수를 잡아주지 못함
```

**문제 2 — 지역화(스코프)가 제대로 되지 않는다.**

```js
{
    var x = 5;
}
console.log(x); // 5 — 블록이 끝났는데도 x가 살아있음
```

변수가 특정 범위(스코프) 안에서만 살고 그 범위를 벗어나면 사라져야, 서로 다른 코드 영역의 변수들이 이름 충돌 없이 안전하게 공존할 수 있다. `var`는 이 지역화가 제대로 되지 않아 코드가 커질수록 변수 이름 충돌 위험이 커진다.

`let`은 이 두 문제를 모두 해결한다.

```js
let x = 3;
let x = 4; // SyntaxError — 이미 선언된 변수입니다

{
    let y = 5;
    console.log(y); // 5
}
console.log(y); // ReferenceError — y is not defined
```

`let`으로 선언한 변수는 함수 호출 스택에 쌓이는 "스택 프레임" 단위(중괄호 블록)로 지역화된다. 블록이 시작되면 그 변수를 위한 공간이 만들어지고, 블록이 끝나면 그 공간이 스택에서 정상적으로 제거되어 더 이상 접근할 수 없다.

## 4. const — 재할당을 막는 상수형 변수

`const`는 자바의 `final`과 비슷한 역할을 한다. 한 번 값을 대입하면 이후에는 절대로 다른 값을 다시 대입할 수 없다.

```js
const add = function (x, y) {
    return x + y;
};

add = 4; // TypeError: Assignment to constant variable.
```

함수를 변수에 대입해서 정의할 때는, 그 함수가 중간에 다른 값으로 실수로 덮어써지는 것을 막기 위해 `var`나 `let`이 아니라 `const`로 선언하는 것이 바람직하다.

## 5. 템플릿 리터럴 — 백틱과 `${}`

문자열 안에 변수 값을 끼워 넣을 때, 과거에는 `+` 연산자로 문자열을 끊었다 이어붙여야 했다.

```js
let korName = "아메리카노";
let price = 2000;

let template = "menu name : " + korName + ", menu price : " + price;
```

템플릿 리터럴을 쓰면 백틱(`` ` ``)으로 문자열을 감싸고, 그 안에 `${표현식}` 형태로 변수나 식을 바로 끼워 넣을 수 있다.

```js
let template = `menu name : ${korName}, menu price : ${price}`;
```

일반 문자열(`"`나 `'`로 감싼 문자열)은 줄바꿈을 그대로 쓸 수 없어서, 여러 줄을 이어 쓰려면 `+`로 문자열을 계속 연결하거나 각 줄 끝에 역슬래시(`\`)를 붙여야 했다. 백틱으로 감싼 템플릿 리터럴은 이런 제약 없이 줄바꿈을 그대로 쓸 수 있다.

### 5-1. `String.raw` — 이스케이프 문자를 그대로 출력하기

템플릿 리터럴 안에 `\t`(탭)나 `\n`(줄바꿈) 같은 표기를 쓰면 실제 탭·줄바꿈으로 해석된다. 이 표기를 해석하지 않고 문자 그대로("날것") 출력하고 싶을 때는 `String.raw`를 함수처럼 템플릿 앞에 붙인다.

```js
let template = String.raw`
\tmenu name : ${korName}, \
\tmenu price : ${price}`;
```

이렇게 하면 `\t`, `\`가 탭이나 줄바꿈으로 해석되지 않고 글자 그대로 출력된다.

## 6. 옵셔널 체이닝(`?.`) — 없을 수도 있는 속성·메서드 접근하기

객체에 특정 속성(특히 함수)이 있는지 없는지 확신할 수 없을 때, 그냥 점(`.`)으로 접근하면 그 속성이 없을 경우 오류가 난다.

```js
let menu = { id: 1, korName: "아메리카노", price: 2000 };

menu.info(); // TypeError: menu.info is not a function
```

`?.`을 쓰면 그 속성이 없을 때 오류를 내는 대신 `undefined`를 반환하고 그 자리에서 평가를 멈춘다.

```js
console.log(menu.info?.()); // undefined — info가 없어도 오류 없이 넘어감

let menu2 = {
    id: 1, korName: "아메리카노", price: 2000,
    add: function (x, y) { return x + y; }
};

let sum = menu2.add?.(4, 5);
if (sum !== undefined) console.log(sum); // 9
```

값이 있을 때만 안전하게 접근하고, 없으면 오류 대신 `undefined`로 처리해서 흐름을 직접 제어하고 싶을 때 유용하다.

## 7. 객체 리터럴 개선 — 속성 축약과 메서드 축약

**속성 축약(property shorthand)**: 변수 이름과 객체 속성 이름이 같을 때, 값을 중복해서 쓰지 않고 이름만 써도 된다.

```js
let kor = 30, eng = 40, math = 49;

// 과거 방식
let exam = { kor: kor, eng: eng, math: math };

// 축약형
let exam2 = { kor, eng, math };
```

**메서드 축약(method shorthand)**: 객체 안에 함수를 멤버로 정의할 때, `함수명: function() {...}` 대신 `함수명() {...}` 형태로 `function` 키워드 없이 쓸 수 있다.

```js
// 과거 방식
let exam3a = {
    kor, eng, math,
    total: function () {
        return this.kor + this.eng + this.math;
    }
};

// 축약형
let exam3 = {
    kor, eng, math,
    total() {
        return this.kor + this.eng + this.math;
    }
};

console.log(`total is ${exam3.total()}`);
```

## 8. 객체 구조 분해(Object Destructuring)

함수에 객체를 통째로 넘기고, 그 객체의 속성을 매번 `객체.속성명`으로 꺼내 쓰면 같은 접근 연산이 반복되어 코드가 복잡해진다.

```js
// 구조를 그대로 쓰는 방식 — 접근 연산이 반복됨
const printExam = function (exam) {
    console.log(`kor : ${exam.kor}`);
    console.log(`eng : ${exam.eng}`);
    console.log(`math : ${exam.math}`);
};
```

객체의 속성을 개별 변수로 그 자리에서 바로 꺼내는 것을 구조 분해라고 한다.

```js
const printExam = function (exam) {
    let { kor, eng, math } = exam; // 객체를 분해 해서 개별 변수로 선언
    let total = kor + eng + math;

    console.log(`kor : ${kor}`);
    console.log(`eng : ${eng}`);
    console.log(`math : ${math}`);
    console.log(`total is ${total}`);
};
```

구조가 있는 데이터(객체·배열)를 그 형태 그대로 여러 번 파고들어 쓰는 코드는 복잡도를 높인다. 구조 분해로 필요한 값을 미리 낱개의 변수로 꺼내놓으면, 그 아래 코드는 마치 평범한 변수만 다루는 것처럼 단순해진다.

## 9. 배열 구조 분해(Array Destructuring)

배열도 객체처럼 각 위치의 값을 개별 변수로 분해할 수 있다.

```js
let nums = [2, 3];
let [num1, num2] = nums;

console.log(`num1:${num1}, num2:${num2}`); // num1:2, num2:3
```

### 9-1. 배열 구조 분해로 값 교환(swap)하기

전통적으로 두 값을 맞바꾸려면 임시 변수가 필요했다.

```js
let temp = nums[0];
nums[0] = nums[1];
nums[1] = temp;
```

배열 구조 분해를 쓰면 임시 변수 없이 한 줄로 값을 교환할 수 있다.

```js
[nums[0], nums[1]] = [nums[1], nums[0]];
```

오른쪽에서 이미 자리를 바꿔 만든 배열을, 왼쪽에서 원래 순서대로 다시 분해해 담기 때문에 결과적으로 두 값이 서로 맞바뀐다.

## 10. `...` 연산자 — 스프레드(흩뿌리기)와 나머지 매개변수(모으기)

**스프레드(spread, 흩뿌리기)**: 배열을 함수에 인자로 통째로 넘기고 싶은데, 그 함수는 개별 인자를 따로 받도록 만들어져 있을 때 쓴다.

```js
const printNums = function (num1, num2, num3) {
    console.log(num1, num2, num3);
};

let nums1 = [3, 5, 6];
printNums(...nums1); // 배열을 낱개로 흩뿌려서 전달 → 3 5 6
```

`...`을 배열 앞에 붙이면 그 배열의 원소들이 각각 낱개의 인자로 풀려서 전달된다.

**나머지 매개변수(rest parameter)**: 반대로, 함수를 정의하는 쪽에서 몇 개가 들어올지 모르는 나머지 인자들을 하나의 배열로 한꺼번에 받고 싶을 때 매개변수 앞에 `...`을 붙인다.

```js
const printNums = function (num1, num2, num3, ...나머지값들) {
    console.log(num1, num2, num3, 나머지값들);
};

let nums1 = [3, 5, 6, 4, 7, 2, 5];
printNums(...nums1, 100);
// 3 5 6 [4, 7, 2, 5, 100] — 앞의 세 개만 개별 변수로, 그 뒤는 전부 배열로 묶임
```

같은 `...` 기호라도, **값을 보내는 쪽(호출부)에서 배열 앞에 쓰면 흩뿌리기(spread)**이고, **값을 받는 쪽(매개변수)에서 쓰면 나머지를 배열로 모으기(rest)**라는 정반대의 의미가 된다는 점에 유의해야 한다.

가변 인자를 받는 방법으로는 이미 `arguments`가 있는데, 왜 굳이 나머지 매개변수를 쓸까?

- `arguments`는 함수에 전달된 **모든** 인자를 담고 있을 뿐, "이름 붙인 매개변수 이후의 나머지만" 따로 골라주지는 않는다. 위 예시처럼 앞의 세 개(`num1`, `num2`, `num3`)와 그 뒤 나머지를 구분해서 받고 싶다면, `arguments`를 쓸 경우 `arguments[3]`부터 끝까지를 직접 잘라내는 코드를 따로 작성해야 한다.
- `arguments`는 진짜 배열이 아니라 배열을 흉내 낸 유사 배열 객체라서 `map`·`filter`·`reduce` 같은 배열 메서드를 바로 쓸 수 없다. 반면 나머지 매개변수(`...나머지값들`)로 받은 값은 처음부터 진짜 배열이므로 배열 메서드를 곧바로 쓸 수 있다.
- 화살표 함수에는 `arguments` 자체가 아예 만들어지지 않는다. 나머지 매개변수는 화살표 함수에서도 똑같이 쓸 수 있다.

즉 "여러 개 들어올 수 있는 인자를 배열로 다루고 싶다"는 목적이라면, 오래된 `arguments`보다 나머지 매개변수 쪽이 훨씬 간결하고 활용도도 높다.
