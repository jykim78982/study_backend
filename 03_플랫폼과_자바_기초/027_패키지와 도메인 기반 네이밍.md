# 패키지와 도메인 기반 네이밍

## 1. 패키지 — 클래스 이름을 유일하게 만들어주는 식별자

`package`는 클래스 이름을 **전 세계에서 유일(unique)하게** 만들어주는 식별자다.

클래스 이름만으로는 유일성이 보장되지 않는다. 사람 이름으로 비유하면, "철수"라는 이름은 세상에 한 명만 존재하지 않는다 — 같은 이름을 가진 사람이 얼마든지 있을 수 있다. 클래스도 마찬가지다. `Exam`이라는 이름의 클래스를 나만 만든다는 보장이 없다. 다른 개발자, 다른 라이브러리도 똑같이 `Exam`이라는 이름을 쓸 수 있고, 그렇게 되면 이름이 충돌한다.

## 2. 어떻게 진짜로 유일하게 만들 수 있는가 — 도메인

이름을 "진짜로, 확실하게" 유일하게 만들 수 있는 유일한 방법은 **돈을 주고 도메인을 사는 것**이다.

도메인은 구매하는 순간 전 세계에서 그 이름을 소유한 사람이 나뿐이라는 게 보장된다. 그래서 자바의 패키지 네이밍 관례는 **자신이 소유한 도메인을 거꾸로 뒤집은 형태**를 쓴다.

예를 들어 `example.com`이라는 도메인을 가진 회사라면, 패키지 이름은 이렇게 시작한다.

```java
package com.example;
```

`com`이라는 최상위 영역 아래 `example`이라는 이름은 **돈을 주고 산 사람만** 가질 수 있으므로, `com.example`로 시작하는 패키지 이름은 전 세계에서 나만 쓸 수 있는 이름이 된다.

여기서 범위를 더 좁혀서 하위 이름을 계속 덧붙일 수도 있다.

```java
package com.example.mylib;
package com.example.mylib.exam;
```

이렇게 세분화할수록 패키지 이름은 점점 길어지는데, 이는 "이름을 더 정확하게 좁혀가는 과정"이지 불필요하게 복잡해지는 게 아니다.

## 3. 패키지 이름 = 실제 폴더 구조

패키지 이름은 단순히 이름표가 아니라, **실제로 파일이 포장(패키징)될 때 사용되는 폴더 구조 그 자체**다. `com.example.mylib`라는 패키지는 실제로 `com/example/mylib/`라는 폴더 경로에 대응된다.

지금 이 스터디처럼 학습용으로 코드를 작성할 때는 이 규칙을 엄격하게 지키지 않아도 당장 문제가 되지 않는다. 하지만 실제로 뭔가를 만들어서 서비스로 배포할 때는, 도메인 네임을 기반으로 한 패키지 이름을 쓰는 게 정석이다. **도메인 네임이 없으면 이런 식의 유일한 패키지 이름 자체를 만들 수 없기 때문에, 정식으로 배포하기가 어려워진다.**

## 4. 정리

| 질문 | 답 |
|---|---|
| 왜 패키지가 필요한가 | 클래스 이름의 충돌(중복)을 막기 위해 |
| 왜 도메인 기반인가 | 도메인은 돈을 주고 사는 순간 전 세계에서 유일함이 보장되므로 |
| 패키지 이름의 실체는 무엇인가 | 실제 파일이 저장되는 폴더 구조 |
| 학습용과 실서비스용의 차이 | 학습 단계에서는 대충 지어도 되지만, 배포하려면 도메인 기반 패키지명이 필요 |
