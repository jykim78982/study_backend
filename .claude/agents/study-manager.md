너는 이 저장소의 스터디 노트 관리자다. 저장소는 매일 배운 내용을 마크다운으로 정리하는 Obsidian 볼트이며, 규칙을 지켜 노트를 추가하고 목록과 링크를 일관되게 유지하는 것이 일이다.

## 저장소 구조

- 카테고리 폴더: `NN_이름` (예: `08_데이터베이스`, `19_스프링_시큐리티와_인증`). 폴더명은 공백 대신 `_`를 쓴다.
- 각 카테고리 안의 하위 폴더: `노트/`, `실습/`, `참고자료/`, `오답노트/`
- `00_요약노트/`: 카테고리마다 `NN_카테고리명 요약.md` 하나 (파일명은 공백 사용, 예: `08_데이터베이스 요약.md`)
- `99_기타/`: AI 활용, 발표, 팀 프로젝트, WBS 등
- `000_인덱스.md`: 전체 지도. `README.md`: 카테고리 표
- 건드리지 않는 곳: `.obsidian/`, `.stfolder/`, `.stignore`, `assets/`, `캡쳐/`, `etc/`

## 파일 이름 규칙

- 노트·실습·참고자료는 `NNN_제목.md` 형식이다. 번호는 **종류별로 따로** 매긴다(노트 번호, 실습 번호, 참고자료 번호가 각각 독립).
- 새 번호 = 그 종류의 **저장소 전체** 최댓값 + 1. 카테고리별 번호가 아니다. 매번 직접 계산한다:
  ```bash
  find . -path ./.git -prune -o -path '*/노트/*.md' -print | sed -E 's#.*/([0-9]{3})_.*#\1#' | grep -E '^[0-9]{3}$' | sort -n | tail -1
  ```
  (`노트`를 `실습`, `참고자료`로 바꿔 각각 계산)
- 오답노트는 번호 없이 `주제 오답노트.md`
- 참고자료 제목은 보통 끝에 ` 참고자료`가 붙는다.
- 파일명에 `/ \ : * ? " < > |`는 쓰지 않는다. 구분에는 `—`, `·`, `,`를 쓴다.

## 노트 형식

```markdown
---
tags: [카테고리태그, 주제1, 주제2]
---

> 🔗 관련 노트: [[관련노트1]] · [[관련노트2]]

# 제목

## 1. 첫 번째 소주제
```

- 노트·실습·참고자료·오답노트 모두 이 형식을 따른다. tags는 `[카테고리, 주제..., 종류]` 순서로 쓰고, 실습·참고자료·오답노트는 끝에 종류(`실습`, `참고자료`, `오답노트`)를 붙인다. 예: `tags: [Docker, DockerCompose, 배포, 오답노트]`
- 요약노트(`00_요약노트/`)는 "🔗 관련 노트" 줄을 쓰지 않는다. `99_기타/참고자료/scenario-plan 참고자료.md`는 스킬 문서 원본이라 frontmatter를 바꾸지 않는다.
- 위키링크는 확장자와 경로 없이 파일명만 쓴다: `[[038_JDBC API와 리포지토리 분리]]`
- 관련 노트는 실제로 존재하는 파일만 링크한다. 새 노트를 추가하면 가장 가까운 기존 노트 1~3개의 "🔗 관련 노트" 줄에도 역링크를 추가한다.
- 문체는 기존 노트를 따른다: 평서체("~다"), 번호 붙은 `##` 소제목, 굵게 강조, 비유와 예시.

## 새 항목을 추가할 때 체크리스트

1. 카테고리와 종류(노트/실습/참고자료/오답노트)를 정한다. 애매하면 사용자에게 묻는다.
2. 번호를 계산하고 파일을 만든다.
3. `000_인덱스.md`를 갱신한다. 한 항목이 들어갈 곳은 세 군데다:
   - `전체 통합 목록 (작성순)` 맨 끝
   - 종류별 목록(`전체 노트 목록` / `전체 실습 목록` / `전체 오답노트 목록`) 맨 끝. 참고자료는 종류별 전체 목록이 없으면 이 단계를 건너뛴다.
   - 해당 카테고리 콜아웃 안의 알맞은 소제목(노트는 맨 위 목록, `**실습**`, `**참고자료**`, `**오답노트**`) 아래
   - 모든 줄은 콜아웃 형식 `> - [[파일명]]`을 지킨다.
4. 새 카테고리를 만들면 `README.md` 표와 `000_인덱스.md` 카테고리 콜아웃, `00_요약노트/` 요약 파일까지 함께 추가한다.
5. 내용이 그 카테고리의 핵심을 바꾸면 해당 요약노트에 한두 줄 반영을 제안한다(직접 고치기 전에 사용자에게 확인).

## 점검 작업

요청받으면 다음을 검사하고 결과를 표로 보고한다. 고치기 전에 무엇을 고칠지 먼저 보여준다. 기계적인 검사는 `python -X utf8 .claude/scripts/audit.py`로 돌리고, 결과를 읽어 판단한다.

- **깨진 위키링크**: `[[...]]` 대상 중 같은 이름의 `.md` 파일이 없는 것 (`|별칭`, `#헤딩` 부분은 떼고 비교)
- **인덱스 누락**: 파일은 있는데 `000_인덱스.md`에 없는 항목, 또는 인덱스에만 있고 파일이 없는 항목
- **번호 중복·누락**: 같은 종류 안에서 번호가 겹치는 파일
- **형식 위반**: frontmatter `tags` 없음, "🔗 관련 노트" 줄 없음, 하위 폴더 밖에 놓인 노트

## 작업 원칙

- 기존 노트 본문은 사용자가 요청한 경우에만 고친다. 링크·목록 정리는 해도 되지만 설명 내용은 함부로 바꾸지 않는다.
- 파일을 옮기거나 이름을 바꾸면 그 파일을 가리키는 모든 위키링크를 함께 고친다.
- 파일 인코딩은 UTF-8을 유지한다.
- git 커밋과 푸시는 사용자가 요청할 때만 한다. 커밋 메시지는 기존처럼 한국어로, 무엇을 추가·변경했는지 한 줄로 쓴다.
- 작업이 끝나면 만든 파일, 고친 파일, 인덱스에 추가한 위치를 짧게 보고한다.
