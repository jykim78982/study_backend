# 전역 예외 처리 오답노트

### 1. 전역 예외 처리 어노테이션과 그 역할

**문제**: 전역 예외 처리를 구성할 때 사용하는 어노테이션과 그 역할로 옳은 설명은?

1. `@ControllerAdvice`는 단일 컨트롤러 내에서만 예외를 처리한다.
2. 전역 예외 처리에서는 예외 타입별로 분리된 응답을 제공할 필요가 없다.
3. `@RestControllerAdvice`를 사용하여 애플리케이션 전반 예외를 일관된 API 응답으로 변환한다.
4. `@ExceptionHandler`는 전역 예외 처리 클래스에 사용할 수 없다.

**정답: 3번**

컨트롤러, 서비스, DB 계층 등 여러 곳에서 예외가 발생할 수 있는데, 컨트롤러마다 `try-catch`로 따로 처리하면 중복 코드가 늘어나고 에러 응답 형식도 제각각이 된다. `@RestControllerAdvice`는 **모든 컨트롤러에서 발생한 예외를 한곳에서 받아 처리하는 중앙 집중식 예외 처리기**다.

```
@RestControllerAdvice = @ControllerAdvice + @ResponseBody
```

`@ResponseBody`가 합쳐져 있기 때문에, 예외가 발생하면 HTML 페이지가 아니라 **일관된 JSON 형태의 API 응답**을 클라이언트(프론트엔드, 모바일 앱)에 돌려준다. `@RestController = @Controller + @ResponseBody`와 같은 구조다.

**코드로 보기 — 전형적인 전역 예외 처리 구조**

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(CustomException.class)
    public ResponseEntity<ErrorResponse> handleCustomException(CustomException e) {
        ErrorResponse response = new ErrorResponse(e.getErrorCode(), e.getMessage());
        return new ResponseEntity<>(response, HttpStatus.BAD_REQUEST);
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleGeneralException(Exception e) {
        ErrorResponse response = new ErrorResponse("INTERNAL_SERVER_ERROR", "서버 내부 오류가 발생했습니다.");
        return new ResponseEntity<>(response, HttpStatus.INTERNAL_SERVER_ERROR);
    }
}
```

- 클래스에 붙은 `@RestControllerAdvice`: 애플리케이션 전체 컨트롤러의 예외를 감지한다.
- 메서드에 붙은 `@ExceptionHandler(예외타입.class)`: "이 메서드는 이 예외를 처리한다"고 지정한다.
- 처음에는 `Exception.class` 하나만 처리하는 핸들러로 시작하고, 따로 다뤄야 하는 예외가 생기면 그 예외 타입용 메서드를 추가해 특화시킨다. 더 구체적인 예외 타입의 핸들러가 우선 적용된다.

| 구분 | @ControllerAdvice | @RestControllerAdvice |
|---|---|---|
| 주요 목적 | 예외 발생 시 뷰(HTML) 화면 반환 (MVC) | 예외 발생 시 JSON/XML 데이터 반환 (REST API) |
| 구성 | `@ControllerAdvice` | `@ControllerAdvice` + `@ResponseBody` |
| 반환값 | 뷰 이름(String) 또는 `ModelAndView` | 데이터 객체(자동으로 JSON 변환) |

**1번이 오답인 이유**: `@ControllerAdvice`는 단일 컨트롤러가 아니라 **애플리케이션 전역의 컨트롤러**에 적용된다. 특정 컨트롤러 하나 안에서만 예외를 처리하고 싶다면, 그 컨트롤러 클래스 안에 `@ExceptionHandler` 메서드를 직접 두면 된다.

**2번이 오답인 이유**: 400(입력값 검증 실패), 404(존재하지 않는 리소스), 500(서버 내부 오류)처럼 예외 타입별로 적절한 HTTP 상태 코드와 메시지를 나눠서 응답해야 클라이언트가 어떤 에러가 왜 발생했는지 알 수 있다. 응답 **형식**은 통일하되, **내용(상태 코드·메시지)**은 예외별로 구분하는 것이 전역 예외 처리의 목적이다.

**4번이 오답인 이유**: `@ExceptionHandler`는 오히려 전역 예외 처리 클래스 안의 메서드에 붙여서 쓰는 것이 기본 사용법이다. 전역 클래스(`@RestControllerAdvice`) 안에 쓰면 전체 컨트롤러에 적용되고, 개별 컨트롤러 안에 쓰면 그 컨트롤러에만 적용된다.

**한 줄 요약**: `@RestControllerAdvice`(= `@ControllerAdvice` + `@ResponseBody`)로 전역 예외를 한곳에 모아 일관된 JSON 응답으로 바꾸고, 그 안에서 `@ExceptionHandler`로 예외 타입별 처리 메서드를 나눈다.
