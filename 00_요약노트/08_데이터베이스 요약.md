# 데이터베이스 요약

데이터를 **무엇으로, 어떻게 저장할지 설계**(모델링)하고, 그 데이터를 **SQL로 꺼내 쓰는** 방법을 다룬다. 설계가 먼저고, SQL과 JDBC가 그 위에 올라간다.

## 1. 한눈에 보기

| 주제 | 핵심 |
|---|---|
| 데이터베이스 | 데이터를 무결하게 저장·공유하기 위한 저장소. 무결성, 트랜잭션, 동시성 제어를 제공한다 |
| 모델링 | 행위와 정보를 데이터 구조로 옮기는 설계. 개념적 → 논리적 → 물리적 순서 |
| 엔티티 | 저장할 데이터의 단위. 무엇을 저장할지는 업무(도메인 지식)가 결정한다 |
| ERD | 엔티티, 속성, 관계의 세 요소. 관계 차수는 1:1, 1:N, M:N |
| M:N 관계 | 조인 테이블(엔티티)로 풀어서 1:N 두 개로 만든다 |
| 정규화 | 중복을 제거해 표준화한다. 1차 → 4차까지 단계별로 진행한다 |
| 제약 조건 | NOT NULL, DEFAULT, CHECK, PRIMARY KEY, UNIQUE, FOREIGN KEY. 설계의 마감 처리 |
| SQL | DDL / DML / DCL로 분류. DML은 CRUD 네 가지 |
| 쿼리 처리 순서 | 필터링(WHERE) → 집계(GROUP BY, HAVING) → 정렬(ORDER BY) → 매핑(SELECT) |
| JOIN | INNER, OUTER(LEFT / RIGHT / FULL), SELF, CROSS |
| JDBC | DBMS가 달라도 코드가 호환되게 하는 표준 API. 리포지토리로 역할을 분리한다 |

## 2. 개념 정리

### 2-1. 모델링의 흐름

```
업무 분석 → 개념적 모델(ERD) → 논리적 모델(테이블, 키) → 물리적 모델(타입, 인덱스, 성능)
```

- **식별관계 vs 비식별관계:** 부모의 키가 자식의 기본키에 포함되는지 여부.
- 정규화는 중복을 줄이지만 JOIN이 늘어난다. 성능을 위해 물리 설계에서 일부러 중복을 허용하기도 한다.

### 2-2. 정규화

| 단계 | 제거하는 것 |
|---|---|
| 1차 | 원자 값이 아닌 도메인(한 칸에 여러 값) |
| 2차 | 부분적 함수 종속 |
| 3차 | 이행적 함수 종속 |
| 4차 | 다치 종속 |

### 2-3. 제약 조건 — 세 단계의 방어선

| 단계 | 역할 |
|---|---|
| 프론트 | 빠른 피드백(사용자 편의) |
| 백엔드 | 업무 규칙 검증 |
| DB | 마지막 방어선. 어떤 경로로 들어와도 무결성을 지킨다 |

- **도메인 제약:** NOT NULL, DEFAULT, CHECK(정규식 포함).
- **엔티티 제약:** PRIMARY KEY, UNIQUE.
- **릴레이션 제약:** FOREIGN KEY.

### 2-4. SQL 핵심

```sql
SELECT 컬럼               -- 4. 매핑
FROM 테이블
WHERE 조건                -- 1. 필터링
GROUP BY 컬럼             -- 2. 집계
HAVING 집계조건           -- 집계 결과 다시 필터링
ORDER BY 컬럼;            -- 3. 정렬
```

- 필터링은 자바가 아니라 **SQL이 해야** 한다. 인덱스를 타는 쿼리(SARGable)를 쓴다.
- `LIKE`로 패턴 검색, `COUNT` / `AVG`로 집계한다.
- 옵션값(GET 파라미터)을 그냥 `int`로 변환하면 빈 값에서 오류가 난다.

### 2-5. JOIN

| 종류 | 결과 |
|---|---|
| INNER | 양쪽에 모두 있는 행만 |
| LEFT / RIGHT OUTER | 기준이 되는 쪽의 행은 모두 유지 |
| FULL OUTER | 양쪽 모두 유지 |
| SELF | 자기 자신을 참조하는 테이블 |
| CROSS | N × M 카티션 곱 |

- **부모와 자식:** 참조키(FK)를 가진 쪽이 자식이다.
- **주인공(anchor):** 어느 쪽을 기준으로 삼을지 정하면 OUTER JOIN의 방향이 정해진다.
- 자식을 곁다리로 붙일 때는 집계로 뭉개서 가져와야 행이 불어나지 않는다.

### 2-6. JDBC의 4단계

```
연결(Connection) → 문장 준비(PreparedStatement) → 실행 → 결과 처리(ResultSet)
```

- 입출력과 데이터 소스가 뒤섞인 통짜 코드는 **리포지토리**로 분리한다.

## 3. 자주 헷갈리는 것

- **WHERE vs HAVING:** WHERE는 집계 전 필터링, HAVING은 집계 결과 필터링.
- **식별자 선택:** 자동 증가 정수 대신 UUID를 쓰는 기준은 참고자료에 정리해 두었다.
- **CHAR vs VARCHAR:** 고정 길이와 가변 길이.
- 서브쿼리와 JOIN은 비슷해 보이지만 결과의 모양과 용도가 다르다.

## 4. 이 카테고리의 실습, 오답노트, 참고자료

- 실습: SQL SELECT 구절 연습, PostgreSQL 제약조건 실습
- 오답노트: 클래스패스와 리소스, SQL 집계와 그룹화, SQL JOIN, 트랜잭션 ACID
- 참고자료: 식별자로 UUID를 선택하는 기준, JDBC API 메서드 체이닝, SQL SELECT 실습 쿼리 모음, 제약조건
