# 제어문과 디버깅 요약

프로그램의 흐름을 바꾸는 **조건문과 반복문**, 그리고 흐름을 눈으로 확인하는 **디버깅**을 다룬다.

## 1. 한눈에 보기

| 주제 | 핵심 |
|---|---|
| 제어구조 | 순차, 분기(if, switch), 반복(while, for, do-while) |
| while | 반복되려면 초기값, 조건, 증감 세 가지 요소가 필요하다 |
| for | 반복 횟수를 알 때 편하다. 무한 루프 + 인덱스 패턴도 쓴다 |
| 조건문 | `if / else if / else`는 위에서부터 판단해 범위가 자동으로 나뉜다 |
| switch | 값에 따라 분기한다. `break`가 없으면 아래 case로 이어진다(fallthrough) |
| break / continue | `break`는 반복을 빠져나가고, `continue`는 이번 회차만 건너뛴다 |
| 디버깅 | 로깅으로 흐름 확인, 브레이크포인트, 스텝 오버 |

## 2. 개념 정리

### 2-1. 반복문의 세 가지 요소

```java
int i = 0;            // 1. 초기값
while (i < 5) {       // 2. 조건
    System.out.println(i);
    i++;              // 3. 증감
}
```

세 가지 중 하나라도 빠지면 한 번도 안 돌거나 무한 루프가 된다.

### 2-2. 디버깅의 기본 흐름

1. 의심되는 줄에 **브레이크포인트**를 건다.
2. 실행하면 그 줄에서 멈춘다.
3. **스텝 오버**로 한 줄씩 실행하며 변수 값을 확인한다.

`System.out.println` 로깅은 간단하지만, 변수를 중간에 직접 보려면 디버거가 훨씬 편하다.

## 3. 자주 헷갈리는 것

- **`if (조건);`** 처럼 조건 뒤에 세미콜론을 붙이면 빈 문장이 되어 바로 아래 블록이 항상 실행된다.
- **switch 안의 break**는 switch만 빠져나가고, 바깥 반복문은 못 빠져나간다.
- 입력을 받을 때는 **입력 버퍼**에 남은 줄바꿈 문자 때문에 다음 입력이 건너뛰어질 수 있다.
