# 트랜잭션과 AOP 요약

여러 작업을 **한 번에 성공하거나 한 번에 실패**하게 묶는 것이 트랜잭션이다. 스프링은 `@Transactional` 한 줄로 이것을 해 주고, 그 원리가 **AOP와 프록시**다.

## 1. 한눈에 보기

| 주제 | 핵심 |
|---|---|
| 트랜잭션 | 한 번에 이루어져야 할 논리적 작업 단위 |
| ACID | 원자성, 일관성, 고립성, 지속성 |
| DBMS의 지원 | `COMMIT`과 `ROLLBACK`. JDBC에서는 자동 커밋을 끈다 |
| 계층을 나누면 | 리포지토리마다 커넥션이 흩어져 하나의 트랜잭션으로 묶기 어렵다 |
| EJB의 해법 | 서버가 해 주지만 무겁고 불편했다 |
| `@Transactional` | 같은 커넥션을 공유시켜 전부 커밋하거나 전부 롤백한다 |
| `ddl-auto` | 엔티티로 테이블 생명주기를 관리한다 (개발용) |
| OOP와 AOP | OOP는 주 업무 기준, AOP는 그 위에서 곁다리 업무를 따로 다룬다 |
| 프록시 | 곁다리 코드를 메서드 밖 한 곳으로 빼고, 호출 흐름만 거치게 한다 |
| 전파 옵션 | 서비스가 서비스를 호출할 때 트랜잭션을 어떻게 이어받을지 |
| 격리 수준 | 읽는 동안 남이 건드리지 못하게 하는 정도 |

## 2. 개념 정리

### 2-1. `@Transactional`이 하는 일

```java
@Transactional
public void register(...) {
    menuRepository.save(menu);          // 같은 커넥션
    categoryRepository.save(category);  // 같은 커넥션 → 둘 중 하나가 실패하면 전부 롤백
}
```

- 트랜잭션은 **DBMS가 하고**, 스프링은 같은 커넥션을 공유하게 만든다.
- 커넥션은 매개변수로 넘기지 않고 **스레드(ThreadLocal)** 에 걸어 둔다. 리포지토리는 공유 커넥션이 있으면 그것을 쓴다.
- 기본 롤백 대상은 **런타임 예외**다. 제약조건 위반은 롤백된다.
- 트랜잭션은 **DB 작업만** 되돌린다. 파일이나 외부 API 호출은 되돌리지 못한다.
- `@Transactional`은 **서비스에만** 붙인다.

### 2-2. AOP

```
호출하는 쪽 → [프록시: 곁다리 코드] → 원본 객체
```

| 용어 | 뜻 |
|---|---|
| Core Concern | 사용자가 요구한 주 업무 |
| Cross-cutting Concern | 흐름을 가로질러 잘라낸 곁다리(로그, 보안, 트랜잭션) |
| Aspect | 사용자가 아닌 개발자·운영자 같은 역할자의 관점 코드 |

- 곁다리 코드를 **한 번만 만들고 붙였다 뗄 수 있게** 한다. 소스 코드가 없어도 가능하다.
- 사용하는 쪽이 **인터페이스**로 참조하고 **DI**로 객체를 받으면 프록시를 넣어도 아무것도 고칠 필요가 없다.
- 자바 동적 프록시는 인터페이스가 필요하다.
- AOP는 주로 **도구를 만드는 사람**이 쓰는 방법론이다. 지금은 개념과 `@Transactional`의 원리까지 이해한다.

### 2-3. 전파 옵션

| 옵션 | 동작 |
|---|---|
| `REQUIRED`(기본) | 있으면 참여, 없으면 생성. 안쪽 오류에 전체 롤백 |
| `REQUIRES_NEW` | 항상 새로 만들고 먼저 커밋. 안쪽 예외를 바깥에서 잡으면 안쪽만 롤백 |
| `SUPPORTS` | 있으면 참여, 없으면 트랜잭션 없이 |
| `MANDATORY` | 없으면 예외 |

- 전파 옵션은 **호출당하는 쪽**(트랜잭션 자식)에 정한다. 말할 때는 어느 "부모"인지 밝힌다.
- 서비스 간 호출은 **자식 → 부모(위) 방향, 단방향**으로만 쓴다.
- 전파 옵션은 **업무 규칙**으로 정한다. AI에게 맡기려면 규칙을 먼저 알려 줘야 한다.

### 2-4. 격리 수준

| 읽기 이상 | 뜻 |
|---|---|
| Dirty Read | 커밋 전의 값을 읽는다 |
| Non-repeatable Read | 같은 행의 값이 바뀐다 |
| Phantom Read | 행의 건수가 바뀐다 |

- 격리 수준이 높을수록 안전하지만 느리다(잠금 범위가 넓어진다).
- DBMS는 잠그지 않고 **스냅샷(MVCC)** 으로 읽는다.
- 기본값: PostgreSQL·Oracle은 `READ COMMITTED`, MySQL은 `REPEATABLE READ`. 보통은 `DEFAULT`로 충분하다.
- 조회만 하는 서비스도 곁다리를 조립하는 동안 값이 바뀌면 안 되면 격리가 필요하다.

## 3. 자주 헷갈리는 것

- **개념과 구현체:** IoC → DI, AOP → 트랜잭션, 필터 → 시큐리티.
- **트랜잭션 필요 여부:** SQL 하나로 끝나는 단순 작업은 생략할 수 있고, 여러 명령으로 된 서비스 메서드는 묶는다.
- **도메인 부모 = 트랜잭션 자식 = 호출당하는 쪽.**
- 운영 환경의 `ddl-auto`는 `validate` 또는 `none`이고, 마이그레이션 도구를 쓴다.
