# 네트워크 요약

웹 개발에서 만나는 네트워크 개념 두 가지, **도메인(DNS)** 과 **동일 출처 정책(CORS)** 을 다룬다.

## 1. 한눈에 보기

| 주제 | 핵심 |
|---|---|
| 도메인 | 사람이 읽을 수 있는 네트워크 주소 이름. TLD → 2단계 도메인 → 하위 도메인의 계층 구조 |
| DNS | 도메인을 IP 주소로 바꿔 주는 시스템 |
| A 레코드 / CNAME | 도메인을 IP에 직접 연결 / 도메인을 다른 도메인의 별칭으로 연결 |
| 동일 출처 정책(SOP) | 브라우저가 다른 출처의 응답을 스크립트가 읽지 못하게 막는 보안 정책 |
| CORS | 서버가 `Access-Control-Allow-Origin` 헤더로 다른 출처의 접근을 허용하는 규칙 |

## 2. 개념 정리

### 2-1. 도메인과 DNS

```
브라우저에 도메인 입력 → DNS 조회 → IP 주소 획득 → 서버 연결
```

```
example.com       → A 레코드     → 203.0.113.10
www.example.com   → CNAME 레코드 → example.com
```

- 도메인은 전 세계에서 유일해야 하고, 등록기관이 중복을 관리한다.
- 서비스를 설계할 때는 오타 접속, 유사 도메인 피싱에 대비해 리디렉션, HSTS, 인증서 설정을 함께 준비한다.

### 2-2. 동일 출처 정책과 CORS

- 출처는 **프로토콜 + 호스트 + 포트**의 조합이다. 하나라도 다르면 다른 출처다.
- 이 정책을 강제하는 것은 **서버가 아니라 브라우저**다.

| 상황 | 주체 | 동작 |
|---|---|---|
| 브라우저 → 다른 출처 서버 | 브라우저 | 서버가 허용 헤더를 주지 않으면 응답을 막는다 |
| 서버 → 다른 출처 서버 | 없음 | 검사할 브라우저가 없으므로 CORS와 무관하다 |

- 요청 자체가 막히는 것이 아니라, **브라우저가 응답을 스크립트에 넘겨주지 않는 것**이다.
- 백엔드의 CORS 설정을 바꾸기 어렵다면, 브라우저는 같은 출처의 프론트엔드 서버에만 요청하고 그 서버가 백엔드를 대신 호출하게 하는 프록시 방식으로 우회할 수 있다.

## 3. 자주 헷갈리는 것

- CORS 오류는 "서버가 요청을 거부했다"가 아니라 "브라우저가 응답을 막았다"는 뜻이다.
- 서버 대 서버 통신(Node.js, Spring, curl 등)에는 CORS가 적용되지 않는다.
