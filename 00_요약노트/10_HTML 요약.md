# HTML 요약

HTML은 **컨텐츠에 의미를 붙이는 마크업 언어**다. 모양을 꾸미는 것이 아니라 "이게 제목인지, 본문인지, 탐색 영역인지"를 구분하는 일이다.

## 1. 한눈에 보기

| 주제 | 핵심 |
|---|---|
| 마크업과 태그 | 컨텐츠를 구분하는 방법. 태그는 편집 명령어가 아니라 의미 표시다 |
| DOCTYPE | 브라우저가 표준 모드로 해석하게 한다. W3C 표준화의 산물 |
| 컨텐츠 블록 | 제목 + 문단, 목록, 표, 인용, 코드 등 4가지 블록 |
| 아웃라인 | 제목(h1~h6)으로 문서 구조를 만든다. 검색엔진과 보조 기기가 이 구조를 읽는다 |
| `div`의 한계 | 의미가 없는 범용 구분 태그라서 구조를 전달하지 못한다 |
| 시맨틱 태그 | `header`, `main`, `footer`, `aside`, `nav`, `section`, `article`. SEO와 접근성에 유리하다 |
| 블록 / 인라인 / 인라인 블록 | 줄을 바꾸며 쌓이는 태그 / 글줄 안에 흐르는 태그 / 둘의 성질을 합친 범주 |
| 폼 요소 | `placeholder`, `required`, `autocomplete`, `datalist`, `select`, `button` 등 |
| GET / POST | 조회는 GET, "등록해줘" 같은 요청은 POST |

## 2. 개념 정리

### 2-1. 컨텐츠와 데코레이션

- **컨텐츠:** 의미가 있는 내용. 태그로 구분한다.
- **데코레이션:** 꾸밈. CSS로 처리한다.
- 판단이 어려울 때는 "스타일을 모두 지워도 이 내용이 남아야 하는가"를 본다.

### 2-2. 시맨틱 구조 예시

```html
<header>…로고, 탐색…</header>
<main>
  <h1>페이지 제목</h1>
  <section>…</section>
</main>
<aside>…보조 정보…</aside>
<footer>…</footer>
```

### 2-3. 폼의 핵심 속성

| 속성 | 역할 |
|---|---|
| `name` | 서버와 클라이언트가 공유하는 키. 서버는 `name`으로 값을 받는다 |
| `required` | 빈 값 전송을 브라우저 단에서 막는다 |
| `placeholder` | 입력 전에만 보이는 안내 문구(라벨을 대신하지 못한다) |
| `autofocus` | 페이지가 열리자마자 포커스를 준다 |
| `option`의 `value` | `select`는 화면 텍스트가 아니라 `value`가 전송된다 |

### 2-4. 인라인 태그

강조(`strong`, `em`), 편집 표시(`ins`, `del`), 첨자(`sub`, `sup`), 인용(`q`, `cite`), 데이터·시간(`time`, `data`), 코드(`code`, `kbd`), 줄바꿈(`br`, `wbr`) 등 27종이 있다. 실무에서는 `span`으로 뭉뚱그려 쓰는 경우가 많다.

## 3. 자주 헷갈리는 것

- **HTML5 아웃라인 알고리즘은 폐기**됐다. 제목 단계를 직접 지키는 것이 기준이다.
- 인라인 태그는 줄이 바뀌지 않지만, 컨텐츠가 나뉘면 줄이 바뀐다.
- **라벨링**은 접근성의 핵심이다. 입력 요소에는 라벨을 연결한다.
- 불린 속성 표기(`required`와 `required="required"`)가 두 가지인 것은 SGML과 XML 문법의 차이에서 온 역사다.
