# 타입스크립트 요약

타입스크립트는 **자바스크립트의 상위집합**이다. 코드를 실행하기 전에 타입을 검사해 오류를 미리 잡는다.

## 1. 한눈에 보기

| 주제 | 핵심 |
|---|---|
| 왜 쓰는가 | 자바스크립트는 타입이 없어서 실수가 실행 중에야 드러난다 |
| 설치와 컴파일 | `tsc`로 `.ts`를 `.js`로 변환한다 |
| 원시 타입 | `string`, `number`, `boolean` 등 |
| 객체 타입 | 익명 객체 타입 또는 타입 별칭(`type`)으로 정의한다 |
| `any` / `unknown` | `any`는 검사를 끈다. `unknown`은 쓰기 전에 타입을 확인해야 한다 |
| Union | 둘 이상의 타입을 허용한다 (`string | number`) |
| Literal | 값 자체를 타입으로 쓴다 (`"left" | "right"`) |
| Enum | 이름 붙은 상수의 집합 |
| 함수 타입 | 매개변수와 반환 타입을 명시한다 |
| Interface vs Type | 실무에서는 `interface`를 더 많이 쓴다 |
| 클래스 | 자바스크립트의 생성자 함수와 `this` |

## 2. 개념 정리

### 2-1. 기본 문법

```ts
type Menu = { id: number; name: string; price?: number };   // 타입 별칭, 선택 속성

interface Category {
  id: number;
  name: string;
}

function total(a: number, b: number): number {
  return a + b;
}

let align: "left" | "right" = "left";   // 리터럴 유니온
```

### 2-2. Interface와 Type Alias

| | interface | type |
|---|---|---|
| 확장 | 선언 병합, `extends` | 교차 타입(`&`) |
| 용도 | 객체의 모양을 정의 | 유니온, 리터럴 등 다양한 타입에 별칭 |

## 3. 자주 헷갈리는 것

- 타입스크립트의 타입은 **컴파일 시점에만** 존재한다. 실행되는 자바스크립트에는 남지 않는다.
- 생성자 함수는 `new`로 호출해야 하고, 그렇지 않으면 `this`가 의도와 다르게 잡힌다.

## 4. 이 카테고리의 오답노트

- 인터페이스와 타입 별칭
- 생성자 함수와 new 연산자
