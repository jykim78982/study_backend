# 함수와 구조화 요약

코드가 길어지면 읽기 어렵다. **비슷한 일을 하는 코드를 묶고(그루핑), 떼어내서 이름을 붙인 것**이 함수이고, 이것이 구조화의 시작이다.

## 1. 한눈에 보기

| 주제 | 핵심 |
|---|---|
| 구조화 | 코드를 그루핑해서 읽기 쉽게 만드는 것. 함수가 대표적인 수단이다 |
| Top-down / Bottom-up | 큰 흐름을 먼저 나누고 채우는 방식 / 작은 부품을 먼저 만들고 조립하는 방식 |
| 함수 정의 | 반환형식, 이름, 매개변수, 본문. `return` 타입은 반환형식과 맞아야 한다 |
| 함수 이름 | 동사로 시작하는 카멜케이스. 접두어(`get`, `set`, `is`, `calc` 등)를 일관되게 쓴다 |
| 여러 값 반환 | `return a, b`는 불가능하다. 타입이 같으면 배열로, 다르면 클래스로 묶는다 |
| 매개변수 전달 | 값 변수는 값이 복사되고, 배열·객체는 주소가 복사된다 |
| 재사용과 배포 | `main`이 있는 파일은 재사용할 수 없다. 재사용할 코드는 따로 jar로 묶는다 |

## 2. 개념 정리

### 2-1. 값 전달 vs 참조 전달

| | 넘기는 것 | 함수 안에서 바꾸면 |
|---|---|---|
| 값 변수(`int`) | 값의 복사본 | 원본은 그대로 |
| 배열·객체 | 참조(주소)의 복사본 | 같은 배열·객체를 가리키므로 원본이 바뀐다 |

### 2-2. 함수로 나눌 때 자주 하는 실수

- 반환형식과 `return` 값의 타입이 맞지 않는다.
- 매개변수 타입이 실제로 넘기는 값과 맞지 않는다.
- 시그니처를 바꾸고 호출부를 안 고쳤다.
- 함수 안에서 `Scanner`를 또 만든다.
- 지역변수를 초기화하지 않고 쓴다.
- 함수가 돌려준 값을 받지 않고 버린다.

### 2-3. switch-case와 함수 분리

`switch`의 case는 `break`가 없으면 다음 case로 흘러내린다. 메뉴 분기를 함수로 빼면 `main`이 짧아지고 읽기 쉬워진다.

## 3. 자주 헷갈리는 것

- 함수 선언 줄 끝에 **세미콜론**을 붙이면 안 된다.
- 함수를 호출할 때 값 변수와 배열은 **전달 방식이 다르다**는 점이 핵심이다.
- 구조화만으로는 함수가 폭증한다. 그 한계를 객체지향이 이어받는다.
