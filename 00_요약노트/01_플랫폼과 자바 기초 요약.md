# 플랫폼과 자바 기초 요약

프로그램은 **언어 + 플랫폼**이다. 이 카테고리는 플랫폼(OS, 컴퓨터)이 무엇이고, 자바가 그 위에서 어떻게 동작하는지, 데이터가 어떻게 저장되고 전달되는지를 다룬다.

## 1. 한눈에 보기

| 주제 | 핵심 |
|---|---|
| 컴퓨터와 리눅스의 역사 | 계산기 → 범용 컴퓨터 → 유닉스와 C → 리눅스. 서버와 개발 도구가 대부분 리눅스 계열이라 리눅스를 배운다 |
| 플랫폼 | 프로그램이 "함께 쓰는 공간"(OS, 브라우저, 서버). 언어는 플랫폼의 기능을 이용하기 위한 도구다 |
| 자바와 WORA | 소스를 바이트코드로 컴파일하고 JVM이 OS별로 실행한다. 한 번 작성해 어디서나 실행한다 |
| JDK와 JRE | JDK는 개발 도구(컴파일러 포함), JRE는 실행 환경. 컴파일과 실행, 두 번 번역한다 |
| 데이터 타입과 진법 | 타입마다 크기가 정해져 있고, 값은 2진수로 저장된다 |
| 문자 코드와 인코딩 | ASCII → 확장 코드 → 유니코드. UTF-8, UTF-16 같은 인코딩이 바이트 표현을 정한다 |
| 엔디안 | 여러 바이트를 담는 순서(빅 엔디안, 리틀 엔디안) |
| 파일 API | 바이트 스트림과 문자 스트림. 경로는 절대 경로와 상대 경로가 있다 |
| 패키지 | 클래스 이름을 유일하게 만드는 식별자. 도메인을 거꾸로 쓰고, 실제 폴더 구조와 같다 |
| 예외 처리 | 오류를 숫자 코드가 아니라 객체로 던진다. try-with-resources로 자원을 자동 반납한다 |

## 2. 개념 정리

### 2-1. 자바 프로그램의 실행 과정

```
Hello.java  →(javac 컴파일)→  Hello.class(바이트코드)  →(JVM 실행)→  OS에서 동작
```

- 컴파일러와 인터프리터(JVM)가 역할을 나눠서 **OS에 독립적**인 실행이 가능해진다.
- 콘솔 출력 같은 API는 플랫폼의 기능에 접근하는 **간접 도구**다.

### 2-2. 값과 형식

- 같은 값도 **형식**(정수, 실수, 문자)에 따라 저장 방식이 다르다.
- 텍스트 저장과 바이너리 저장은 다르다. 텍스트는 어떤 인코딩으로 저장했는지가 중요하다.
- 한글이 깨지는 문제는 대부분 **저장할 때와 읽을 때의 인코딩이 다르기 때문**이다.

### 2-3. 예외 처리

| 오류 종류 | 설명 |
|---|---|
| 구문오류 | 문법이 틀려서 컴파일이 안 된다 |
| 논리오류 | 실행은 되지만 결과가 틀리다 |
| 예외 | 실행 중에 발생하는 문제. 처리할 수 있다 |

- 예외는 API가 검사해서 **객체로 던지고**, 받는 쪽이 다시 던지거나 처리한다.
- `Exception`(검사 예외)과 `RuntimeException`(비검사 예외)을 구분한다.
- 계층 사이에서는 예외를 다른 타입으로 바꿔서 던지기도 한다.

## 3. 자주 헷갈리는 것

- **JDK vs JRE:** 개발에는 JDK, 실행만 하려면 JRE.
- **패키지 이름의 점(.):** 폴더 경로에 그대로 대응된다. 이름과 폴더가 다르면 클래스를 못 찾는다.
- **바이트 스트림 vs 문자 스트림:** 바이너리는 바이트 스트림, 텍스트는 문자 스트림.

## 4. 이 카테고리의 실습과 오답노트

- 실습: 리눅스 파일 시스템, 파일 API, 자바 컬렉션 프레임워크, WSL2 기반 VSCode 개발 환경 구축
- 오답노트: 예외 처리
