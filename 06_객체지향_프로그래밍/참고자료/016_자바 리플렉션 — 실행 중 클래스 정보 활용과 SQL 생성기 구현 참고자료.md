# 자바 리플렉션 — 실행 중 클래스 정보 활용과 SQL 생성기 구현

Spring이나 Hibernate 같은 프레임워크가 어떻게 "우리가 만든 클래스를 미리 알지도 못하면서" DI를 해주고 SQL을 대신 만들어줄 수 있는지, 그 밑바탕에 있는 리플렉션(Reflection) API를 정리한다.

## 1. 리플렉션이란 — 컴파일 타임이 아니라 런타임에 클래스를 들여다본다

평소 우리는 클래스의 구조(필드가 몇 개인지, 어떤 타입인지, 메서드는 무엇이 있는지)를 **컴파일 시점**에 이미 알고 코드를 작성한다. 예를 들어 `user.getName()`을 호출할 수 있는 것은, 컴파일러가 `User` 클래스에 `getName()`이 있다는 것을 소스 코드로 이미 확인했기 때문이다.

**리플렉션**은 이 확인 과정을 소스 코드 작성 시점이 아니라 **실행 중(런타임)**에 할 수 있게 해주는 기능이다. 즉 "이 객체가 어떤 클래스인지, 그 클래스가 어떤 필드와 메서드를 가지고 있는지"를 프로그램이 스스로 조사하고, 심지어 조작까지 할 수 있게 해준다.

## 2. 리플렉션 API의 핵심 도구

리플렉션은 `java.lang` 패키지를 중심으로 제공된다.

- **`Class` 객체**: 자바의 모든 클래스와 인터페이스는 실행 시점에 `Class` 타입의 객체 하나로 표현된다. 이 객체가 해당 클래스의 이름, 필드 목록, 메서드 목록 같은 메타데이터를 담고 있는 진입점이다.
- **`getDeclaredFields()`**: 그 클래스에 선언된 모든 필드를 `Field` 객체 배열로 반환한다. `private`으로 선언된 필드도 포함된다.
- **`getMethod()` / `getDeclaredMethods()`**: 클래스의 메서드 정보를 `Method` 객체로 반환한다.

비유하면, 이 API들은 클래스라는 "블랙박스"를 열어서 그 안에 무엇이 들어있는지 확인하는 렌즈에 해당한다.

## 3. 왜 컴파일 시점에 다 아는데 실행 중에 또 확인하는가

의문이 생길 수 있다 — "클래스를 만들 때 이미 필드와 메서드를 다 아는데, 왜 실행 중에 다시 조사해야 하는가?" 답은 **프레임워크를 만드는 입장**에서 나온다.

- **프레임워크 개발**: Spring이나 Hibernate는 사용자가 나중에 어떤 이름의 클래스를, 어떤 필드로 만들지 미리 알 수 없다. 프레임워크 코드는 사용자의 프로젝트보다 먼저 작성되어 배포되기 때문이다. 그래서 프레임워크는 사용자가 만든 클래스를 **실행 중에** 리플렉션으로 분석해서, SQL 문을 생성하거나 DI로 주입할 대상을 찾거나 데이터를 매핑한다.
- **동적 처리**: 입력값을 어떤 클래스의 어떤 속성에 대입해야 하는지 실행 중에 판단해서 대입할 수 있다.
- **범용 도구 제작**: 직렬화(Serialization), JSON 변환기처럼 "어떤 클래스가 오더라도" 그 구조를 자동으로 분석해야 하는 도구를 만들 때 필수적이다.

즉 리플렉션은 "클래스의 형태를 코드에 미리 못 박아두지 않고, 실행 중에 알아내서 자동화하고 싶을 때" 쓰는 도구다.

## 4. 리플렉션으로 할 수 있는 것들

- **클래스 정보 조회**: 클래스 이름, 패키지, 상속 관계, 구현한 인터페이스 확인
- **필드(Field) 조회**: 필드의 이름, 타입, 접근 제어자(`private`/`public` 등) 확인
- **메서드(Method) 조회**: 메서드 이름, 파라미터 타입, 반환 타입 확인
- **객체 생성**: 리플렉션으로 얻은 생성자(`Constructor`)를 통해 클래스의 인스턴스를 동적으로 생성
- **필드 값 읽기/쓰기**: `Field` 객체의 `get()`/`set()`으로 객체의 필드 값을 직접 읽거나 바꿈
- **메서드 호출**: `Method` 객체의 `invoke()`로 특정 메서드를 동적으로 실행

## 5. 예제로 보는 실용성 — SQL 생성기

`User` 클래스가 있다고 하자.

```java
public class User {
    private int id;
    private String username;
    private String email;

    // Getter, Setter, Constructor 생략
}
```

이 클래스의 필드 목록을 리플렉션으로 읽어올 수 있다면, `SELECT`문과 `INSERT`문을 자동으로 조합하는 프로그램을 만들 수 있다.

**동작 원리**

1. `User` 클래스의 메타데이터를 담은 `Class` 객체를 얻는다.
2. `getDeclaredFields()`로 `id`, `username`, `email` 필드를 가져온다.
3. 각 필드 이름을 순회하며 SQL 문자열을 조합한다.
   - `SELECT` 문: `SELECT id, username, email FROM user`
   - `INSERT` 문: `INSERT INTO user (id, username, email) VALUES (?, ?, ?)`

이렇게 만들면, 나중에 `User`에 `phone` 필드가 추가되어도 **SQL 생성기 코드를 한 줄도 고치지 않고** 자동으로 `phone` 컬럼이 포함된 SQL이 생성된다. 클래스 구조가 SQL 로직에 하드코딩되어 있지 않기 때문이다.

## 6. 구현 코드 (Java 21)

```java
import java.lang.reflect.Field;
import java.util.Arrays;
import java.util.stream.Collectors;

public class ReflectionSqlGenerator {

    public static void main(String[] args) {
        // 1. 대상 클래스의 Class 객체를 얻는다.
        Class<?> clazz = User.class;

        System.out.println("=== 클래스 이름: " + clazz.getName() + " ===");

        // 2. 클래스에 선언된 모든 필드를 가져온다. private 필드도 포함된다.
        Field[] fields = clazz.getDeclaredFields();

        // 3. 필드 이름만 추출한다.
        String[] columnNames = Arrays.stream(fields)
                .map(Field::getName)
                .toArray(String[]::new);

        // 4. SELECT 문 생성
        String selectSql = generateSelectSql(columnNames, "user");
        System.out.println("SELECT: " + selectSql);

        // 5. INSERT 문 생성
        String insertSql = generateInsertSql(columnNames, "user");
        System.out.println("INSERT: " + insertSql);
    }

    // 컬럼 이름 배열을 받아 SELECT 문장을 생성한다.
    private static String generateSelectSql(String[] columns, String tableName) {
        String columnList = String.join(", ", columns); // 예: "id, username, email"
        return "SELECT " + columnList + " FROM " + tableName;
    }

    // 컬럼 이름 배열을 받아 INSERT 문장을 생성한다.
    private static String generateInsertSql(String[] columns, String tableName) {
        String columnList = String.join(", ", columns);

        // 컬럼 개수만큼 "?"를 쉼표로 연결한다. 예: "?, ?, ?"
        String placeholders = Arrays.stream(columns)
                .map(c -> "?")
                .collect(Collectors.joining(", "));

        return "INSERT INTO " + tableName + " (" + columnList + ") VALUES (" + placeholders + ")";
    }
}
```

**실행 결과**

```
=== 클래스 이름: User ===
SELECT: SELECT id, username, email FROM user
INSERT: INSERT INTO user (id, username, email) VALUES (?, ?, ?)
```

**코드 해설**

- `Class<?> clazz = User.class;` — `User.class`는 컴파일 시점에 `User` 클래스에 대응하는 `Class` 객체를 참조한다. 이 객체가 `User`의 모든 메타데이터를 담는 진입점이다.
- `clazz.getDeclaredFields()` — `User` 내부에 선언된 모든 필드를 `Field` 배열로 반환한다. `Field` 객체는 필드 이름(`getName()`), 타입(`getType()`), 접근 제어자(`getModifiers()`) 등을 조회하는 핸들러 역할을 한다.
- `Arrays.stream(fields).map(Field::getName)...` — `Field` 배열을 스트림으로 바꾸고, 각 `Field`에서 이름만 뽑아 문자열 배열(`"id"`, `"username"`, `"email"`)로 만든다.
- `String.join(", ", columns)` — 추출한 컬럼 이름들을 쉼표로 이어붙여 SQL 문법에 맞게 포맷팅한다.

## 7. 정리 — 리플렉션과 프레임워크의 관계

| 개념 | 핵심 |
|---|---|
| 리플렉션 | 컴파일 타임이 아니라 런타임에 클래스의 구조(필드·메서드)를 조사·조작하는 기능 |
| 핵심 도구 | `Class` 객체, `getDeclaredFields()`, `getMethod()`/`getDeclaredMethods()` |
| 필요한 이유 | 프레임워크는 사용자가 나중에 만들 클래스를 미리 알 수 없으므로, 실행 중에 분석해서 자동화해야 한다 |
| 대표 활용 | DI 대상 탐색, ORM(Hibernate)의 SQL 자동 생성, JSON 직렬화/역직렬화 도구 |
| 이점 | 클래스 구조를 코드에 하드코딩하지 않아도 되므로, 필드가 추가·변경돼도 관련 코드를 고칠 필요가 없다 |

Spring이 `@Component`가 붙은 클래스를 찾아 빈으로 등록하고, 생성자나 필드에 알맞은 구현체를 주입해주는 것도 결국 이 리플렉션 위에서 이루어진다 — 프레임워크가 우리 클래스의 소스 코드를 열어본 적이 없는데도 그 구조를 알아내는 것은, 실행 중에 리플렉션으로 클래스 정보를 읽어내기 때문이다.
