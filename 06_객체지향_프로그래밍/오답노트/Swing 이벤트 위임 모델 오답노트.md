# Swing 이벤트 위임 모델 오답노트

### 1. Swing에서 프레임이 마우스 클릭 시 구체적 처리 로직을 모르는 대신 수행하는 역할은 무엇인가?

**문제**: Swing에서 프레임이 마우스 클릭 시 구체적 처리 로직을 모르는 대신 수행하는 역할은 무엇인가?

1. 다이얼로그의 부모 컴포넌트를 자동으로 결정한다.
2. 이벤트 리스너의 모든 메서드를 빈 구현으로 제공한다.
3. 이벤트 발생을 감지하고 등록된 리스너의 메서드를 호출한다.
4. 모든 이벤트 처리 메서드를 직접 구현한다.

**정답: 3번**

핵심 개념은 **이벤트 위임 모델(Event Delegation Model)**이다. Java Swing은 컴포넌트(프레임, 버튼 등)와 이벤트 처리 로직 간의 결합도를 낮추기 위해 이 모델을 사용한다.

- **이벤트 소스(Event Source — 프레임, 버튼 등)**: 사용자가 마우스를 클릭하는 등의 물리적 입력을 감지한다. 하지만 "클릭했을 때 무슨 비즈니스 로직을 실행해야 하는지"는 전혀 알지 못하며, 알 필요도 없다.
- **이벤트 리스너(Event Listener — 개발자가 구현한 코드)**: 마우스가 클릭되었을 때 실제로 실행될 구체적인 처리 로직을 구현해 놓은 객체다.

프레임(Frame)은 단순히 "마우스 클릭이 발생했네? 아까 나한테 등록(`addMouseListener`)된 리스너 객체가 있으니, 그 리스너의 `mouseClicked()` 메서드를 호출해서 일 처리를 넘겨줘야겠다!"라는 역할만 수행한다.

```
[사용자 클릭] ──> [ Swing 프레임 (이벤트 감지) ]
                         │
                         ▼ (등록된 리스너의 메서드 호출)
                 [ MouseListener 구현체 (구체적 로직 실행) ]
```

**코드로 이해하기**

```java
JFrame frame = new JFrame();

// 프레임은 이 안에서 마우스가 클릭되었을 때 정확히 무슨 일이 일어날지 모릅니다.
// 그저 등록된 mouseClicked() 메서드를 호출해 줄 뿐입니다.
frame.addMouseListener(new MouseAdapter() {
    @Override
    public void mouseClicked(MouseEvent e) {
        // [구체적인 처리 로직] - 이 부분은 개발자가 작성한 리스너가 담당합니다.
        System.out.println("마우스가 클릭되었습니다! 좌표: " + e.getX() + ", " + e.getY());
    }
});
```

**1번이 오답인 이유**: 다이얼로그(`JDialog`)를 생성할 때 부모 프레임을 지정해주는 기능은 소유권(Ownership) 및 모달(Modal) 창 처리를 위한 GUI 계층 구조의 역할이지, 마우스 클릭 이벤트 처리 로직과는 아무런 관련이 없다.

**2번이 오답인 이유**: 리스너의 메서드를 빈 구현(`{}`)으로 미리 만들어 제공하는 객체는 프레임이 아니라 **어댑터 클래스**(Adapter Class, 예: `MouseAdapter`)다.

**4번이 오답인 이유**: 만약 프레임이 모든 이벤트 처리 메서드를 직접 구현해야 한다면, 프레임 하나를 쓸 때마다 클릭했을 때 DB를 조회할지, 창을 닫을지 등의 구체적 로직을 프레임 내부 코드에 일일이 고쳐 넣어야 한다. 이는 객체지향 원칙(OCP, DIP)에 심각하게 위배된다.

**연관되는 디자인 패턴: 옵저버 패턴(Observer Pattern)**

Swing의 이 방식은 SOLID 원칙 중 **DIP(의존 역전 원칙)**와 **옵저버 패턴**을 따르고 있다.

- 프레임은 구체적인 클래스에 의존하지 않고, `MouseListener`라는 인터페이스(추상화)에만 의존한다.
- 사용자가 마우스를 클릭하는 이벤트(상태 변화)가 발생하면, 프레임은 자신에게 관찰자(Observer)로 등록된 `MouseListener`들에게 알림(메서드 호출)을 보내 처리를 위임한다.

**한 줄 요약**: 프레임(이벤트 소스)은 이벤트 발생을 "감지"하고 등록된 리스너의 메서드를 "호출"만 할 뿐, 그 메서드 안에서 무엇을 할지는 전혀 알지 못한다 — 감지와 처리의 책임이 분리되어 있는 것이 이벤트 위임 모델의 핵심이다.
