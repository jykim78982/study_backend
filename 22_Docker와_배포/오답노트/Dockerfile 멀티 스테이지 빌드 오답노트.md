# Dockerfile 멀티 스테이지 빌드 오답노트

### 1. 멀티 스테이지 빌드를 쓰는 주요 목적

**문제**: Dockerfile에서 멀티 스테이지 빌드를 사용하는 주요 목적은 무엇인가?

1. 빌드 도구(JDK 등)와 캐시를 최종 이미지에 포함시키지 않고 실행 결과물만 복사해 이미지 크기와 공격 표면을 줄이기 위해
2. 여러 컨테이너를 동시에 실행하기 위해
3. 컨테이너 내부에서 개발 작업을 계속 수행하기 위해
4. 호스트의 IDE 환경 전체를 이미지에 포함시키기 위해

**정답: 1번**

**싱글 스테이지의 문제 — 빌드할 때만 필요한 것이 남는다**

스프링 부트 앱을 이미지로 만들 때 필요한 것은 단계마다 다르다.

| 단계 | 필요한 것 |
|---|---|
| 빌드(JAR 만들기) | JDK(컴파일러), Gradle, 소스 코드, 의존성 캐시 |
| 실행(서버 띄우기) | JRE와 JAR 파일 하나 |

`FROM`이 하나뿐인 Dockerfile 안에서 빌드까지 하면, 빌드에만 쓴 JDK·Gradle·소스·캐시가 **최종 이미지에 그대로 남는다.** 이미지가 무거워지고, 실행에 필요 없는 프로그램이 많을수록 공격자가 노릴 수 있는 곳(**공격 표면**, attack surface)도 넓어진다.

**멀티 스테이지 — `FROM`을 여러 번 써서 결과물만 넘긴다**

```dockerfile
# 1단계: 빌드용 — JDK로 JAR를 만든다. 최종 이미지에는 들어가지 않는다
FROM eclipse-temurin:21-jdk AS build
WORKDIR /app
COPY . .
RUN ./gradlew bootJar --no-daemon

# 2단계: 실행용 — JRE만 있는 가벼운 이미지에 JAR만 가져온다
FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=build /app/build/libs/*.jar app.jar
ENTRYPOINT ["java", "-jar", "app.jar"]
```

- `AS build`로 첫 단계에 이름을 붙이고, `COPY --from=build`로 그 단계의 **결과물만** 골라 온다.
- 최종 이미지는 **마지막 `FROM`부터** 만들어진다. 1단계의 JDK, 소스, Gradle 캐시는 빌드가 끝나면 버려진다.
- 수업 실습에서도 JDK 하나로 만든 이미지(약 833MB)보다 JRE로 실행 단계를 나눈 이미지(약 567MB)가 작았다.

| 얻는 것 | 이유 |
|---|---|
| **이미지 크기 감소** | 컴파일러·빌드 도구·캐시가 빠진다. 올리고 받는 시간도 줄어든다 |
| **공격 표면 축소** | 소스 코드와 빌드 도구가 서버에 남지 않는다 |
| **빌드 환경 통일** | 내 컴퓨터가 아니라 도커 안의 정해진 JDK로 빌드하므로, 누가 빌드해도 결과가 같다 |

**나머지 보기가 틀린 이유**

| 보기 | 실제로 맡는 것 |
|---|---|
| 2. 여러 컨테이너를 동시에 실행 | **Docker Compose**(또는 쿠버네티스). 멀티 스테이지는 이미지 **하나**를 만드는 방법이고, 결과도 컨테이너 하나다. "스테이지가 여러 개 = 컨테이너가 여러 개"가 아니다 |
| 3. 컨테이너 안에서 개발을 계속 | 컨테이너는 **실행 전용** 환경이다. 개발 중 코드 반영은 볼륨 마운트나 개발용 컨테이너 설정의 영역이다 |
| 4. IDE 환경 전체를 이미지에 포함 | 오히려 멀티 스테이지가 **빼려는** 것이다. 실행에 필요 없는 것을 넣을수록 이미지가 커지고 위험해진다 |

> **헷갈리기 쉬운 점**: 멀티 스테이지와 Compose는 둘 다 "여러 개"가 붙어서 섞이기 쉽다.
>
> | 구분 | 멀티 스테이지 빌드 | Docker Compose |
> |---|---|---|
> | 다루는 대상 | **이미지 하나**를 만드는 과정 | **컨테이너 여러 개**를 함께 실행 |
> | 적는 곳 | `Dockerfile` (`FROM`이 여러 번) | `docker-compose.yaml` (`services:` 아래 여러 개) |
> | 시점 | `docker build` | `docker compose up` |

**정리**: 멀티 스테이지 빌드는 빌드 단계(JDK)와 실행 단계(JRE)를 나눠, 최종 이미지에 **실행 결과물(JAR)만** 남기는 방법이다. 목적은 이미지 크기와 공격 표면을 줄이는 것이고, 여러 컨테이너를 함께 띄우는 것은 Compose의 일이다.
