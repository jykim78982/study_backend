# 자바 인터페이스 구현 실습 — 인터페이스를 구현하는 다양한 방법 알아보기

**대상**: 자바 기초 문법(클래스, 메소드, List)을 알고 인터페이스 개념을 막 접한 입문자

**목표**: `Comparator` 인터페이스를 구현하는 법을 익히고, 외부 클래스부터 람다까지 단계별로 줄여가며 "왜 이렇게 줄일 수 있는가"를 체득한다

**완성물**: `List<String>`을 역정렬하는 코드를 여섯 가지 방식으로 작성하고, 마지막에 내장 유틸 `Comparator.reverseOrder()`로 한 줄로 마무리하는 `App.java`

> Java 8 이상 JDK가 설치되어 있어야 합니다. `javac`과 `java` 명령이 터미널에서 동작하는지 확인하세요.

## 1. 두 가지 인터페이스 비교

자바에서 인터페이스란 두 개의 객체 또는 하나의 객체와 기능이 결합하기 위한 약속을 의미합니다. 지금은 구현체가 존재하지 않지만 나중에 그것을 결합할 때의 합을 맞추기 위한 약속이죠.

그런데 그런 합을 맞추기 위한 약속에는 자세히 보면 종류가 다른 두 가지가 있다는 것을 알 수 있습니다.

하나는 캡슐(역할자)을 구현하겠다는 약속이고 또 하나는 일부 기능(역할자의 일부 기능)을 구현하겠다는 약속입니다.

이번 실습은 그 중 "일부 기능(메소드)을 구현하겠다는 약속"을 정의한 인터페이스를 구현하는 방법에 대해 알아보겠습니다.

이런 인터페이스는 시대적인 변천사에 따라 그것을 구현하는 방법이 여러 번 변화를 가져왔는데, 그것이 어떻게 변해왔으며 지금은 어떤 식으로 구현하고 있는지 하나씩 알아보도록 하겠습니다.

그렇다면 우리가 선택해야 할 인터페이스 구현 방법은 무엇일까요? 맞습니다. 가장 나중에 설명하는 방식이 우리가 사용해야 할 가장 좋은 방법이 되겠습니다. 따라서 그 방법 이전 내용은 가볍게 경험하시면 됩니다.

**1-1. 두 가지 인터페이스 비교**

| 구분 | 캡슐의 서비스를 약속한 인터페이스 | 일부 기능을 약속한 인터페이스 |
|---|---|---|
| 예시 | `List`, `Map`, `Set` | `Comparator`, `Runnable`, `Function` |
| 약속 내용 | "데이터 관리를 위한 서비스들"의 약속 (`add`, `get`, `size` 등) | 캡슐의 서비스를 위해 필요한 ("값의 비교, 변환 등") 구현을 위한 약속 (`compare`, `run`, `apply` 등) |
| 구현체 | `ArrayList`, `HashMap` 등 | 우리가 직접 만들거나 람다로 대체 |

**1-2. 이번 실습의 목표**

`List.sort()` 메소드는 정렬할 때 그 정렬 기준을 사용자로부터 넘겨 받습니다. 그 때 우리가 넘겨줘야 할 것은 `Comparator`를 구현한 구현체이며, 이 객체가 하는 역할은 "두 객체를 비교해서 순서를 알려주는 메소드 하나"를 약속한 인터페이스입니다.

> **핵심**: `List`는 데이터를 관리하는 역할자로 정렬 기능을 서비스하고 있습니다. 그리고 정렬을 서비스하기 위해 "비교하는 규칙"을 넘겨받기 위한 `compare` 메소드를 `Comparator` 인터페이스 이름으로 정의하였습니다. 우리는 이 인터페이스(약속)를 구현해서 넘겨주는 방식으로 정렬을 수행할 수 있습니다.

✅ **확인**
- `List` 인터페이스와 `Comparator` 인터페이스의 차이가 "데이터를 선형으로 관리하는" 역할자에 대한 약속 vs 정렬을 위한 일부 기능("동작 규칙")에 대한 약속임을 설명할 수 있습니다.

🎓 **newlec 쌤의 코멘트**

어찌되었든 인터페이스는 나중에 무엇을 구현해주겠다는 약속입니다. 역할(Role)자의 서비스 목록을 약속하든 어떤 연산을 약속하든, 그 모든 것은 약속이고, 그 약속에 이름을 붙여서 정의하는 도구는 인터페이스입니다.

`List`는 "목록을 관리"하는 서비스 역할을, `Comparator`는 "비교연산"이라는 기능을 약속한 인터페이스입니다. 이번 실습에서는 `Comparator`라는 기능을 약속한 인터페이스를 다양한 방법으로 구현해볼 예정입니다.

## 2. compare 메소드의 규약

`Comparator` 인터페이스는 `compare` 메소드 하나만 구현하면 됩니다. 이 메소드가 반환하는 숫자의 의미는 다음과 같습니다.

**2-1. compare 메소드의 반환값**

```
int compare(T o1, T o2)
```

- 음수 (-1 등): `o1`이 `o2`보다 앞에 온다 (작다)
- 0: `o1`과 `o2`가 같다
- 양수 (1 등): `o1`이 `o2`보다 뒤에 온다 (크다)

**2-2. list.sort가 이 값을 어떻게 쓰는지**

`list.sort(comparator)`는 리스트 안의 모든 쌍을 `comparator.compare(a, b)`로 비교합니다.

- `compare(a, b)`가 음수를 반환하면 `a`를 `b`보다 앞에 배치합니다.
- 양수를 반환하면 `b`를 `a`보다 앞에 배치합니다.
- 역정렬을 하려면? `a`와 `b`의 비교 결과를 반대로 돌려주면 됩니다. 즉, `a.compareTo(b)` 대신 `b.compareTo(a)`를 반환하면 됩니다.

✅ **확인**
- `compare(a, b)`가 -1을 반환하면 `a`가 앞에 온다는 것을 설명할 수 있습니다.
- 역정렬을 위해 `b.compareTo(a)`를 반환해야 한다는 것을 이해했습니다.

🎓 **newlec 쌤의 코멘트**

`compare` 메소드의 반환값은 "순서"를 결정하는 신호입니다. 숫자 자체의 크기가 중요하지 않고, 부호(+/0)만이 중요합니다. 실무에서는 -1, 0, 1을 반환하는 것이 관례지만, `a.compareTo(b)`와 같이 실제 차이를 반환해도 동작은 같습니다.

📝 **이 단계의 핵심**
- `compare`는 음수/0/양수를 반환해서 순서를 결정합니다.
- 역정렬은 비교 대상을 뒤집어(`b.compareTo(a)`) 반환하면 됩니다.

## 3. 외부 클래스로 구현하기

가장 기본적인 방법입니다. `MyComparator`라는 별도 클래스를 만들어 `Comparator<String>`을 구현합니다.

**3-1. 패키지 구조 만들기**

프로젝트 루트 폴더에서 다음 명령을 실행해 폴더를 만듭니다.

```bash
mkdir -p anonymouse_class
```

> Windows PowerShell에서도 `mkdir -p anonymouse_class`가 작동합니다. 만약 안 되면 `mkdir anonymouse_class`로 시도하세요.

**3-2. MyComparator.java 만들기**

파일: `anonymouse_class/MyComparator.java`

```java
package anonymouse_class;

import java.util.Comparator;

public class MyComparator implements Comparator<String> {
    @Override
    public int compare(String a, String b) {
        // 역정렬: b 와 a 를 비교
        return b.compareTo(a);
    }
}
```

**3-3. App.java 만들기**

파일: `anonymouse_class/App.java`

```java
package anonymouse_class;

import java.util.ArrayList;
import java.util.List;

public class App {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        list.add("banana");
        list.add("apple");
        list.add("cherry");

        // MyComparator 를 사용해 역정렬
        list.sort(new MyComparator());

        System.out.println(list);
    }
}
```

**3-4. 컴파일 및 실행**

프로젝트 루트 폴더에서:

```bash
javac anonymouse_class/App.java
java anonymouse_class.App
```

✅ **확인**
- 터미널에 `[cherry, banana, apple]`이 출력됩니다.
- `anonymouse_class` 폴더 안에 `App.class`와 `MyComparator.class` 파일이 생겼습니다.

🎓 **newlec 쌤의 코멘트**

이것이 가장 "정석"적인 방법입니다. `MyComparator`는 독립된 클래스이므로 다른 프로젝트에서도 재사용할 수 있습니다. 하지만 이번 예제처럼 "단 한 번만 쓰는 정렬 기준"이라면, 이렇게 별도 파일을 만드는 것이 과할 수 있습니다. 다음 단계에서 이 문제점을 살펴봅니다.

❌ **자주 하는 실수**

| 증상 | 원인 | 해결 |
|---|---|---|
| `package does not exist` | `package` 문이 파일 첫 줄이 아님 | `package anonymouse_class;`를 파일 맨 위에 배치 |
| `cannot find symbol: class MyComparator` | `MyComparator.java` 파일이 없거나 이름이 다름 | 파일명이 `MyComparator.java`인지 확인, 대소문자 주의 |
| `class App is public, should be declared in a file named App.java` | 파일명과 클래스명이 다름 | 파일명을 `App.java`로 변경 |

📝 **이 단계의 핵심**
- `implements Comparator<String>`으로 인터페이스를 구현합니다.
- `@Override`로 `compare` 메소드를 재정의합니다.

## 4. 외부 클래스 방식의 문제점

3단계의 코드는 동작하지만, 실무 관점에서 몇 가지 비효율이 있습니다.

**4-1. 문제점 분석**

- **불필요한 클래스 생성**: 정렬 기준 하나를 위해 `MyComparator`라는 클래스를 새로 만들었습니다.
- **이름이 없는 존재에 이름을 부여**: 이 비교 로직은 "App 안에서만 쓰이는 역정렬"인데, `MyComparator`라는 이름을 갖는 것은 오버입니다.
- **개체 수 증가**: 비교 기준이 10개만 되어도 클래스 파일이 10개 늘어납니다.

> **핵심**: "한 번 정의하고, 한 번 생성하고, 더 이상 쓰지 않는" 클래스는 별도 파일로 둘 이유가 없습니다.

✅ **확인**
- "외부 클래스로 만드는 것이 왜 비효율적인가"를 3가지 이유로 설명할 수 있습니다.

🎓 **newlec 쌤의 코멘트**

소프트웨어 설계에서 YAGNI(You Aren't Gonna Need It) 원칙이 있습니다. "필요할 때까지 만들지 마라"는 뜻입니다. `MyComparator`는 현재 App 안에서만 쓰이므로, App 안에 두는 것이 더 적절합니다.

📝 **이 단계의 핵심**
- 한 번만 쓰는 로직은 별도 클래스로 만들지 않는 것이 좋습니다.
- 클래스는 "재사용 가능한 역할"일 때만 별도 파일로 만듭니다.

## 5. 내부 클래스로 옮기기

`MyComparator`를 `App` 클래스 안에 넣습니다.

**5-1. MyComparator.java 삭제**

```bash
rm anonymouse_class/MyComparator.java
rm anonymouse_class/MyComparator.class
```

> Mac/Linux는 `rm`, Windows는 `del` 명령을 사용합니다.

**5-2. App.java 수정**

파일: `anonymouse_class/App.java`

```java
package anonymouse_class;

import java.util.ArrayList;
import java.util.List;
import java.util.Comparator;

public class App {

    // App 클래스 안에 MyComparator 를 정의
    class MyComparator implements Comparator<String> {
        @Override
        public int compare(String a, String b) {
            return b.compareTo(a);
        }
    }

    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        list.add("banana");
        list.add("apple");
        list.add("cherry");

        // 내부 클래스를 생성
        App app = new App();
        list.sort(app.new MyComparator());

        System.out.println(list);
    }
}
```

**5-3. 컴파일 및 실행**

```bash
javac anonymouse_class/App.java
java anonymouse_class.App
```

✅ **확인**
- 터미널에 `[cherry, banana, apple]`이 출력됩니다.
- `anonymouse_class` 폴더 안에 `App.class`와 `App$MyComparator.class` 파일이 생겼습니다.

🎓 **newlec 쌤의 코멘트**

내부 클래스는 외부 클래스의 인스턴스를 필요로 합니다. 그래서 `App app = new App();` 후 `app.new MyComparator()`로 생성해야 합니다. 이 코드가 다소 번거로워 보이지만, `MyComparator`가 App 안에 속해 있다는 점을 명확히 보여줍니다.

❌ **자주 하는 실수**

| 증상 | 원인 | 해결 |
|---|---|---|
| `non-static method cannot be referenced from a static context` | `main`은 static이지만 `MyComparator`는 non-static 내부 클래스 | `App app = new App();` 후 `app.new MyComparator()`로 생성 |
| `MyComparator cannot be resolved` | `MyComparator`가 App 안에 없거나 접근 불가 | `MyComparator`가 App 클래스 안에 있는지 확인 |

📝 **이 단계의 핵심**
- 내부 클래스는 외부 클래스 인스턴스가 필요합니다.
- `app.new MyComparator()`로 생성합니다.

## 6. 내부 클래스도 여전히 과하다

5단계의 코드는 여전히 "클래스를 정의하고, 인스턴스를 생성하고, 메소드를 구현"하는 구조입니다.

**6-1. 불필요한 부분 분석**

- 클래스 정의: `class MyComparator implements ...`
- 인스턴스 생성: `App app = new App(); list.sort(app.new MyComparator());`
- 메소드 구현: `compare` 메소드

> 의심: "한 번만 쓰는 비교 로직"에 클래스를 정의하고, 인스턴스를 생성하고, 메소드를 구현할 필요가 있는가?

✅ **확인**
- "내부 클래스도 여전히 과하다"는 점을 인식했습니다.

🎓 **newlec 쌤의 코멘트**

자바 5 이후에 이런 불편함을 없애기 위해서 메소드 중첩 클래스와 익명 클래스가 등장했습니다. 다음 단계에서 `main` 메소드 안에서 바로 클래스(메소드 중첩 클래스)를 정의하는 방법을 보여줍니다.

📝 **이 단계의 핵심**
- 한 번만 쓰는 로직은 클래스 정의와 인스턴스 생성이 불필요할 수 있습니다.

## 7. main 메소드 안에서 클래스 정의하기

`main` 메소드 상단에 클래스를 선언하고 바로 `new`합니다.

**7-1. App.java 수정**

파일: `anonymouse_class/App.java`

```java
package anonymouse_class;

import java.util.ArrayList;
import java.util.List;
import java.util.Comparator;

public class App {
    public static void main(String[] args) {
        // main 메소드 안에서 클래스를 정의
        class MyComparator implements Comparator<String> {
            @Override
            public int compare(String a, String b) {
                return b.compareTo(a);
            }
        }

        List<String> list = new ArrayList<>();
        list.add("banana");
        list.add("apple");
        list.add("cherry");

        // 바로 생성
        list.sort(new MyComparator());

        System.out.println(list);
    }
}
```

**7-2. 컴파일 및 실행**

```bash
javac anonymouse_class/App.java
java anonymouse_class.App
```

✅ **확인**
- 터미널에 `[cherry, banana, apple]`이 출력됩니다.
- `anonymouse_class` 폴더 안에 `App.class`와 `App$1MyComparator.class`(또는 유사한 이름) 파일이 생겼습니다.

🎓 **newlec 쌤의 코멘트**

이제 App 인스턴스를 만들 필요 없이 `new MyComparator()`로 바로 생성할 수 있습니다. 하지만 여전히 `class MyComparator`라는 이름이 있습니다. 이 이름도 불필요할 수 있습니다.

📝 **메소드 중첩 클래스의 특징**
- **스코프 제한**: 메소드 내부에서만 정의되고 사용될 수 있어, 클래스의 다른 부분이나 외부에서 접근할 수 없습니다.
- **인스턴스 필드 접근**: 정의된 메소드가 인스턴스 메소드인 경우, 해당 클래스의 인스턴스 필드나 메소드에 직접 접근할 수 있습니다.
- **로컬 변수 접근**: 메소드 내에서 선언된 `final` 또는 effectively final 로컬 변수를 참조할 수 있습니다.
- **명시적 생성 필요**: `new` 키워드를 사용하여 명시적으로 인스턴스를 생성해야 하며, 다른 중첩 클래스와 달리 `new Outer.Inner()`와 같은 구문은 사용할 수 없습니다.

📝 **이 단계의 핵심**
- 로컬 클래스는 메소드 안에서 정의할 수 있습니다.
- 외부 클래스 인스턴스가 필요 없습니다.

## 8. 익명 클래스로 이름 없애기

클래스 이름을 붙일 이유가 없다면, 이름을 없앱니다.

**8-1. App.java 수정**

파일: `anonymouse_class/App.java`

```java
package anonymouse_class;

import java.util.ArrayList;
import java.util.List;
import java.util.Comparator;

public class App {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        list.add("banana");
        list.add("apple");
        list.add("cherry");

        // 익명 클래스로 구현
        list.sort(new Comparator<String>() {
            @Override
            public int compare(String a, String b) {
                return b.compareTo(a);
            }
        });

        System.out.println(list);
    }
}
```

위의 코드 내용은 다음과 같습니다.

- `Comparator<String>(){ ... }`: 중괄호는 인터페이스로 약속한 추상 메서드(`compare`)를 구현하는 코드 블록입니다.
- `new Comparator<String>()`: 익명으로 구현한 클래스의 인스턴스를 생성합니다.

**8-2. 컴파일 및 실행**

```bash
javac anonymouse_class/App.java
java anonymouse_class.App
```

✅ **확인**
- 터미널에 `[cherry, banana, apple]`이 출력됩니다.
- `anonymouse_class` 폴더 안에 `App.class`와 `App$1.class`(또는 유사한 이름) 파일이 생겼습니다.

🎓 **newlec 쌤의 코멘트**

익명 클래스는 "이름이 없는 클래스"입니다. `new Comparator<String>() { ... }`로 바로 생성하고 사용합니다. 하지만 여전히 `new`, 중괄호, `@Override`가 있습니다. 이것이 람다식이 등장하게 된 배경입니다.

❌ **자주 하는 실수**

| 증상 | 원인 | 해결 |
|---|---|---|
| `incompatible types: Comparator<String> cannot be converted to Comparator` | 제네릭 타입이 다름 | `new Comparator<String>()`로 제네릭을 명시 |
| `method does not override or implement a method from a supertype` | `@Override`가 있지만 메소드가 인터페이스에 없음 | `compare` 메소드가 `Comparator`에 있는지 확인 |

📝 **이 단계의 핵심**
- 익명 클래스는 이름을 붙이지 않고 바로 생성합니다.
- `new Interface() { ... }` 형태로 작성합니다.

## 9. 익명 클래스도 여전히 과하다

8단계의 코드는 여전히 `new`, 중괄호, `@Override`가 있습니다.

**9-1. 불필요한 부분 분석**

- `new`: `new Comparator<String>()`
- 중괄호: `{ ... }`
- `@Override`: `@Override`
- 메소드 시그니처: `public int compare(String a, String b)`

> **핵심**: `compare` 메소드 하나만 구현하는데, 이 모든 것이 필요할까?

✅ **확인**
- "익명 클래스도 여전히 과하다"는 점을 인식했습니다.

🎓 **newlec 쌤의 코멘트**

자바 8에서 도입된 람다식은 이 모든 것을 생략할 수 있게 해줍니다. 인터페이스가 메소드 하나만 약속할 때(함수형 인터페이스), 람다식으로 대체할 수 있습니다.

📝 **이 단계의 핵심**
- 함수형 인터페이스는 람다식으로 대체할 수 있습니다.
- `Comparator`는 함수형 인터페이스입니다.

## 10. 람다식으로 한 줄로 줄이기

람다식으로 바꾸면 코드가 한 줄이 됩니다.

**10-1. App.java 수정**

파일: `anonymouse_class/App.java`

```java
package anonymouse_class;

import java.util.ArrayList;
import java.util.List;
import java.util.Comparator;

public class App {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        list.add("banana");
        list.add("apple");
        list.add("cherry");

        // 람다식으로 구현
        list.sort((a, b) -> b.compareTo(a));

        System.out.println(list);
    }
}
```

**10-2. 람다식과 익명 클래스의 대응**

| 익명 클래스 | 람다식 |
|---|---|
| `new Comparator<String>() {` | `(a, b) ->` |
| `@Override public int compare(String a, String b) {` | (생략) |
| `return b.compareTo(a);` | `b.compareTo(a)` |
| `}` | (생략) |
| `}` | (생략) |

**10-3. 컴파일 및 실행**

```bash
javac anonymouse_class/App.java
java anonymouse_class.App
```

✅ **확인**
- 터미널에 `[cherry, banana, apple]`이 출력됩니다.
- `anonymouse_class` 폴더 안에 `App.class` 파일만 있습니다. (익명 클래스 클래스 파일 없음)

🎓 **newlec 쌤의 코멘트**

람다식은 "함수형 인터페이스를 구현하는 익명 클래스"의 축약형입니다. `Comparator`는 `compare` 메소드 하나만 약속하므로, `(a, b) -> b.compareTo(a)`로 충분합니다. 이것이 자바 8 이후의 표준적인 방식입니다.

❌ **자주 하는 실수**

| 증상 | 원인 | 해결 |
|---|---|---|
| `incompatible types: lambda expression not compatible with Comparator` | 람다식 인자 개수가 다름 | `(a, b) ->`로 두 인자를 명시 |
| `cannot infer type arguments` | 제네릭 타입을 추론할 수 없음 | `list.sort((String a, String b) -> b.compareTo(a))`로 타입 명시 |

📝 **이 단계의 핵심**
- 람다식은 `(인자) -> 표현식` 형태로 작성합니다.
- 함수형 인터페이스는 람다식으로 대체할 수 있습니다.

## 11. 실무에서는 내장 유틸을 쓴다

직접 구현하는 연습은 이해를 위해서고, 실무에서는 내장 유틸을 씁니다.

**11-1. Comparator.reverseOrder() 사용**

파일: `anonymouse_class/App.java`

```java
package anonymouse_class;

import java.util.ArrayList;
import java.util.List;
import java.util.Comparator;

public class App {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        list.add("banana");
        list.add("apple");
        list.add("cherry");

        // 내장 유틸로 역정렬
        list.sort(Comparator.reverseOrder());

        System.out.println(list);
    }
}
```

**11-2. 다른 내장 유틸 소개**

| 유틸 | 설명 | 예시 |
|---|---|---|
| `Comparator.naturalOrder()` | 자연 순서 (오름차순) | `list.sort(Comparator.naturalOrder())` |
| `Comparator.reverseOrder()` | 역순 (내림차순) | `list.sort(Comparator.reverseOrder())` |
| `Comparator.comparing(...)` | 특정 필드로 비교 | `list.sort(Comparator.comparing(User::getName))` |
| `thenComparing(...)` | 추가 비교 기준 | `list.sort(Comparator.comparing(User::getAge).thenComparing(User::getName))` |

**11-3. 컴파일 및 실행**

```bash
javac anonymouse_class/App.java
java anonymouse_class.App
```

✅ **확인**
- 터미널에 `[cherry, banana, apple]`이 출력됩니다.
- 코드가 한 줄로 줄었습니다.

🎓 **newlec 쌤의 코멘트**

실무에서는 `Comparator.reverseOrder()` 같은 내장 유틸을 사용합니다. 직접 구현하는 연습은 "왜 이렇게 동작하는지"를 이해하기 위한 것이며, 실무에서는 가독성과 유지보수성을 위해 내장 유틸을 씁니다.

📝 **이 단계의 핵심**
- 실무에서는 `Comparator.reverseOrder()` 같은 내장 유틸을 사용합니다.
- 직접 구현은 이해를 위한 연습입니다.

## 12. 왜 이렇게 줄일 수 있었는가

외부 클래스 → 내부 클래스 → main 안 클래스 → 익명 클래스 → 람다 → 내장 유틸. 이 줄임이 가능한 이유는 무엇일까요?

**12-1. 핵심 이유**

**인터페이스가 메소드 하나만 약속했기 때문입니다.**

- `Comparator`는 `compare` 메소드 하나만 약속합니다.
- 따라서 "이 메소드를 구현하는 로직"을 람다식으로 축약할 수 있습니다.
- 만약 `Comparator`가 `compare` 외에 `equals`, `hashCode` 등 여러 메소드를 약속했다면, 람다식으로 축약할 수 없었을 것입니다.

**12-2. 다음에 볼 내용**

- 람다식의 자세한 동작 원리
- 함수형 인터페이스의 종류 (`Function`, `Predicate`, `Consumer`, `Supplier`)
- 스트림 API와 람다식의 결합

✅ **확인**
- "인터페이스가 메소드 하나만 약속했기 때문에 람다식으로 축약할 수 있다"는 것을 설명할 수 있습니다.

🎓 **newlec 쌤의 코멘트**

자바 8 이후의 코드는 "인터페이스 + 람다"의 조합으로 훨씬 간결해졌습니다. 하지만 이 간결함의 기반은 "인터페이스가 무엇을 약속하는지"를 아는 것입니다. 이번 실습을 통해 `Comparator`가 "비교하는 메소드 하나"를 약속한다는 것을 체득했습니다.

📝 **이 단계의 핵심**
- 함수형 인터페이스는 람다식으로 축약할 수 있습니다.
- 실무에서는 내장 유틸을 사용합니다.

## 정리

1. 인터페이스는 "캡슐을 약속" 또는 "메소드를 약속"하는 두 가지가 있다.
2. `Comparator`는 `compare` 메소드 하나를 약속하며, 음수/0/양수로 순서를 결정한다.
3. 외부 클래스로 `Comparator`를 구현하면 별도 파일이 필요하다.
4. 한 번만 쓰는 로직은 별도 클래스로 만들 이유가 없다.
5. 내부 클래스로 이동하면 외부 클래스 인스턴스가 필요하다.
6. 내부 클래스도 여전히 클래스 정의와 인스턴스 생성이 불필요할 수 있다.
7. `main` 메소드 안에서 클래스를 정의하면 외부 인스턴스가 필요 없다.
8. 익명 클래스는 이름을 붙이지 않고 바로 생성한다.
9. 익명 클래스도 `new`, 중괄호, `@Override`가 반복된다.
10. 람다식은 `(a, b) -> b.compareTo(a)`로 한 줄로 줄인다.
11. 실무에서는 `Comparator.reverseOrder()` 같은 내장 유틸을 사용한다.
12. 인터페이스가 메소드 하나만 약속했기 때문에 람다식으로 축약할 수 있다.
