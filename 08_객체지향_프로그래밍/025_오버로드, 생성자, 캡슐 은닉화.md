# 오버로드, 생성자, 캡슐 은닉화

## 1. 오버로드(Overload) 메서드

동일한 이름의 함수가 한 캡슐 안에 여러 개 있을 수 있을까? **있다.** 자바는 이름이 같은 메서드가 여러 개 있어도, **인자(매개변수)로 구분**해서 정확히 어떤 메서드를 부른 건지 알아낸다.

- 동일한 이름의 메서드 중에서 **인자가 더 많은 쪽**을 오버로드 메서드라고 부른다
- 인자가 더 적은 쪽(보통 인자 없음)은 **디폴트 메서드**라고 부른다

### 오버로드 집중화

오버로드 메서드가 여러 개 있다는 건, 그 안에 **중복된 내용이 있을 가능성**이 높다는 신호다. 그래서 인자가 적은(값이 고정된) 쪽에서, 인자를 갖고 있는 쪽을 그대로 호출하도록 몰아주는 방식을 쓴다 — 이걸 **오버로드 집중화**라고 부른다.

```java
public void init() {
    init(50, 50, 50);   // 값이 고정된 쪽이, 인자 있는 쪽을 호출
}

public void init(int kor, int eng, int math) {
    this.kor = kor;
    this.eng = eng;
    this.math = math;
}
```

`init()`은 자기가 직접 필드를 채우지 않고, "기본값 50, 50, 50으로 `init(int, int, int)`를 불러줘"라고 위임한다. 덕분에 실제 초기화 로직은 `init(int, int, int)` 한 곳에만 존재한다.

`print()`도 같은 패턴이다.

```java
public void print() {
    print(false);
}

public void print(boolean hasBorder) {
    ...
    if (hasBorder) {
        System.out.println("--------------------------------");
    }
}
```

## 2. 생성자(Constructor)

생성자는 **객체를 생성할 때 그 객체를 초기화하는 특수 목적의 함수**다. 다만 "생성자 함수"나 "초기화 함수"라고는 부르지 않는다 — 이유는 아래에서 이어진다.

### 초기화 함수 vs `init()`

진짜 초기화 함수는 **객체가 생성될 때 딱 한 번만 호출되고, 다시는 호출될 수 없는 것**이어야 한다. 그런데 지금까지 써온 `init()`은 아무 때나 다시 부를 수 있으니, 사실 "초기화 함수"라기보다는 **초기값으로 되돌리는 reset 함수**에 더 가깝다.

객체는 `new` 연산자를 쓸 때 생성된다. 그리고 자바에서 **모든 클래스는 반드시 생성자를 가지고 있어야 한다** — 클래스 이름과 똑같은 이름을 가진 함수처럼 보이는 그 녀석, `Exam()`이라고 썼던 게 바로 생성자다.

### 주의: 생성자는 함수가 아니다

- 함수는 **이름**이 있다. 그런데 생성자는 "`Exam`"이 이름이 아니다 — 호출할 수 있는 이름을 따로 갖고 있지 않다
- 생성자는 `(){}` **그 자체**가 생성자다. `Exam`은 "나를 호출할 수 있는 건 방금 태어난 `Exam` 객체뿐"이라는 **제한자** 역할만 할 뿐이다
- 함수의 원형은 **반환형식 + 함수명 + 인자**를 갖는데, 생성자는 **반환형식도 없고 함수이름도 없다.** 인자는 가질 수 있고, 호출은 된다
- 즉 생성자는 이름으로 호출하는 게 아니라 **객체로 호출**되는, 조금 특이한 존재다

### 생성자도 오버로드된다

```java
// 기본 생성자
public Exam() {
}

// 오버로드 생성자
public Exam(int kor, int eng, int math) {
    this.kor = kor;
    this.eng = eng;
    this.math = math;
}
```

- `init()`은 이름이 있어서 필요할 때마다 몇 번이고 다시 부를 수 있지만, 생성자는 **객체를 생성하는 그 순간에 딱 한 번만** 호출된다
- 지금 `public Exam() { }`은 몸통이 비어 있어서, `new Exam()`으로 만들면 필드는 자바의 기본값(`int`는 0)으로만 남는다. 여기에 `this(50, 30, 40)`처럼 오버로드 생성자를 호출하는 코드를 넣으면, 인자 없이 생성해도 원하는 초기값으로 바로 채워지게 만들 수 있다 — 이때 `this`는 지금 막 만들어지고 있는 그 객체 자신을 가리킨다

### 기본 생성자는 언제 자동으로 생기는가

생성자를 하나도 안 만들고 객체를 만들면, **번역기(컴파일러)가 알아서 기본 생성자를 추가**해준다 — 생성자는 무조건 있어야 하는 존재라서다. 이 자동 생성된 기본 생성자는 보통 기본값으로 필드를 세팅해준다.

그런데 **오버로드 생성자를 하나라도 직접 만들면, 컴파일러는 더 이상 기본 생성자를 자동으로 만들어주지 않는다.** 왜냐하면 이미 "생성자가 있는 상태"이기 때문에, 굳이 컴파일러가 나서서 하나 더 만들어줄 이유가 없어서다.

이 성질을 거꾸로 이용할 수도 있다 — **일부러 오버로드 생성자만 만들고 기본 생성자를 안 만들면**, `new Exam()`처럼 인자 없이 생성하는 방법 자체가 사라진다. 즉 "인자를 반드시 주고 생성해야 한다"는 규칙을 컴파일 단계에서 강제할 수 있다.

이렇게 생성자를 여러 개(기본 + 오버로드) 만들어두면, 사용하는 입장에서는 상황에 맞는 걸 골라 쓸 수 있어서 편해진다. 오버로드는 많을수록 좋다 — 서버(=캡슐)는 클라이언트가 쉽게 쓸 수 있도록 다양한 사용 방식을 미리 준비해두는 역할을 해야 한다.

## 3. 캡슐 은닉화

캡슐로 나눠놨다고 끝이 아니다. 어떤 함수가 다른 캡슐의 데이터 구조를 서비스를 거치지 않고 직접 가져다 쓰는 순간, **그 캡슐은 깨진다.**

이런 접근은 원칙적으로 금지된다. 다른 캡슐의 데이터가 필요하면, 그 데이터를 직접 만지는 게 아니라 **반드시 서비스를 요청해서** 결과만 받아 써야 한다.

문제는 "서비스로만 쓰자"는 규칙을 정해놔도, 실제로는 이 규칙을 넘어서서 데이터에 직접 손대는 경우가 생긴다는 것이다. 그래서 캡슐 스스로를 **방어하는 도구**가 필요한데, 이게 바로 **은닉화**다. 캡슐이 자기 자신을 숨길 수 있어야 규칙이 강제되고, 그렇지 못하면 캡슐은 언제든 깨질 수 있다.

자바에서 이 방어 도구가 바로 `private`이다.

```java
public class Exam {
    private int kor;
    private int eng;
    private int math;
}
    // private로 막아서 외부에서 exam.kor 처럼 바로 접근할 수 없게 한다
    // 캡슐을 깨는 것을 방지 = 캡슐 은닉
```

필드를 `private`으로 감싸면, `Exam` 밖에서는 아예 `exam.kor`라고 쓸 수조차 없다. 이전에 "데이터는 역할자 안에 숨기고 서비스로만 다루게 한다"고 정리했던 것을, `private` 키워드로 **강제**하는 것이 은닉화다 — 규칙을 "지켜주길 바라는 것"에서 "지킬 수밖에 없게 만드는 것"으로 바꾸는 단계다.

## 4. 종합 예시 — step3_capsule의 최종 형태

앞서 다룬 `step3_capsule` 단계에서, `Exam`은 오버로드 생성자와 은닉화까지 적용된 최종 형태로 발전했다.

```java
public class Exam {
    private int kor;
    private int eng;
    private int math;

    public Exam() {
        this(50, 50, 50);
    }

    public Exam(int kor, int eng, int math) {
        this.kor = kor;
        this.eng = eng;
        this.math = math;
    }

    public void init() {
        init(50, 50, 50);
    }

    public void init(int kor, int eng, int math) {
        this.kor = kor;
        this.eng = eng;
        this.math = math;
    }

    public void print() {
        print(false);
    }

    public void print(boolean hasBorder) {
        ...
        if (hasBorder) {
            System.out.println("--------------------------------");
        }
    }
}
```

```java
Exam exam1 = new Exam();
// 기본 생성자 → 내부에서 this(50, 50, 50) 호출

Exam exam2 = new Exam(10, 20, 30);
// 오버로드 생성자 → 원하는 값으로 바로 초기화

exam1.init();          // 기본값(50, 50, 50)으로 재설정
exam1.init(10, 20, 30); // 원하는 값으로 재설정

exam1.print();       // 구분선 없이 출력
exam1.print(true);   // 구분선까지 출력
```

`kor`, `eng`, `math`는 이제 `private`이라 `App`에서 절대 직접 건드릴 수 없다. `App`이 할 수 있는 건 오직 생성자로 객체를 만들고, `init()`/`print()` 같은 공개된 서비스를 호출하는 것뿐이다 — 캡슐이 완전히 은닉된 상태다.
