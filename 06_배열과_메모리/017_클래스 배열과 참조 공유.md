# 클래스 배열과 참조 공유

## 1. 슬라이드 핵심 문구 — "클래스 배열은 객체 배열이 아니라 객체 참조 배열이다"

강의 슬라이드에서 `Exam[] exams`를 그림으로 보여준 것의 핵심 메시지:

> **배열의 각 칸(`exams[0]`, `exams[1]`, ...)은 객체 자체를 담고 있는 게 아니라, 객체를 가리키는 "참조(주소)"만 담고 있다.**

그리고 이 참조는 **배열 칸뿐 아니라, 배열 밖의 평범한 변수도 똑같이 가질 수 있다.** 그래서 배열 칸 하나와 별도 변수 하나가 **같은 객체를 동시에 가리키는 것(공유, aliasing)**이 가능하다 — 이게 그림에서 화살표 여러 개가 상자 하나로 모이는 이유였다.

```
exams[0]  ──→ 상자 A (화살표 1개, 독립)

exam      ──┐
exams[1]  ──┼──→ 상자 B (화살표 3개 모임, 셋이 공유)
exams[2]  ──┘
```

## 2. Code3.java — 실제 코드로 재현

```java
package ex5_struct;

public class Code {
    public static void main(String[] args) {

        Exam[] exams = new Exam[3];

        Exam exam = new Exam();
        exams[1] = exam;
        exams[2] = exam;

        exams[0] = new Exam();

    }
}
```

### 한 줄씩 메모리 상태 따라가기

**`Exam[] exams = new Exam[3];`**
```
exams: [ null, null, null ]   ← 참조를 담을 빈 칸 3개. 아직 Exam 객체는 0개
```

**`Exam exam = new Exam();`** — 새 객체 하나 생성, `exam`이 가리킴 (배열과는 아직 무관)
```
exam ──→ #100 Exam{ }
exams: [ null, null, null ]
```

**`exams[1] = exam;`** — `exam`이 가리키던 주소(#100)를 그대로 복사해서 `exams[1]`에도 적어 넣음. **새 객체가 생기는 게 아니라 참조만 복사됨**
```
exam ──────┐
            ├──→ #100 Exam{ }
exams[1] ──┘
```

**`exams[2] = exam;`** — 같은 방식으로 `exams[2]`도 같은 주소(#100)를 받음
```
exam ──────┐
            ├──→ #100 Exam{ }   ← 셋이 같은 객체를 공유
exams[1] ──┤
exams[2] ──┘
```

**`exams[0] = new Exam();`** — `exam`, #100과 완전히 무관한 **별도의 새 객체** 생성
```
exams[0] ──→ #200 Exam{ }        ← 독립된 객체 (아무도 안 공유)

exam ──────┐
            ├──→ #100 Exam{ }    ← 여전히 셋이 공유 중
exams[1] ──┤
exams[2] ──┘
```

### 최종 상태

| 이름 | 가리키는 객체 |
|---|---|
| `exams[0]` | #200 (독립, 혼자만 가리킴) |
| `exam`, `exams[1]`, `exams[2]` | **#100 (셋이서 같은 객체를 공유)** |

## 3. `new`가 있는 줄 vs 없는 줄 — 새 객체가 생기는지 구분하는 기준

```java
exams[0] = new Exam();   // ✅ new가 있음 → 이 순간 진짜 새 객체 생성
exams[1] = exam;         // ❌ new 없음 → 이미 있는 객체의 참조만 복사
exams[2] = exam;         // ❌ new 없음 → 위와 동일한 참조를 한 번 더 복사
```

`new`가 붙어있느냐만 보면, 그 줄에서 **힙에 새 데이터가 생기는지 아니면 기존 참조를 나눠 갖는 것뿐인지** 바로 판단할 수 있다. 이 세 줄이 끝난 뒤에도 힙에 생긴 `Exam` 객체는 딱 하나(#100)뿐이고, 그걸 가리키는 이름표만 세 개로 늘어난 것.

## 4. `Exam`, `Exam[]`, `Exam()`, `exam` — 용어 정리

같은 이름 `Exam`을 여러 문맥에서 써서 헷갈리기 쉬운데, 역할이 전부 다르다.

| 표기 | 정체 | 역할 |
|---|---|---|
| `Exam` | **클래스(타입) 이름** | "이건 Exam 종류다"라고 선언할 때 (`Exam exam;`) |
| `Exam[]` | **배열 타입** | "Exam 여러 개를 담는 배열"이라는 타입 (`Exam[] exams;`) |
| `Exam()` | **생성자 호출** | 반드시 `new`와 함께 — 실제로 객체를 하나 만들어내는 실행 동작 |
| `exam` (소문자) | **변수 이름** | `Exam` 타입의 어떤 객체를 가리키는 이름표 하나 |

```
타입 이름  변수이름 = new 타입이름(...);
   ↑                    ↑
"이건 이 타입이다"    "실제로 만들어라"
```

- `Exam exam;` — 선언만, 아직 객체 없음 (`null`)
- `new Exam()` — 실행, 이 순간 힙에 진짜 객체 생성
- `Exam exam = new Exam();` — 위 두 줄을 한 줄로 합친 것, 완전히 동일

## 5. `exam.kor / exam.eng / exam.math`는 배열이 아니다

`exam` 안에 값이 세 개(`kor, eng, math`) 들어있다고 해서 배열이 되는 건 아니다. "값을 여러 개 묶는다"는 점만 같을 뿐, 구조와 접근 방식이 다르다.

| | 배열 | `Exam` 객체의 필드 |
|---|---|---|
| 값을 구분하는 방법 | 번호(인덱스) — `nums[0]` | **이름(필드명)** — `exam.kor` |
| 담는 값의 종류 | 전부 같은 타입 | 필드마다 다른 타입 가능 (`int kor; String name;`) |
| 개수 | `new int[N]`으로 자유롭게 정함 | 클래스 설계도(`Exam.java`)에 **고정** |
| 반복문(`for`)으로 순회 | 가능 (`for i in 0..length`) | **불가능** — 번호가 없어서 못 돌림 |
| 없는 항목에 접근 시 | 실행 중 오류(`ArrayIndexOutOfBoundsException`) | **컴파일 시점**에 바로 오류(`cannot find symbol`) |

```
배열 (int[] scores):              객체 (Exam exam):
┌──────┬──────┬──────┐            ┌─────────────────┐
│ [0]  │ [1]  │ [2]  │            │  kor  : (값)     │
└──────┴──────┴──────┘            │  eng  : (값)     │
  번호로 구분                       │  math : (값)     │
                                   └─────────────────┘
                                     이름으로 구분
```

**결론** — "여러 값을 하나로 묶는다"는 아주 추상적인 수준에서는 배열과 비슷해 보이지만, 값을 구분하는 방식(번호 vs 이름), 크기 유연성(가변 vs 고정), 순회 가능 여부(가능 vs 불가능)가 전부 달라서 자바는 이 둘을 **배열(Array)**과 **클래스/객체(Class/Object)**라는 별개의 문법으로 나눠서 제공한다.

- [[015_배열과 참조, 메모리 구조]]의 13번 섹션("구조체 배열")과 이어지는 내용 — 거기서는 `exams[0].kor`처럼 **바깥 배열 구조**를 2차원 배열과 비교했다면, 이 노트는 그 안의 **`Exam` 객체 하나가 배열이 아니라는 점**과 **참조 공유(aliasing)**를 다룬다.
