# 메뉴 캡슐화와 파일 저장/불러오기 실습

메뉴 하나(id, 이름, 가격)를 관리하는 `Menu` 캡슐을 만들고, 입력·출력뿐 아니라 **파일 저장/불러오기까지 스스로 책임지게** 만든 실습.

## 1. Menu 클래스 — 데이터 + 서비스

```java
public class Menu {
    int id;
    String name;
    int price;

    void input() {
        int id;
        String name;
        int price;

        Scanner scan = new Scanner(System.in, "MS949");

        System.out.println("메뉴 입력");
        System.out.print("메뉴 ID : ");
        id = Integer.parseInt(scan.nextLine());
        System.out.print("메뉴 명 : ");
        name = scan.nextLine();
        System.out.print("메뉴 가격 : ");
        price = Integer.parseInt(scan.nextLine());

        this.id = id;
        this.name = name;
        this.price = price;
    }

    void print() {
        System.out.println("메뉴 출력");
        System.out.printf("%d, %s, %d%n", id, name, price);
    }

    void save() throws IOException {
        FileOutputStream fos = new FileOutputStream("menu.data");
        PrintStream ps = new PrintStream(fos);

        ps.printf("%d,%s,%d", id, name, price);

        ps.close();
        fos.close();
    }

    void load() throws IOException {
        FileInputStream fis = new FileInputStream("menu.data");
        Scanner scan = new Scanner(fis);

        scan.useDelimiter(",|\\r\\n|\\n");

        if (scan.hasNext()) {
            this.id = scan.nextInt();
            this.name = scan.next();
            this.price = scan.nextInt();
            System.out.println("메뉴를 성공적으로 불러왔습니다.");
        }

        scan.close();
        fis.close();
    }
}
```

`App`은 `menu.input()`, `menu.print()`, `menu.save()`, `menu.load()`처럼 서비스 이름만 부르고, `id`/`name`/`price` 필드는 전혀 건드리지 않는다. 이전에 정리한 캡슐화 3단계 중 마지막 단계(capsule)와 같은 구조다.

## 2. 겪은 문제와 해결

### 2-1. 입력한 한글이 `?`로 깨짐

`Scanner(System.in)`처럼 인코딩을 지정하지 않으면, 윈도우 콘솔의 실제 인코딩(MS949)과 자바가 입력을 해석하는 인코딩이 어긋나서 한글이 깨진다.

```java
Scanner scan = new Scanner(System.in, "MS949");
```

콘솔 인코딩을 명시적으로 맞춰주면 해결된다.

### 2-2. `save()`/`load()`에 `throws IOException`을 붙였더니 `App`에서 컴파일 에러

파일 입출력은 **체크 예외(checked exception)**인 `IOException`을 던질 수 있어서, 이 메소드를 부르는 쪽도 처리해야 한다.

- **방법 1**: 호출부(`main`)에도 그대로 `throws IOException`을 붙여서 위로 넘긴다 — 간단하지만, 예외가 실제로 나면 프로그램이 그대로 종료된다.
  ```java
  public static void main(String[] args) throws IOException {
  ```
- **방법 2**: `try-catch`로 감싸서 직접 처리한다 — 저장/로드 한 번 실패해도 프로그램은 계속 실행된다.
  ```java
  try {
      menu.save();
  } catch (IOException e) {
      System.out.println("저장 중 오류가 발생했습니다.");
  }
  ```

메뉴 관리 프로그램처럼 계속 루프를 도는 구조에서는 방법 2가 더 안전하지만, 실습 단계에서는 방법 1로 먼저 넘어가도 된다.

### 2-3. CSV 구분자 정규식 — `,|\\r\\n|\\n`

`useDelimiter(",|\\r\\n|\\n")`는 "쉼표(,) **또는** CRLF(`\r\n`, 윈도우 줄바꿈) **또는** LF(`\n`, 유닉스 줄바꿈)" 중 아무거나 나오면 그 지점에서 값을 끊어 읽으라는 뜻이다. `1,아메리카노,2000\r\n2,라떼,3000\r\n` 같은 CSV 데이터에서, 쉼표든 줄바꿈이든 구분자를 만날 때마다 잘라서 `"1"`, `"아메리카노"`, `"2000"`, `"2"`, `"라떼"`, `"3000"` 순으로 값을 하나씩 꺼낼 수 있게 해준다.

**주의**: `\\r\\n`을 `\\n\\r?`처럼 순서를 바꿔 쓰면 안 된다. 윈도우 줄바꿈의 실제 바이트 순서는 항상 `\r`이 먼저, `\n`이 나중(`\r\n`)이라서, 순서를 반대로 쓰면 `\r`이 델리미터로 인식되지 않고 직전 값 끝에 그대로 남아 `Integer.parseInt()`가 `NumberFormatException`을 던지는 등 눈에 안 보이는 버그로 이어진다.

## 3. 접근 제한자 — public / (default) / private

| 접근 제한자 | 같은 클래스 | 같은 패키지 | 다른 패키지 |
|---|---|---|---|
| `public` | 가능 | 가능 | 가능 |
| (아무것도 안 씀) | 가능 | 가능 | 불가능 |
| `private` | 가능 | 불가능 | 불가능 |

지금 `input()`, `print()`, `save()`, `load()`는 접근 제한자를 안 붙인 default 상태라서, `App`과 `Menu`가 같은 패키지에 있는 덕분에 우연히 잘 동작하고 있다. 하지만 이 메소드들은 `App`이 외부에서 호출해서 쓰는 **서비스**이므로, "이건 외부에 공개하는 기능이다"라는 의도를 명확히 드러내려면 `public`을 붙이는 게 맞다.

## 4. `System.out` vs `System.err`

| | `System.out` | `System.err` |
|---|---|---|
| 이름 | 표준 출력 | 표준 에러 |
| 용도 | 정상적인 결과 출력 | 에러·경고 메시지 |
| 리다이렉트(`java App > result.txt`) | 파일로 저장됨 | 화면에 그대로 출력됨 |

콘솔에서 눈으로 볼 땐 둘 다 같은 화면에 섞여 나와서 차이가 안 느껴지지만, "진짜 결과 데이터"와 "안내·디버깅 메시지"를 구분하고 싶을 때 스트림 레벨에서 나눠 쓸 수 있다.
