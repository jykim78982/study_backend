# 컬렉션·제네릭 API 메서드 체이닝 뜯어보기

`001`, `035` 노트에서 다룬 컬렉션 코드의 체이닝 호출들을, 한 단계씩 무엇을 반환하고 무엇을 하는지 뜯어서 정리한다.

## 1. 리스트에서 값을 꺼내자마자 그 값의 메서드 호출하기

```java
list.get(0).getKorName();
```

- **`list`**: `List<Menu>` 타입 변수. 내부적으로는 `Object[]`에 `Menu`의 참조들을 담고 있다(`001` 노트 7장).
- **`.get(0)`**: 인덱스 0번 칸에 저장된 참조를 꺼낸다. 내부에서는 `Object[]`에서 꺼낸 값을 제네릭이 정해둔 타입(`Menu`)으로 **자동 캐스팅**해서 돌려준다. 반환값은 **`Menu`** 객체 그 자체다.
- **`.getKorName()`**: 방금 꺼낸 그 `Menu` 객체에 바로 이어서 메서드를 호출한다. 중간에 `Menu menu = list.get(0);`처럼 변수에 담는 과정을 생략하고, **반환된 객체에 바로 점(`.`)을 찍어 이어 부르는 것**이 메서드 체이닝이다.

## 2. request에서 꺼낸 리스트를 형변환하고, 그 자리에서 바로 조회하기

```java
List<Menu> menus = (List<Menu>) request.getAttribute("menus");
...
menus.get(i).getId()
```

- **`request.getAttribute("menus")`**: `request` 저장소에서 `"menus"`라는 이름으로 저장된 값을 꺼낸다. 반환 타입은 `Object`다.
- **`(List<Menu>) ...`**: 그 안에 실제로 `List<Menu>`가 들어있다는 걸 알고 있으므로 형변환한다. 이 시점부터 `menus` 변수는 `.get()`, `.size()` 같은 `List`의 기능을 쓸 수 있게 된다.
- **`menus.get(i)`**: `i`번째 칸의 `Menu` 참조를 꺼낸다.
- **`.getId()`**: 꺼낸 `Menu` 객체에 바로 이어서 `id` 값을 요청한다. JSP의 반복문 안에서 `menus.get(i).getId()`, `menus.get(i).getKorName()`처럼 매번 같은 패턴이 반복되는 이유는, 한 번 꺼낸 객체를 변수에 담지 않고 그 자리에서 바로 필요한 값만 뽑아 쓰기 때문이다.

## 3. 직접 만든 제네릭 리스트(`GList<T>`)의 `add`/`get`

```java
public void add(T menu) {
    objs[size] = menu;
    size++;
}

public T get(int i) {
    return (T) objs[i];
}
```

- **`add(T menu)`**: 넘겨받은 `menu`(타입은 `T`로 표시되어 있지만, 실제로는 항상 참조형 하나)를 내부 배열 `objs`(`Object[]`)의 `size`번 칸에 그대로 저장하고, `size`를 하나 늘린다. 저장되는 순간 `T`라는 타입 정보는 사라지고 `Object`로만 취급된다(제네릭의 타입 소거).
- **`get(int i)`**: `objs[i]`에서 값을 꺼내는데, 꺼낸 값의 실제 타입은 `Object`이므로 **`(T)`로 캐스팅**해서 호출한 쪽이 기대하는 타입으로 돌려준다.
- `list.add(new Menu())`, `list.get(0).getKorName()`처럼 실제로 이 `add`/`get`을 호출하는 코드에서는 `T`가 `Menu`로 확정되어 있어서, 굳이 캐스팅을 눈으로 안 봐도 되지만 — 내부적으로는 항상 이 캐스팅이 숨어서 일어나고 있다는 걸 기억해두면 좋다.

## 4. 체이닝이 아닌 개별 선언·문장도 뜯어보기

```java
public class GList<T> {
    private Object[] objs = new Object[10];
    private int size = 0;
```

- **`public class GList<T>`**: 클래스 이름 옆의 `<T>`가 "이 클래스는 타입을 하나 나중에 받을 준비가 되어 있다"는 선언이다. 클래스를 정의하는 지금 시점에는 `T`가 무엇인지 전혀 모른다 — 실제로 `new GList<Menu>()`처럼 쓰는 쪽에서 정해준다.
- **`private Object[] objs = new Object[10];`**: 값을 저장할 내부 배열을 **`Object[]`로** 선언한다. `T[]`처럼 제네릭 타입으로 직접 배열을 만들 수는 없기 때문에(제네릭은 배열 생성과 잘 안 맞는다), 항상 `Object[]`로 만들어두고 꺼낼 때 캐스팅하는 방식을 쓴다. `new Object[10]`은 처음부터 칸 10개짜리 배열을 만든다는 뜻이다.
- **`private int size = 0;`**: 지금까지 실제로 채워 넣은 개수를 기억하는 변수. `objs.length`(배열의 전체 칸 수, 항상 10)와는 다른 값이라는 걸 구분해야 한다 — `size`는 "지금까지 몇 칸이 실제로 쓰였는가"를 센다.

```java
if (objs.length <= size) {
    // 배열을 큰걸로 바꿔주기
}
```

- **`objs.length`**: 배열이 처음에 만들어진 **전체 칸 수**(여기선 10). 배열은 한 번 만들면 크기를 바꿀 수 없다는 자바의 규칙 때문에, 늘리려면 새 배열을 만들어서 옮기는 수밖에 없다.
- **`<= size`**: "이미 다 채워졌거나 그 이상 채우려고 한다"는 조건이다. 이 조건이 참이 되는 순간 지금 배열로는 더 이상 못 담는다는 뜻이므로, 그 자리에서 더 큰 배열을 새로 만들고 기존 값을 복사해 옮기는 처리를 해야 한다(주석으로만 남겨둔 부분이 실제 `ArrayList`가 내부에서 하는 일이다).

```java
List<Integer> list = new ArrayList<>();
list.add(10);
int num = list.get(0);
```

- **`List<Integer>`**: 이 리스트는 `Integer`(정수의 래퍼 클래스)만 담기로 약속한다. `int` 기본형은 제네릭 타입 인자로 쓸 수 없어서(타입 소거 때문에 `Object`가 될 자격이 필요), 반드시 래퍼 클래스인 `Integer`로 선언한다.
- **`list.add(10)`**: 여기 적힌 `10`은 `int` 기본형이지만, `add(T menu)`가 참조형만 받을 수 있으므로 컴파일러가 자동으로 `Integer.valueOf(10)`으로 **오토박싱**해서 넣어준다.
- **`int num = list.get(0)`**: 반대로 꺼낼 때도, `get(0)`이 돌려주는 건 `Integer` 객체인데 왼쪽 변수 `num`은 `int`이므로 컴파일러가 자동으로 `.intValue()`를 호출하는 **오토언박싱**이 일어난다.
