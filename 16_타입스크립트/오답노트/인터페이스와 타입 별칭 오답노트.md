# 인터페이스와 타입 별칭 오답노트

### 1. 인터페이스(interface)가 type 별칭과 비교해 갖는 특징으로 옳은 것은?

**문제**: 인터페이스(interface)가 type 별칭과 비교해 갖는 특징으로 옳은 것은?

1. 인터페이스는 다른 인터페이스를 extends로 확장할 수 있다
2. 인터페이스는 값의 리터럴만 허용한다
3. 인터페이스는 함수의 반환 타입을 지정할 수 없다
4. 인터페이스는 객체 타입 정의에 전혀 사용되지 않는다

**정답: 1번**

- `interface`는 객체의 구조를 정의할 때 주로 사용되며, `extends` 키워드로 기존 인터페이스를 상속받아 확장하는 것이 자연스럽다. (타입 별칭 `type`은 `extends` 대신 교차 타입 `&`을 사용한다.)

```typescript
interface Animal {
  name: string;
}

interface Dog extends Animal {
  bark(): void; // name과 bark()를 모두 가짐
}
```

- 인터페이스는 같은 이름으로 여러 번 선언하면 자동으로 하나로 합쳐지는 선언 병합(Declaration Merging) 특징도 가지고 있어, 라이브러리 타입 확장 시 자주 쓰인다.

**2번이 오답인 이유**: 리터럴 타입(예: `type Direction = 'North' | 'South'`)이나 유니온 타입(`type Union = string | number`)은 오히려 `type` 별칭이 가지는 고유한 장점이다. 인터페이스는 이런 단일 리터럴 유니온을 직접 정의할 수 없다.

**3번이 오답인 이유**: 인터페이스 내부의 메서드나 함수 시그니처를 정의할 때 반환 타입을 당연히 지정할 수 있다. (예: `interface Calc { add(a: number): number; }`)

**4번이 오답인 이유**: 인터페이스의 가장 주요한 용도가 바로 객체(Object)의 형태·구조를 정의하는 것이다.

**한 줄 요약**: 인터페이스는 `extends`로 확장하기 쉬우며, 객체의 구조를 정의할 때 최적화되어 있다.
