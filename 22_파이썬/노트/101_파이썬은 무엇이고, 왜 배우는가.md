# 파이썬은 무엇이고, 왜 배우는가

파이썬을 함께 배워나갈 연재 노트의 첫 번째 글이다.

깃/깃허브나 리눅스, WSL을 조금이라도 써봤거나, 자바나 자바스크립트 같은 언어로 개발을 접해본 사람을 기준으로 작성했다.

하지만 내용을 읽어보고 어렵지 않게 느껴진다면 누구든 바로 시작해도 괜찮다.

---

## 이 노트의 목표

코드를 한 줄도 치기 전에, 지금 배우려는 것이 무엇이고 왜 배우는지를 분명히 한다. 이 단계가 끝나면

1. 파이썬이 어떤 언어이고 누가 왜 만들었는지 한 문단으로 말할 수 있고
2. 파이썬이 지금 어디에 쓰이는지, 반대로 어디에 안 쓰이는지 알며
3. "나는 이걸 왜 배우는가"에 자기 답을 한 줄 적을 수 있다.

---

## 0-1. 파이썬은 어떤 언어인가

파이썬은 **사람이 읽기 쉬운 것**을 가장 앞에 둔 프로그래밍 언어다. 아래는 "1부터 10까지 더해서 출력"하는 파이썬 코드다.

```python
total = 0
for n in range(1, 11):
    total = total + n
print(total)
```

아직 문법을 몰라도 대강 무슨 뜻인지 알 수 있을 것이다. "total 은 0에서 시작, n 을 1부터 10까지 돌면서, total 에 n 을 더하고, total 을 출력." 파이썬은 이런 언어다. 영어 문장에 가깝게 쓰고, 기호와 괄호가 적고, 줄 수가 짧다.

> [!tip] 🎓 newlec 쌤의 코멘트
> 다른 언어를 안다면: 같은 일을 Java 로 쓰면 클래스 선언과 `main` 메서드까지 7~8줄이 필요하다. 파이썬에는 세미콜론도, 중괄호도, 변수 타입 선언도 없다. 대신 **들여쓰기가 문법**이다. 2단계에서 바로 만난다.

## 0-2. 누가, 왜 만들었나

### 1989년 크리스마스 휴가

파이썬은 네덜란드의 프로그래머 **귀도 반 로섬(Guido van Rossum)** 이 1989년 12월, 연구소가 문을 닫은 크리스마스 휴가 동안 취미로 만들기 시작했다. 첫 공개 버전(0.9.0)은 1991년 2월에 나왔다.

### 왜 만들었나

귀도는 그 전에 암스테르담의 연구소 CWI 에서 **ABC** 라는 언어 프로젝트에 참여했다. ABC 는 "프로그래밍을 처음 배우는 사람을 위한 언어"로 설계되어 배우기는 쉬웠지만, 실제 일에 쓰기엔 부족했다. 파일을 다루거나 운영체제와 대화하는 일이 어려웠다.

반대편에는 **C** 가 있었다. 무엇이든 할 수 있지만, 배우기 어렵고 작은 실수로 프로그램이 죽었다.

귀도가 원한 것은 그 사이였다. ① ABC 처럼 읽기 쉽고, ② C 처럼 실제 일을 할 수 있는 언어. 그래서 파이썬은 처음부터 두 가지를 동시에 잡으려 했고, 그 균형이 지금까지 파이썬의 성격이다.

### 이름

파이썬(Python)은 '뱀'이라는 뜻이지만, 뱀에서 이름을 가져온 것이 아니다. 귀도가 평소에 즐겨 보던 영국의 유명 코미디 프로그램 **"몬티 파이썬의 날아다니는 서커스(Monty Python's Flying Circus)"**에서 이름을 따왔다. 프로그램 이름이 마음에 들어 가볍게 가져다 쓴 것이다.

그래서 파이썬 공식 문서나 예제 코드를 보면 뱀 이야기 대신 그 코미디 프로그램에 나오던 농담이나 단어(`spam`, `eggs` 등)가 자주 등장한다.

## 0-3. 설계 철학: 읽는 사람이 먼저

파이썬 안에는 만든 사람들이 중요하게 여긴 생각이 마치 시(詩)처럼 담겨 있다. 1단계에서 환경을 만든 뒤 `uv run python -c "import this"` 라는 명령어를 입력하면 20줄짜리 원칙이 나온다. 그중에서 프로그래밍을 하는 동안 계속 떠올리게 될 네 줄이다.

| 원문 | 뜻 |
|---|---|
| Beautiful is better than ugly. | 아름다운 것이 추한 것보다 낫다 |
| Explicit is better than implicit. | 드러내는 것이 숨기는 것보다 낫다 |
| Simple is better than complex. | 단순한 것이 복잡한 것보다 낫다 |
| Readability counts. | 읽기 쉬움은 중요하다 |

핵심은 마지막 줄이다. 코드는 쓰는 시간보다 **읽히는 시간**이 훨씬 길다. 내가 쓴 코드를 석 달 뒤의 내가 읽고, 동료가 읽고, 요즘은 AI 가 읽는다. 파이썬은 "읽는 사람"을 위해 설계된 언어이고, 그래서 첫 언어로도, 여러 사람이 함께 쓰는 언어로도 적합하다.

또 하나의 철학은 **"배터리 포함(batteries included)"**이다. 새 장난감을 샀을 때 상자 안에 건전지가 기본으로 들어 있어 바로 가지고 놀 수 있는 것과 같다. 파이썬도 프로그램을 설치하기만 하면 파일 읽기·쓰기, 날짜 계산, 데이터 변환(JSON), 문자열 찾기(정규식), 인터넷 연결, 코드 검사(테스트)처럼 자주 쓰이는 도구들이 이미 준비되어 있다. 별도로 다른 프로그램을 찾아 설치할 필요 없이 바로 가져다 쓸 수 있다. 이 과정의 29단계까지도 외부 추가 프로그램 없이 파이썬에 기본으로 들어 있는 도구만으로 진행한다.

## 0-4. 역사: 조용한 30년, 그리고 폭발

| 시기 | 사건 | 의미 |
|---|---|---|
| 1991 | 0.9.0 공개 | 시작 |
| 2000 | Python 2.0 | 널리 쓰이기 시작 |
| 2005 전후 | Django 등 웹 프레임워크 등장 | 웹 서버 언어로 자리 잡음 |
| 2008 | Python 3.0 | 2 와 호환되지 않는 대수술. 이후 10년간 2 와 3 이 공존 |
| 2010년대 중반 | NumPy·Pandas 성숙, TensorFlow(2015)·PyTorch(2016) 등장 | 데이터 과학과 AI 의 표준 언어가 됨 |
| 2020. 1. 1 | Python 2 지원 종료 | 이제 파이썬은 3 뿐 |
| 2022~ | ChatGPT 이후 생성형 AI 시대 | LLM 을 다루는 거의 모든 도구가 파이썬 우선 |
| 2023~2025 | 3.12, 3.13, 3.14 | 매년 10월 새 버전. 성능 개선이 계속됨 |

파이썬은 20년 가까이 "쓰기 편한 보조 언어" 정도였다. 그러다 데이터 과학과 AI 가 커지면서 중심으로 올라왔다. 이유는 단순하다. ① 수학자와 과학자가 쓰기 쉬운 언어였고, ② 그들이 만든 라이브러리가 쌓였고, ③ 그 라이브러리를 쓰려고 더 많은 사람이 파이썬으로 왔다.

> [!tip] 🎓 newlec 쌤의 코멘트
> 버전에 대해 지금 알아야 할 것은 두 가지다. 첫째, 인터넷에서 `print "hello"` 처럼 괄호 없는 코드를 보면 Python 2 다. **무시한다.** 둘째, 이 과정은 **3.12** 를 쓴다. 최신은 3.14 지만 이유는 1단계에서 설명한다.

## 0-5. 지금 어디에 쓰이나

| 분야 | 하는 일 (예) |
|---|---|
| 데이터 분석 | 표·통계, Pandas, Jupyter |
| AI / 머신러닝 | 모델 학습·추론, PyTorch, TensorFlow |
| 웹 서버·API | Django, FastAPI, Flask |
| 시각화 | 차트·대시보드, Matplotlib, Streamlit |
| 자동화·스크립트 | 파일 정리, 엑셀 합치기, 크롤링 |
| 과학·연구 | 수치 계산, 실험 코드 |
| DevOps·인프라 | 배포·점검 스크립트 |
| 교육 | 입문·학교 수업 |
| IoT·임베디드(여유 있는 장치) | 센서 수집, MicroPython |

이 표에서 눈여겨볼 점은 파이썬이 들어간 칸이 아주 많다는 것이다. 보통의 프로그래밍 언어는 한두 가지 분야에서만 주로 쓰인다. 반면 파이썬은 데이터를 분석하고, AI 모델을 돌리고, 웹 서버를 만들고, 시각화 그림을 그리는 것까지 거의 모든 분야에 다 쓰인다. 그래서 파이썬을 서로 다른 작업들을 하나로 연결해 주는 **"접착제 언어(glue language)"**라고도 부른다. 여러 종류의 일을 한 가지 언어로 싹 묶어서 처리할 수 있는 거의 유일한 언어이기 때문이다.

우리가 공부할 이 과정의 목차도 바로 이 표를 바탕으로 짜여 있다. 먼저 누구나 **공통 과정**을 통해 기초를 단단히 다진 뒤, 자신이 원하는 방향에 맞춰 **데이터(A), 웹 API(B), AI(C), IoT(D)**라는 세부 분야로 걸음을 넓혀가게 된다. 어떤 길을 선택하든 출발점은 언제나 같다.

## 0-6. 파이썬이 약한 곳

솔직하게 말해서 파이썬이 만능 언어는 아니다.

1. **실행 속도.** 같은 계산을 C 나 Rust 로 짜면 수십 배 빠를 수 있다. 다만 파이썬의 무거운 라이브러리(NumPy, PyTorch)는 속이 C 로 되어 있어서, 실무에서는 "파이썬으로 지휘하고 C 가 일한다"는 구조로 이 약점을 피한다.
2. **모바일 앱.** iOS·Android 앱은 파이썬으로 만들지 않는다.
3. **브라우저 안.** 웹 페이지 안에서 움직이는 코드는 JavaScript 의 영역이다. 파이썬은 서버 쪽이다.
4. **아주 작은 장치.** 메모리가 수십 KB 인 장치에는 C 를 쓴다. MicroPython 은 그보다 여유 있는 장치용이다.

이 네 가지가 목표라면 파이썬이 첫 언어가 아닐 수 있다. 그 외의 거의 모든 일에는 파이썬이 가장 짧은 길이다.

## 0-7. 왜 내가 이걸 배워야 하는가

여기가 이 단계의 본론이다. 네 가지 이유를 들고, 마지막에 자기 답을 적는다.

### 1. AI 시대의 공용어이기 때문에

지금 AI 를 만드는 쪽도, AI 를 쓰는 쪽도 파이썬이다. 모델을 학습시키는 코드, 데이터를 준비하는 코드, LLM API 를 호출하는 코드, 에이전트를 짜는 코드가 전부 파이썬이 기본이다. 새 AI 도구가 나오면 파이썬 예제가 가장 먼저 나오고, 다른 언어는 나중이거나 없다. AI 를 직업으로 삼지 않더라도, AI 를 도구로 제대로 쓰려면 파이썬이 읽혀야 한다.

### 2. 첫 언어로 가장 손실이 적기 때문에

프로그래밍에서 정말 배워야 할 것은 문법이 아니라 **생각하는 방법**이다. 문제를 쪼개고, 반복을 찾고, 데이터를 구조화하고, 오류를 추적하는 방법. 파이썬은 이 본질을 가리는 문법 소음이 가장 적다. 파이썬으로 배운 생각하는 방법은 나중에 어떤 언어로 가도 그대로 가져간다.

### 3. 내일 당장 쓸모가 있기 때문에

이 과정의 20단계쯤이면 엑셀 파일 수십 개를 합치거나, 폴더의 파일 이름을 규칙대로 바꾸거나, 매일 들어가는 사이트에서 숫자를 긁어 오는 일을 파이썬으로 할 수 있다. 배우는 도중에 이미 손이 편해지는 언어는 많지 않다.

### 4. 혼자가 아니기 때문에

막히면 검색하고, 검색하면 답이 있는 언어다. 라이브러리가 수십만 개이고, 질문과 답이 수십 년치 쌓여 있고, 요즘은 AI 도우미도 파이썬을 가장 잘 안다. 첫 언어를 배울 때 가장 큰 벽은 "막혔을 때 혼자"인 상황인데, 파이썬은 그 벽이 가장 낮다.

### 자기 이유

위 네 가지는 일반론이다. 각자의 이유는 다를 수 있고, 달라야 한다. 아래 한 줄을 채운다. 노트 앱이든 종이든 상관없다.

> 나는 파이썬으로 ______________________ 를 하고 싶다.

"회사 센서 데이터를 직접 분석하고 싶다", "매주 하는 보고서를 자동으로 만들고 싶다", "AI 챗봇이 어떻게 동작하는지 속을 보고 싶다", "취업하고 싶다". 무엇이든 된다. 이 한 줄이 35단계 동안 어려운 부분을 지나는 연료가 된다. 그리고 분기 과정에서 어느 길로 갈지 정할 때 이 줄을 다시 본다.

## 0-8. 이 과정은 어떻게 진행되나

### 구조

```
공통 과정 (기초·문법·파일·클래스 …)
        │
        ▼
   ┌────┼────┬────┐
   A    B    C    D
 데이터 웹API  AI  IoT
```

공통 과정은 어떤 목적이든 똑같이 배우는 파이썬이다. 분기부터 목적에 따라 갈라진다.

### 방식

- **코드 하나를 키운다.** 3단계에서 시작한 코드가 35단계까지 이어진다. 14단계부터는 "쇼핑 주문 데이터"를 소재로 삼아 클래스, 파일, 로깅 같은 것을 붙여 나간다.
- **단계마다 노트 하나, 브랜치 하나.** 노트는 지금 읽는 이 파일 같은 것이고, 브랜치는 그 단계가 끝난 시점의 코드다. 1단계에서 받는 법을 배운다.
- **매 단계 끝에 "확인 포인트"와 "일부러 망가뜨려 보기"가 있다.** 확인 포인트는 넘어가도 되는지 스스로 점검하는 목록이고, 망가뜨려 보기는 오류를 미리 겪어 두는 연습이다. 오류 메시지를 두려워하지 않게 되는 것이 이 과정의 숨은 목표 중 하나다.

### 생각해 보기

1. 0-1 의 네 줄짜리 코드를 다시 본다. `range(1, 11)` 이 왜 10 이 아니라 11 인지 추측해 본다. 7단계에서 답을 확인한다.
2. 0-5 의 분야 중 지금 가장 끌리는 칸 하나를 고른다. 그 칸이 분기 과정의 어디에 해당하는지 0-8 과 맞춰 본다.
3. 주변에서 "파이썬으로 만들었다"는 것을 하나 찾아본다. 인스타그램의 초기 서버, 유튜브의 일부, 넷플릭스 추천 시스템, ChatGPT 를 만든 연구 코드가 모두 파이썬이다.
