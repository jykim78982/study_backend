# 서버 컴포넌트와 클라이언트 컴포넌트 참고자료

React 18·Next.js 13(App Router)의 핵심 패러다임인 서버 컴포넌트가 왜 등장했고, 클라이언트 컴포넌트와 어떻게 역할을 나누는지 정리한 참고자료.

## 1. 등장 배경

전통적인 클라이언트 렌더링(CSR) 방식의 React는 다음 순서로 동작한다.

1. 서버가 거의 비어 있는 HTML과 큰 자바스크립트 번들을 브라우저로 보낸다.
2. 브라우저가 그 자바스크립트를 내려받아 실행하며 화면(DOM)을 그린다.
3. 필요하면 API를 다시 호출해 데이터를 가져온다.

이 방식은 사용자 기기 성능에 렌더링 속도가 좌우되고, 번들 용량이 커질수록 초기 로딩이 느려지며, "렌더링 → 데이터 요청 → 재렌더링"이 순차적으로 이어지는 워터폴(Waterfall) 지연이 생긴다. 서버 컴포넌트는 **서버가 잘하는 일(DB 접근, 데이터 가공, HTML 생성)을 서버에서 끝내고, 그 결과만 브라우저로 보내자**는 아이디어에서 나왔다.

## 2. 서버 컴포넌트의 특징

### 2-1. 자바스크립트 번들 용량 0

서버 컴포넌트를 작성할 때 쓴 라이브러리나 코드는 브라우저로 전송되는 JS 번들에 포함되지 않는다. 서버에서 실행을 마치고 최종 결과(HTML/데이터)만 넘겨주기 때문이다.

### 2-2. 백엔드 자원에 직접 접근

API 계층을 거치지 않고 컴포넌트 안에서 바로 DB 조회, 파일 시스템 접근, 비밀 키 사용 등을 할 수 있다.

```jsx
// Next.js App Router 예시
import db from '@/lib/db';

export default async function Page() {
  const users = await db.user.findMany();

  return (
    <ul>
      {users.map(u => <li key={u.id}>{u.name}</li>)}
    </ul>
  );
}
```

### 2-3. 보안성

API 토큰, DB 접속 정보 같은 민감한 값이 브라우저로 나갈 일이 없다 — 애초에 그 코드가 브라우저로 전송되지 않기 때문이다.

### 2-4. 초기 로딩·SEO

서버가 완성된 HTML을 내려주므로 검색 엔진이 내용을 바로 읽을 수 있고(SEO), 첫 화면이 뜨는 속도도 빠르다.

## 3. 서버 컴포넌트 vs 클라이언트 컴포넌트

| 구분 | 서버 컴포넌트 | 클라이언트 컴포넌트 |
|---|---|---|
| 실행 위치 | 서버에서만 실행 | 서버에서 SSR 후 브라우저에서 하이드레이션 |
| 선언 방법 | Next.js App Router의 기본값 | 파일 맨 위에 `'use client'` 필요 |
| 상태 관리 | `useState`/`useReducer` 사용 불가 | 사용 가능 |
| 생명주기 Hook | `useEffect`/`useLayoutEffect` 사용 불가 | 사용 가능 |
| 사용자 이벤트 | `onClick`/`onChange` 등 사용 불가 | 사용 가능 |
| 브라우저 API | `window`/`document`/`localStorage` 접근 불가 | 접근 가능 |

서버 컴포넌트가 상태·이벤트·브라우저 API를 못 쓰는 이유는 단순하다 — 애초에 서버에서만 실행되고 끝나는 코드라서, 사용자와 상호작용할 브라우저 쪽 실행 시점 자체가 없다.

## 4. 함께 쓰는 구조

서버 컴포넌트가 모든 걸 대체하지는 않는다. 인터랙션(클릭, 입력, 상태 변화)이 필요한 부분만 클라이언트 컴포넌트로 잘게 쪼개 결합하는 것이 기본 구조다.

```
[ 전체 페이지 (Server Component) ] — DB 조회, 레이아웃 구성
  ├── [ 게시글 본문 (Server Component) ] — 데이터 렌더링
  └── [ 좋아요 버튼 (Client Component) ] — 'use client', onClick·useState
```

## 5. 정리

서버 컴포넌트는 상호작용이 없는 UI(데이터 조회·출력)를 서버에서 미리 처리해 브라우저로 보낼 자바스크립트 양을 줄이는 기술이고, 클릭·입력처럼 상태와 이벤트가 필요한 부분만 `'use client'`로 선언한 클라이언트 컴포넌트로 남겨 두 종류를 함께 쓰는 것이 Next.js App Router의 기본 설계다.
