# 스프링 시큐리티 세션 고정 방지 오답노트

### 1. 세션 고정 공격 방지의 기본 전략

**문제**: Spring Security의 세션 고정 공격(Session Fixation) 방지 전략 중, 로그인 성공 시 기존 세션의 속성을 복사하면서 새로운 세션 ID를 생성하는 기본(Default) 정책은 무엇인가?

1. `none`
2. `newSession`
3. `changeSessionId`
4. `migrateSession`

**정답: 3번**

**세션 고정 공격**

```
1. 공격자가 사이트에 접속해 세션 ID(abc)를 받는다
2. 이 ID를 피해자 브라우저에 심는다 (링크의 ;jsessionid=abc, 쿠키 주입 등)
3. 피해자가 그 세션(abc)으로 로그인한다 → 세션 abc가 "로그인된 세션"이 된다
4. 공격자도 abc를 알고 있으므로, 피해자로 로그인된 상태가 된다
```

막는 방법은 간단하다. **로그인에 성공하는 순간 세션 ID를 바꾼다.** 공격자가 아는 ID(abc)는 로그인 전의 ID일 뿐, 로그인 후에는 쓸모가 없어진다.

**네 가지 전략**

| 전략 | 세션 객체 | 세션 ID | 기존 속성 | 비고 |
|---|---|---|---|---|
| `changeSessionId` | **그대로** | 새 ID | 그대로 유지 | **기본값**(서블릿 3.1+). `request.changeSessionId()` 사용 |
| `migrateSession` | **새로 만든다** | 새 ID | 새 세션에 **복사** | 서블릿 3.0 이하의 기본값이었다 |
| `newSession` | 새로 만든다 | 새 ID | 복사하지 않는다(스프링 시큐리티 관련 속성만 남김) | 깨끗한 세션이 필요할 때 |
| `none` | 그대로 | **그대로** | 그대로 | 방어하지 않음. 쓰지 않는다 |

```java
http.sessionManagement(session -> session
        .sessionFixation(fixation -> fixation.changeSessionId()));   // 기본값이라 생략해도 같다
```

> 원문 바로잡기 — 문제는 "기존 세션의 속성을 **복사**하면서 새로운 세션 ID를 생성"이라고 했지만, 이 표현은 엄밀히는 `migrateSession`의 설명에 가깝다. `changeSessionId`는 세션을 새로 만들어 속성을 옮기는 게 아니라 **같은 세션 객체를 그대로 두고 ID만 바꾸므로** 복사가 일어나지 않는다. 두 전략 모두 결과적으로 "속성은 유지되고 ID는 바뀐다"는 점이 같아서 헷갈리기 쉽다. 문제의 핵심 단서는 "**기본(Default)** 정책"이고, 지금 환경(서블릿 3.1 이상, 스프링 부트 3)의 기본은 `changeSessionId`다.

**왜 기본값이 바뀌었나**: `migrateSession`은 세션을 하나 더 만들고 속성을 하나하나 옮기는 비용이 든다. 서블릿 3.1에 ID만 바꾸는 `changeSessionId()`가 생기면서, 더 가볍고 결과는 같은 이 방식이 기본이 되었다.

**정리**: 세션 고정 공격은 공격자가 미리 아는 세션 ID로 피해자를 로그인시키는 공격이고, 로그인 성공 시 ID를 바꿔 막는다. 기본 전략은 **`changeSessionId`**(같은 세션, ID만 교체)이고, `migrateSession`은 새 세션을 만들어 속성을 복사하는 예전 기본값이다.
