# CSS 결합자·우선순위 테스트

`publishing/css/step1/ex3-comb-test.html` 실습. 10단계에 걸쳐 두 규칙 중 어느 색이 최종 적용될지 조원끼리 먼저 예측한 뒤, 주석을 하나씩 해제해가며 실제 결과를 확인하는 방식으로 진행했다. 실습 파일에는 모든 규칙이 처음부터 주석 처리되어 있고 답은 적혀 있지 않다.

## 실습 환경

```html
<div id="container" class="box-wrapper">
  <section class="card active" data-type="main">
    <h2 class="title">타이틀 영역</h2>
    <p id="target" class="desc highlight" data-status="read">
      이 글자의 색상은 무엇으로 바뀔까요?
    </p>
  </section>
</div>
```

목표 요소인 `<p id="target" class="desc highlight" data-status="read">`는 아이디(`target`)·클래스 2개(`desc`, `highlight`)·속성(`data-status="read"`)을 동시에 갖고 있어서, 이 요소 하나로 온갖 조합의 명시도를 비교할 수 있다.

## 1단계: 단일 태그 vs 태그 자손 결합자

```css
p { color: red; }
div p { color: blue; }
```

- **목표**: 결합자로 태그가 늘어나면 명시도가 얼마나 올라가는지 확인.
- **풀이**: `p`는 태그 1개(명시도 1), `div p`는 태그 2개(명시도 2)다. 태그끼리 비교이므로 개수가 많은 쪽이 이긴다. `div p`가 이겨서 **파란색**이 된다.

## 2단계: 자손 결합자 vs 자식 결합자

```css
section > p { color: green; }
section p { color: orange; }
```

- **목표**: 결합자의 기호(`>` vs 공백)가 명시도에 영향을 주는지 확인.
- **풀이**: 결합자 기호 자체는 명시도 점수에 들어가지 않는다. `section > p`와 `section p` 둘 다 태그 2개(명시도 2)로 동일하다. 명시도가 같으므로 **나중에 선언된 규칙**이 이긴다 — `section p`(orange)가 뒤에 있으므로 **주황색**이 된다.

## 3단계: 긴 태그 결합 체인 vs 단일 클래스

```css
html body div section p { color: purple; }
.desc { color: brown; }
```

- **목표**: 태그 선택자를 아무리 길게 이어붙여도 클래스 1개를 이길 수 없다는 걸 확인.
- **풀이**: `html body div section p`는 태그 5개(명시도 5)지만, 태그는 클래스보다 한 등급 낮은 단위라 아무리 많아도 클래스 1개(명시도 10)를 넘지 못한다. `.desc`가 이겨서 **갈색**이 된다.

## 4단계: 클래스+태그 결합자 vs 다중 클래스

```css
.card p { color: teal; }
.desc.highlight { color: crimson; }
```

- **목표**: "부모 클래스 + 자식 태그" 조합과 "한 요소의 클래스 2개" 조합을 비교.
- **풀이**: `.card p`는 클래스 1개+태그 1개(명시도 11). `.desc.highlight`는 클래스 2개(명시도 20). 클래스 개수가 더 많은 `.desc.highlight`가 이겨서 **진홍색(crimson)**이 된다.

## 5단계: 인접 형제 결합자의 점수 및 매칭

```css
.card .highlight { color: navy; }
h2.title + p { color: coral; }
```

- **목표**: 결합자가 늘어난다고 해서 무조건 명시도가 더 높아지는 건 아니라는 걸 확인.
- **풀이**: `.card .highlight`는 클래스 2개(명시도 20). `h2.title + p`는 태그 2개(`h2`, `p`)+클래스 1개(`.title`)로 계산하면 명시도 12에 불과하다. 선택자 개수(3개 vs 3개)는 같아 보여도, 실제로 점수를 결정하는 건 **어떤 등급의 선택자가 몇 개인지**다 — 클래스가 2개인 `.card .highlight`가 클래스 1개인 `h2.title + p`보다 높아서 **남색(navy)**이 이긴다. "선택자가 더 길어 보이니까 더 셀 것"이라는 직관이 틀릴 수 있다는 걸 보여주는 단계다.

## 6단계: 속성 선택자와 결합자

```css
.card > p[data-status="read"] { color: darkgreen; }
.card > .desc.highlight { color: slateblue; }
```

- **목표**: 속성 선택자(`[attr=value]`)의 명시도 가중치가 클래스와 동일(10점)하다는 것을 확인.
- **풀이**: `.card > p[data-status="read"]`는 클래스 1개+태그 1개+속성 1개(명시도 21). `.card > .desc.highlight`는 클래스 3개(명시도 30). 클래스 3개 쪽이 더 높아서 **슬레이트블루(slateblue)**가 된다.

## 7단계: 클래스 체인 vs 단일 아이디

```css
.box-wrapper .card.active .desc.highlight[data-status="read"] { color: gray; }
#target { color: darkred; }
```

- **목표**: 클래스·속성을 아무리 많이 엮어도 아이디 1개를 이길 수 없다는 것을 확인.
- **풀이**: 위쪽 규칙은 클래스 5개+속성 1개(명시도 60)로 매우 높지만, 아이디는 클래스보다 한 등급 위라서 `#target`(명시도 100) 하나가 그대로 이긴다. **어두운 빨강(darkred)**이 된다.

## 8단계: 아이디 단일 지정 vs 부모 아이디+자식 결합자

```css
#target { color: magenta; }
#container > section > p { color: darkblue; }
```

- **목표**: 아이디가 이미 있을 때, 추가 결합자·태그가 그 판도를 뒤집을 수 있는지 확인.
- **풀이**: `#target`은 아이디 1개(명시도 100). `#container > section > p`는 아이디 1개+태그 2개(명시도 102)로 태그가 추가돼 있다. 아이디 개수가 같으면(1=1) 승부가 나지 않으므로 그다음 등급인 태그 개수(0 vs 2)로 넘어가서 비교하고, 여기서 **어두운 파랑(darkblue)**이 이긴다.

## 9단계: 아이디+클래스 결합 체인 종합 비교

```css
#container .card > p#target { color: gold; }
#container section.card.active p.desc.highlight { color: darkviolet; }
```

- **목표**: 아이디·클래스·태그가 뒤섞였을 때 종합 점수를 직접 계산해보기.
- **풀이**: `#container .card > p#target`은 아이디 2개(`#container`, `#target`)+클래스 1개+태그 1개(명시도 211). `#container section.card.active p.desc.highlight`는 아이디 1개+클래스 4개+태그 2개(명시도 142). 아이디 개수에서 이미 승부가 갈려 **금색(gold)**이 이긴다.

## 10단계: "완전 동점처럼 보이는" 상황 직접 검증하기

```css
div#container .card p#target.desc { color: black; }
#container > .card.active > p#target { color: limegreen; }
```

- **목표**: 겉보기 복잡도가 비슷해도 실제로 세어보지 않으면 동점인지 아닌지 알 수 없다는 걸 확인.
- **풀이**: 얼핏 보면 둘 다 "아이디+클래스+태그가 섞인 비슷한 길이의 선택자"라 동점처럼 보이지만, 실제로 하나씩 세어보면 그렇지 않다.
  - `div#container .card p#target.desc` → 아이디 2개(`#container`, `#target`) + 클래스 2개(`.card`, `.desc`) + 태그 2개(`div`, `p`)
  - `#container > .card.active > p#target` → 아이디 2개(`#container`, `#target`) + 클래스 2개(`.card`, `.active`) + 태그 1개(`p`)
  - 아이디 개수(2=2)와 클래스 개수(2=2)는 정확히 같지만, **태그 개수에서 2 대 1로 차이가 난다.** 아이디·클래스가 동점이면 그다음은 태그 개수로 승부가 갈리므로, 태그가 더 많은 `div#container .card p#target.desc`(**검정, black**)이 이긴다.
  - 이 단계의 진짜 포인트는 "동점이면 나중 선언이 이긴다"가 아니라, **셀렉터 개수를 정확히 세어보기 전까지는 동점인지 판단할 수 없다**는 것이다. 헷갈릴 때는 눈대중이 아니라 브라우저 개발자 도구의 Styles 패널에서 취소선으로 직접 확인하는 게 가장 정확하다.

## 10단계를 관통하는 핵심 패턴

- 결합자 **기호 자체**(`>`, `+`, `~`, 공백)는 명시도 점수에 아무 영향을 주지 않는다. 점수에 반영되는 건 오직 그 결합자로 엮인 **선택자의 종류와 개수**(아이디·클래스/속성/슈도클래스·태그)뿐이다.
- 태그를 아무리 많이 엮어도 클래스 1개를 이기지 못하고, 클래스를 아무리 많이 엮어도 아이디 1개를 이기지 못한다 — 등급(아이디 > 클래스류 > 태그) 자체가 개수보다 우선한다.
- 등급이 같은 선에서 붙었을 때만 개수 싸움이 의미가 있다 — 상위 등급(아이디)부터 순서대로 개수를 비교하고, 거기서도 같으면 그다음 등급(클래스류), 또 같으면 그다음 등급(태그) 순으로 내려가며 비교한다. 모든 등급의 개수가 진짜로 완전히 같을 때만 비로소 **코드에서 더 나중에 선언된 규칙**이 최종 결정권을 갖는다.
