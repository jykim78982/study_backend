# CSS 콤비네이터·우선순위 심화, 슈도 클래스·엘리먼트, 함수

## 1. 문서 구조 비유 — 아이디는 어디에 부여해야 하는가

문서 구조를 단순화하면 **레이아웃(방) < 섹션(가구 — id 부여) < 콘텐츠(수납할 물건)**의 3단 구조로 볼 수 있다. 방(레이아웃) 안에 가구(섹션)를 배치하고, 그 가구 안에 물건(콘텐츠)을 수납하는 것과 같다.

- 아이디는 "이 집의 문패"처럼 예외적으로 부여하는 것이지, 남발할 대상이 아니다. 콘텐츠 하나하나(`a`, `span` 같은 개별 요소)에 전부 아이디를 붙여서 지목하는 방식은 반복적인 스타일링을 지옥으로 만든다.
- 반면 **섹션(가구)은 아이디를 부여해도 되는 영역**이다. 섹션은 콘텐츠를 담고 제목을 갖는 단위이기 때문에, 문서 안에서 "이 구역이 무엇인지" 고유하게 식별할 이유가 있다 — 예를 들어 `#quick-menu`처럼 문서 상단에서 특정 영역으로 바로 이동하는 바로가기 용도로 쓰인다.

## 2. 콤비네이터가 필요한 이유

그렇다면 섹션 안에 있는 개별 콘텐츠(`a` 등)는 어떻게 타겟팅할까? 여기서 콤비네이터가 필요해진다. 섹션에 부여한 아이디를 기준으로 삼아 그 내부 요소를 결합해서 찾으면, 콘텐츠 하나하나에 아이디를 남발하지 않고도 원하는 대상만 골라낼 수 있다.

```css
#quick-menu a { color: blue; }
```

- 이렇게만 하면 `#quick-menu` 섹션 안의 `a`는 모두 걸리지만, 그중에서도 특정 클래스를 가진 것만 다르게 스타일링하고 싶다면 클래스 선택자까지 이어붙여서 범위를 한 번 더 좁히면 된다.

```css
#quick-menu .nav1 { color: red; }
```

- 문서 안에 `h1`이 여러 개 있을 때도 마찬가지다. `h1` 태그 선택자 하나만 쓰면 문서의 모든 `h1`이 다 걸려버려서 원하는 것만 고를 수 없다. 이럴 때 상위 섹션 요소를 앞에 붙여서 범위를 좁히는 것이 콤비네이터의 역할이다. 아이디를 예외적인 곳(섹션)에만 부여하고, 나머지는 콤비네이터로 좁혀서 찾는 것 — 이 조합이 "아이디 남발 없이 원하는 것만 정확히 선택하는" 실무 방식이다.

## 3. 콤비네이터(결합자)의 종류

| 결합자 | 문법 | 의미 |
|---|---|---|
| 자손 결합자 | `A B` | A 내부에 있는 모든 B (자식·손자·증손 등 깊이 상관없이) |
| 자식 결합자 | `A > B` | A의 바로 아래 자식인 B만 |
| 인접 형제 결합자 | `A + B` | A 바로 다음(형 바로 밑 동생)에 오는 B |
| 일반 형제 결합자 | `A ~ B` | A보다 뒤에 오는 형제 중 B에 해당하는 모든 것 |

```css
h3.h3 { color: green; }
section > .h3 { color: orange; }
section .h3 { color: blue; }
section > h3 { color: blueviolet; }
.h3 { color: red; }
```

- 자손 결합자(`section .h3`)는 `section` 안이라면 몇 단계를 거쳐 들어가 있든 전부 걸린다. 반대로 자식 결합자(`section > .h3`)는 `section`의 **바로 한 단계 아래**에 있는 것만 걸리므로, `section` 안에 또 `section`이 중첩되어 있으면 손자뻘 요소는 대상에서 빠진다.
- 인접 형제 결합자(`+`)는 "바로 다음 형제 하나"만 가리킨다. 예를 들어 `a.first + span`은 `a.first` 바로 뒤에 오는 형제가 `span`일 때만 걸리고, 그 사이에 다른 태그가 끼어 있거나 두 칸 이상 떨어져 있으면 걸리지 않는다.
- 일반 형제 결합자(`~`)는 "그 뒤에 오는 형제들 중에서"라는 뜻이라 범위가 더 넓다 — 바로 다음이 아니어도, `a.first`보다 뒤에 있는 형제 중 조건에 맞는 요소를 모두 찾아낸다.

## 4. 콤비네이터와 우선순위 — 범위가 좁을수록 강하다

콤비네이터로 범위를 좁힌 선택자는 단일 선택자보다 우선순위(명시도)가 높다. [[046_CSS 기초 — 캐스케이딩, 선택자, 우선순위]]에서 다룬 "아이디 > 클래스 > 태그 > 유니버설" 규칙에 더해, **콤비네이터가 들어가서 대상 범위가 좁아질수록 그만큼 우선순위가 높아진다**는 규칙이 하나 더 붙는다.

```css
h1[lang="ko"] { color: blue; }
.h1 { color: red; }
```

```html
<h1 class="h1" lang="ko">우리카페</h1>
```

- 얼핏 보면 클래스 선택자(`.h1`)가 태그+속성 선택자(`h1[lang="ko"]`)보다 우선순위 규칙상 앞서는 것처럼 헷갈릴 수 있지만, 실제로는 `h1[lang="ko"]` 쪽이 이긴다. 태그 선택자에 속성 선택자가 결합되면서 범위가 더 한정적으로 좁아졌기 때문이다.
- 판단이 애매할 때는 "범위가 넓을수록 약하고, 범위가 좁을수록(더 구체적일수록) 강하다"는 기준으로 접근하면 된다. 단일 선택자만 셀 게 아니라, 결합으로 인해 대상이 얼마나 한정됐는지까지 같이 봐야 정확한 우선순위를 판단할 수 있다.

## 5. 슈도 클래스(Pseudo-class) — 존재하지 않는 "상태"에 스타일 주기

**Pseudo**는 "가짜의, 모조의, 허위의, 유사한(겉으로만 비슷한)"이라는 뜻의 접두사다. 그리스어 *pseudēs*(거짓의, 속이는)에서 유래했으며, "진짜는 아니지만 겉보기에는 비슷하게 모방한 것"을 뜻한다.

클래스는 원래 개발자가 이름을 지어 요소에 직접 부여하는 것이다. 하지만 **내가 이름 붙이지 않았는데도 콜론(`:`) 하나를 붙여서 마치 클래스처럼 쓸 수 있는 것**이 있다 — 슈도(가짜) 클래스다. "가짜"라고 부르는 이유는, 실제로 존재하는 요소(element)에 이름을 붙이는 게 아니라 **그 요소가 처한 상태**에 이름을 붙이는 것이기 때문이다. 이 상태값들은 개발자가 정하는 게 아니라 W3C·WHATWG 같은 표준 단체가 미리 정의해 둔 것이다.

```css
a:active { color: chocolate; }
input:focus { background-color: yellow; }
```

- **링크(`a`)의 상태**: 기본이 되는 노멀 상태 외에도 마우스를 올린 **호버(`:hover`)**, 클릭하고 있는 **액티브(`:active`)**, 이미 방문한 **비지티드(`:visited`)** 등 여러 상태를 가진다.
- **입력창(`input`)의 상태**: 포커스를 얻었는지 여부(`:focus`)가 핵심 상태다. 예를 들어 `input:focus`로 배경색을 지정하면, 평소에는 그 색이 보이지 않다가 사용자가 `Tab` 키나 클릭으로 그 입력창에 포커스를 옮기는 순간에만 배경색이 나타난다. 전체를 통으로 스타일링하는 것과 달리, **상태 단위로 선택적으로 스타일을 줄 수 있다는 것**이 슈도 클래스의 핵심이다.
- **트리 구조상의 위치(`:first-child`/`:last-child`)**: `li:first-child`는 형제 목록 중 첫 번째 `li`, `li:last-child`는 마지막 `li`를 가리킨다. 목록(`ol`/`ul`)의 첫 항목이나 막내 항목만 다르게 꾸미고 싶을 때 클래스를 따로 붙이지 않고도 처리할 수 있다.

## 6. 슈도 엘리먼트(Pseudo-element) — 존재하지 않는 "요소"에 스타일 주기

슈도 클래스가 존재하는 요소의 **상태**에 이름을 붙이는 것이었다면, 슈도 엘리먼트는 한 단계 더 나아가 **문서에 실제로 존재하지 않는 요소 자체**를 만들어서 스타일을 주는 것이다. 그래서 콜론을 두 개(`::`) 붙여서 구분한다.

```css
ol::before {
  content: "hello";
  display: list-item;
}
```

- `content` 속성으로 실제 내용을 지정해야 화면에 나타난다. `::before`를 쓰면 대상 요소의 맨 앞에, `::after`를 쓰면 맨 뒤에 가상의 요소가 하나 추가된다.
- 이 기능이 필요한 이유는 **데코레이션(꾸밈)과 콘텐츠(내용)를 구분**하기 위해서다. 화살표 아이콘, 메뉴 앞에 붙는 `+` 기호처럼 "있으면 예쁘지만 문서의 의미상 반드시 HTML 태그로 들어갈 필요는 없는" 요소들은, HTML에 직접 넣는 대신 CSS의 슈도 엘리먼트로 만드는 것이 원칙에 맞다.
- 반면 어떤 이미지가 콘텐츠인지 데코레이션인지는 항상 명확하게 갈리지는 않는다. 뉴스 기사의 사고 현장 사진처럼 내용을 설명하는 이미지는 명백한 콘텐츠이지만, 로고처럼 "브랜드를 전달하는 의미가 있다"와 "그냥 꾸며주는 것이다"라는 관점이 갈리는 경계 사례도 있다. 메뉴판의 상품 사진(예: 카페라떼 이미지)처럼 상품 정보 자체를 담고 있는 이미지는 콘텐츠로 보는 쪽이 합리적이다 — 이런 판단 기준을 갖고 있어야 "이걸 HTML에 넣을지, CSS 슈도 엘리먼트로 꾸밀지"를 결정할 수 있다.

**많이 쓰이는 슈도 엘리먼트**

| 슈도 엘리먼트 | 용도 |
|---|---|
| `::before` / `::after` | 요소 앞·뒤에 가상 콘텐츠 삽입(장식 아이콘, 구분자 등) — 가장 많이 쓰인다 |
| `::first-letter` | 문단의 첫 글자만 스타일링(신문 기사 같은 큰 첫 글자 효과) |
| `::first-line` | 문단의 첫 줄만 스타일링 |
| `::placeholder` | `input`/`textarea`의 플레이스홀더 텍스트 스타일링 |
| `::selection` | 사용자가 드래그로 선택한 텍스트의 스타일(배경색 등) |
| `::marker` | 리스트(`li`)의 불릿·숫자 마커 스타일링 |

## 7. CSS 함수(Functional Notation)와 커스텀 프로퍼티

CSS는 값 계산이나 재사용을 위한 함수 문법도 제공한다.

```css
h1 {
  --x: 10%;

  background-color: greenyellow;
  width: calc(50% + var(--x));
}
```

- `--x: 10%;`처럼 두 개의 하이픈으로 시작하는 이름은 **커스텀 프로퍼티(변수)**다. 값을 저장해두고 다른 속성에서 재사용할 수 있다.
- 저장한 변수를 꺼내 쓰려면 `var()` 함수가 필요하다 — `--x`에 담긴 값을 다른 속성 값 안에 그대로 쓰려면 `var(--x)`처럼 감싸야 한다.
- `calc()`는 서로 다른 단위(`%`, `px` 등)를 섞어서 연산할 수 있게 해주는 함수다. `calc(50% + var(--x))`처럼 퍼센트 값에 변수를 더하는 식의 계산이 가능해진다.
- 이 외에도 CSS는 용도별로 다양한 함수 카테고리를 제공한다 — 이동·회전·크기 변환을 위한 **Transform functions**, 반올림·절댓값 등 **Math functions**, 흐림·명암 등 **Filter functions**, 색상을 다루는 **Color functions**, 배경·아이콘 이미지를 다루는 **Image functions**, 숫자를 세는 **Counter functions**, 폰트를 다루는 **Font functions**, 도형을 정의하는 **Shape functions**. `calc()`와 `var()`는 그중 극히 일부일 뿐이며, 나머지는 각 주제(트랜스폼 등)를 다룰 때 함께 등장한다.
