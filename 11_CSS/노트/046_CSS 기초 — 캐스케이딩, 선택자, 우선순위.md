# CSS 기초 — 캐스케이딩, 선택자, 우선순위

## 1. CSS란 무엇인가 — Cascading의 의미

- CSS는 **Cascading Style Sheets**의 약자다. "스타일을 시트에 적어놓은 것"이라는 뒷부분(Style Sheets)은 직관적이지만, 앞의 **Cascading(캐스케이딩)**이 CSS의 동작 방식을 이해하는 핵심 개념이다.
- 캐스케이딩은 "계단식으로 흐른다"는 뜻이다. CSS로 스타일을 적용한다는 건 **기존 스타일을 지우고 새로 채우는 게 아니라, 기존 스타일 위에 내가 바꾸고 싶은 부분만 얹어서 오버라이드(덮어쓰기)하는 것**이다.
- 예를 들어 `h1`은 브라우저가 이미 기본 스타일(글자 크기, 두께 등)을 갖고 있다. 여기에 `color`만 지정하면, 색만 덮어써지고 나머지 기본 스타일(크기·두께)은 그대로 유지된다. 이렇게 스타일을 계단식으로 하나씩 얹어가는 방식이 캐스케이딩이다.

## 2. 스타일 적용 방법 — 인라인 대신 선택자를 쓰는 이유

가장 직관적인 방법은 태그 안에 `style` 속성으로 직접 스타일을 적는 **인라인 스타일**이다.

```html
<h1 style="color: pink;">우리카페</h1>
```

- 인라인 스타일은 입문 단계에서는 쓸 수 있지만, 실무에서는 **거의 쓰지 않는다.** 이유는 반복 문제 때문이다 — 문서 안에 같은 스타일을 공유해야 하는 요소(예: 부제목 `h2` 여러 개)가 있을 때, 인라인 스타일로는 요소마다 똑같은 `style`을 반복해서 붙여넣어야 한다. 나중에 스타일을 하나 바꾸고 싶으면 그 반복된 곳을 전부 찾아 고쳐야 한다.
- 그래서 실무에서는 **선택자(selector)**를 이용해 "이 스타일을 적용할 대상"을 지정하고, 그 스타일 정의를 한 곳(`<style>` 블록이나 별도 CSS 파일)에 모아둔다. 대상을 한 번만 정의해두면, 그 대상에 해당하는 모든 요소에 스타일이 한꺼번에 적용된다.

```html
<style>
  h2 {
    color: blue;
    font-weight: bold;
  }
</style>
```

## 3. 스타일 속성의 종류 — 크게 네 갈래로 묶어보기

CSS 속성은 얼핏 보면 수백 개로 끝없이 나열되어 있어 압도적으로 느껴지지만, 실제로는 **하나의 스타일 종류가 여러 세부 속성으로 나뉘어 나열되기 때문에 많아 보이는 것**이다. 예를 들어 "배경"이라는 스타일 하나가 `background-color`, `background-image` 등으로 세분화된다.

크게 묶으면 아래 네 갈래로 정리할 수 있다.

- **텍스트**: `font`, `color`, `size`, `content`, `text-*`, `filter`, `mask`, `cursor`
- **박스**: `border`, `background`, `overflow`, `margin`, `padding`, `shape`
- **레이아웃**: `flexbox`, `float`, `grid`, `positioning`, `place-*`, `column`
- **효과**: `animation`, `transform`, 그리고 `contrast()`, `min()`/`max()`, `counters()`, `matrix()`, `image-set()`, `url()` 같은 CSS 함수들

실무에서 이 네 갈래(텍스트·박스·레이아웃·효과)만 큰 틀로 잡아두면, 세부 속성을 하나하나 외우지 않아도 "이건 어느 갈래에 속하는 스타일이구나"라는 감으로 접근할 수 있다.

## 4. 선택자의 종류

| 선택자 | 문법 | 대상 |
|---|---|---|
| 태그 선택자 | `h2 { ... }` | 문서 안의 모든 `h2` 태그 |
| 클래스 선택자 | `.nav-1 { ... }` | `class="nav-1"`을 가진 모든 요소 |
| 아이디 선택자 | `#footer { ... }` | `id="footer"`를 가진 요소(문서에 하나뿐이어야 함) |
| 유니버설 선택자 | `* { ... }` | 문서 안의 모든 요소 |

```html
<style>
  h1 { color: pink; }
  * { color: aqua; }
</style>
```

- 유니버설 선택자(`*`)로 전체 색을 바꿔도, `h1`처럼 더 구체적인 선택자가 따로 있으면 그 요소는 유니버설 선택자를 따르지 않고 **더 구체적인 선택자 쪽을 따른다** — 이 우선순위 규칙은 7절에서 다룬다.
- 개발자 도구의 Styles(Rules) 패널에서 오버라이드된 스타일은 취소선으로 표시된다. 어떤 규칙이 어떤 규칙에게 밀렸는지 시각적으로 확인할 수 있다.

## 5. 클래스와 아이디 — 스타일 이름표가 아니라 문서상의 역할이 다르다

클래스와 아이디는 둘 다 "내가 원하는 이름을 붙일 수 있는 속성"이라는 점에서 비슷해 보이지만, 원래 의도된 역할이 다르다.

- **아이디(`id`)는 스타일을 주기 위한 용도가 아니다.** HTML 자체가 문서 안의 특정 컨텐츠(리소스)를 고유하게 식별하기 위해 쓰는 속성이다. 그래서 **문서 안에서 같은 `id`를 두 번 이상 쓰면 안 된다** — 유일해야 한다는 게 원칙이다.
  - `id`가 붙은 영역은 URL에 `#id값`을 붙이는 것만으로 그 위치로 바로 스크롤 이동할 수 있다(`https://.../list.html#footer`). 이건 브라우저가 "이 페이지 안의 `footer`라는 콘텐츠 영역으로 이동해라"라는 뜻으로 해석하는 것이다 — `id`가 "스타일용 이름"이 아니라 "콘텐츠 식별자"라는 걸 보여주는 대표적인 예시다.
- **클래스(`class`)는 그룹 이름이다.** 같은 클래스명을 가진 요소는 "같은 그룹에 속한다"는 뜻이고, 문서 여러 곳에 자유롭게 재사용할 수 있다. 그래서 CSS로 여러 요소를 한꺼번에 스타일링할 때는 클래스를 쓰는 게 원칙이다.
- 옛날 문서 중에는 스타일링 편의를 위해 모든 요소에 `id`를 개별로 붙여둔 경우도 있는데, 이렇게 되면 요소 하나하나를 따로따로 타겟팅해야 해서 클래스로 묶어서 한 번에 스타일을 주는 CSS 본연의 장점을 살릴 수 없다. 가능하면 스타일링은 클래스 기반으로, `id`는 콘텐츠 식별 용도로 분리해서 쓰는 게 바람직하다.

## 6. 속성 선택자(attribute selector)

태그명·클래스·아이디로 잡히지 않는 나머지 속성값을 기준으로도 요소를 선택할 수 있다.

| 문법 | 의미 |
|---|---|
| `[attr]` | 그 속성을 갖고 있는 요소 |
| `[attr=value]` | 속성값이 정확히 `value`와 일치 |
| `[attr~=value]` | 공백으로 구분된 값 목록 중 `value`가 포함됨 |
| `[attr\|=value]` | 값이 `value`이거나 `value-`로 시작함(언어 코드용) |
| `[attr^=value]` | 값이 `value`로 시작함 |
| `[attr$=value]` | 값이 `value`로 끝남 |
| `[attr*=value]` | 값 어딘가에 `value`가 포함됨 |
| `[attr operator value i]` | 대소문자 구분 없이 비교(`i` 플래그) |

```css
/* lang 속성이 있는 모든 span은 굵게 */
span[lang] { font-weight: bold; }

/* 포르투갈어(pt) span은 초록색 */
span[lang="pt"] { color: green; }

/* 미국 영어(en-us 등)로 시작하는 값은 파란색 */
span[lang~="en-us"] { color: blue; }

/* 중국어 계열(zh, zh-CN, zh-TW 등)은 빨간색 */
span[lang|="zh"] { color: red; }

/* # 으로 시작하는 내부 링크는 골드 배경 */
a[href^="#"] { background-color: gold; }

/* .cn 으로 끝나는 링크는 빨간 글자 */
a[href$=".cn"] { color: red; }

/* url에 example이 포함된 링크는 회색 배경 */
a[href*="example"] { background-color: #cccccc; }

/* type이 email인지 대소문자 구분 없이 비교 */
input[type="email" i] { border-color: blue; }
```

- `[attr~=value]`(물결 연산자)는 공백으로 구분된 값들 중 **완전히 일치하는 단어 하나**가 포함되어 있는지를 본다. 예를 들어 `lang="en-us fr"`처럼 여러 언어가 공백으로 나열되어 있을 때, 그 목록 안에 `en-us`라는 값이 정확히 하나 들어있으면 매칭된다.
- `href`처럼 원래 스타일과 무관한 속성도 얼마든지 선택자로 쓸 수 있다 — `a[href]`처럼 태그명과 조합해도 되고, 태그명을 생략하면 `href` 속성을 가진 모든 태그(사실상 대부분 `a`)를 대상으로 한다.

## 7. 우선순위(specificity) — 캐스케이딩 충돌을 해결하는 순서

여러 선택자가 같은 요소를 동시에 겨냥하면, 브라우저는 어떤 스타일을 최종적으로 적용할지 정해야 한다. 이때 기준이 되는 게 **우선순위(명시도)**다.

**우선순위: 아이디 > 클래스 > 태그 > 유니버설**

```css
.h1 { color: aqua; }    /* 클래스 선택자 */
h1 { color: pink; }     /* 태그 선택자 */
```

```html
<h1 class="h1">우리카페</h1>
```

- 위 예시에서 `h1` 요소는 태그 선택자(`h1`)와 클래스 선택자(`.h1`) 둘 다에게 선택된다. 이때 **클래스 선택자가 태그 선택자보다 우선순위가 높기 때문에**, 최종 색상은 `aqua`가 된다 — CSS 코드상 순서(`h1`이 먼저 쓰였는지, `.h1`이 먼저 쓰였는지)와는 무관하다.
- **우선순위가 같을 때만 순서가 의미를 가진다.** 같은 태그 선택자 `h1`을 두 번 다른 색으로 정의했다면, 나중에 선언된 규칙이 앞의 규칙을 캐스케이딩(덮어쓰기)해서 최종적으로 적용된다.
  ```css
  h1 { color: pink; }
  h1 { color: blue; }
  ```
  둘 다 똑같은 태그 선택자라 우선순위가 같기 때문에, 이 경우 최종 색상은 코드에서 **더 나중에 나온** `blue`가 된다.
- 반대로 **우선순위가 다르면 코드 순서를 아무리 바꿔도 결과가 안 바뀐다.** 우선순위가 낮은 선택자를 아무리 나중에 써도, 우선순위가 높은 선택자를 이길 수 없다.
- 실무에서 "분명히 스타일을 줬는데 왜 안 먹지?"라는 문제가 생기면, 대부분 이 우선순위 문제다. 개발자 도구에서 그 요소를 선택했을 때 어떤 규칙이 취소선으로 밀려 있는지 확인하면, 어떤 선택자가 어떤 선택자에게 졌는지 바로 알 수 있다.
