# 플렉스박스 아이템 속성과 박스 사이징

## 1. flex-basis — 신축 계산이 시작되는 "기본 크기"

`css/flex/flex.css`는 플렉스 아이템 다섯 개에 `flex-basis: 100px`만 준 예제다.

```css
.ex1-flex {
    background-color: gray;
    height: 500px;

    display: flex;

    div {
        flex-basis: 100px;
    }
}
```

`flex-basis`는 `flex-grow`·`flex-shrink`가 계산을 시작하는 **출발점 크기**다. `width`와 비슷해 보이지만, `flex-direction: column`이면 `width` 대신 세로 크기의 기준이 되는 등 축이 바뀌어도 항상 "주축 방향의 기본 크기"를 가리킨다는 점이 다르다. 이 예제는 다섯 아이템 모두 `flex-grow`를 주지 않았으므로(기본값 `0`), 각자 `100px`만 차지하고 컨테이너에 남는 공간은 아무에게도 분배되지 않은 채 그대로 남는다 — "여백이 있어도 `flex-grow`가 없으면 아무도 그 여백을 가져가지 않는다"는 걸 보여 주는 기본형이다.

## 2. flex-grow·flex-shrink와 flex 축약형

`flex-basis`가 신축 계산의 출발점이라면, `flex-grow`와 `flex-shrink`는 그 출발점에서 얼마나 늘어나고 줄어들지를 정하는 속성이다.

- **`flex-grow`**(기본값 `0`): 컨테이너에 남는 공간이 있을 때, 그 여백을 아이템들이 나눠 갖는 비율이다. 모든 아이템이 `flex-grow: 1`이면 남는 공간을 똑같이 나눠 가지고, 한 아이템만 `flex-grow: 2`라면 그 아이템이 나머지보다 두 배 더 많이 가져간다. 기본값이 `0`이라서, 아무 값도 주지 않으면 컨테이너에 여백이 남아도 아무도 그 공간을 가져가지 않는다 — 1절의 `flex.css` 예제가 바로 이 기본 동작(모두 `100px`만 차지하고 나머지는 빈 채로 남음)을 보여 준다.
- **`flex-shrink`**(기본값 `1`): 반대로 컨테이너 공간이 모자랄 때, 아이템이 얼마나 줄어들지를 정하는 비율이다. 기본값이 `1`이라서 아이템은 별다른 설정이 없어도 공간이 좁아지면 자동으로 줄어든다. `flex-shrink: 0`을 주면 아무리 공간이 모자라도 그 아이템만은 줄어들지 않는다.

`flex-grow`가 "남는 공간을 누가 더 가져갈지"를 정한다면, `flex-shrink`는 그 반대로 "공간이 모자랄 때 누가 더 양보할지"를 정하는 속성이다. 이 둘과 `flex-basis`를 매번 세 줄로 따로 쓰는 대신 한 번에 지정할 수도 있는데, `css/flex/flex-line.css`와 `flex-order.css`는 아이템에 `flex: 0 0 100px;`를 준다.

```css
div {
    flex: 0 0 100px;
}
```

`flex` 축약 속성은 `flex-grow`·`flex-shrink`·`flex-basis`를 이 순서로 한 번에 지정한다. `0 0 100px`은 "늘어나지도 않고(`flex-grow: 0`), 줄어들지도 않고(`flex-shrink: 0`), 기본 크기는 `100px`"이라는 뜻이라, 컨테이너 크기가 어떻게 바뀌든 이 아이템은 항상 정확히 `100px`을 유지한다. 사이드바를 무슨 일이 있어도 고정하려면 `flex-shrink: 0`을 추가하는 것과 같은 원리를, 실전에서는 이렇게 축약형 한 줄로 쓰는 경우가 많다.

세 값을 다 풀어 쓰지 않고 키워드나 값 하나만 줄 수도 있는데, 이때는 다음처럼 나머지 값이 자동으로 채워진다.

| 축약 표현 | 풀어 쓴 값 | 의미 |
|---|---|---|
| `flex: none` | `flex: 0 0 auto` | 늘어나지도 줄어들지도 않고, 크기는 콘텐츠 기준 |
| `flex: auto` | `flex: 1 1 auto` | 자유롭게 늘고 줄되, 기본 크기는 콘텐츠 기준 |
| `flex: initial` | `flex: 0 1 auto` | 늘어나진 않지만 줄어들 수는 있음(기본값과 동일) |
| `flex: 100px` | `flex: 1 1 100px` | 값 하나만 주면 `flex-basis`로 취급되고, grow·shrink는 `1`로 채워짐 |

세 값을 각각 외우기보다, 이렇게 자주 쓰는 조합에 이름을 붙여 놓은 것으로 이해하면 된다.

## 3. flex-direction·flex-wrap과 flex-flow 축약형

두 속성은 각각 다음을 담당한다.

```css
.ex1-flex {
    background-color: gray;
    height: 500px;

    display: flex;
    flex-direction: row;
    flex-wrap: wrap;
}
```

- **`flex-direction`**(기본값 `row`): 아이템이 나열되는 주축 방향을 정한다. `row`는 가로로, `column`은 세로로 나열하고, `row-reverse`/`column-reverse`를 쓰면 순서를 뒤집는다.
- **`flex-wrap`**(기본값 `nowrap`): 아이템들이 한 줄에 다 들어가지 않을 때 줄바꿈을 허용할지 정한다. 기본값 `nowrap`은 줄바꿈 없이 아이템을 억지로 한 줄에 우겨넣거나(줄어들 수 있다면 `flex-shrink`로 쪼그라들며) 넘치게 두고, `wrap`을 주면 다음 줄로 넘긴다.

아이템이 각각 `flex: 0 0 100px`로 줄어들지 않게 고정돼 있으므로, 컨테이너 폭이 아이템들의 합보다 좁아지면 억지로 쪼그라드는 대신 `wrap` 덕분에 다음 줄로 넘어간다 — `flex-shrink: 0`과 `flex-wrap: wrap`을 같이 쓰면 "각 아이템 크기는 고정하고, 줄 수만 늘려서 대응한다"는 조합이 완성된다.

이 두 속성을 한 번에 지정하는 축약형이 `flex-flow`다. 실제로 `flex-line.css`의 컨테이너는 위 두 줄을 풀어 쓰는 대신 `flex-flow: row wrap;` 한 줄로 쓴다.

```css
.ex1-flex {
    background-color: gray;
    height: 500px;

    display: flex;
    flex-flow: row wrap;
}
```

## 4. align-items vs align-content — "아이템 정렬"과 "줄 정렬"은 다르다

`flex-order.css`는 여러 줄로 줄바꿈된 상태에서 교차축 정렬을 다룬다.

```css
.ex1-flex {
    background-color: gray;
    height: 600px;

    display: flex;
    flex-flow: row wrap;
    justify-content: flex-end;

    align-items: center;
    /* 각 줄 안에서 아이템을 교차축 가운데로 정렬한다 */
    align-content: center;
    /* 줄바꿈으로 생긴 줄 전체를 교차축 가운데로 정렬한다 */

    div {
        flex: 0 0 100px;
    }
}
```

`align-items`는 **각 줄 안에서** 아이템을 교차축 방향으로 어떻게 정렬할지 정한다. 반면 `align-content`는 `flex-wrap: wrap`으로 여러 줄이 생겼을 때, **줄(line) 전체 묶음**을 컨테이너의 교차축 공간(위 예제에서는 `height: 600px`이 남긴 세로 여백) 안에서 어떻게 배치할지 정한다. 한 줄만 있을 때는 `align-content`가 아무 효과도 없어 보이지만, 아이템이 줄바꿈으로 여러 줄이 됐고 컨테이너 세로 크기에 아직 여백이 남아 있다면 `align-items`(줄 내부 정렬)와 `align-content`(줄 사이 여백 배분)가 서로 다른 역할을 한다는 걸 확인할 수 있다.

네 개의 정렬 속성이 자꾸 헷갈린다면, 각각이 "누구를" "어느 축으로" 정렬하는지로 구분하면 된다.

- `justify-content` — 모든 아이템을 **주축** 방향으로 정렬한다.
- `align-items` — 모든 아이템을 **교차축** 방향으로 정렬한다.
- `align-self` — **아이템 하나만** 교차축 방향으로 정렬한다(컨테이너가 아니라 아이템에 주는 속성).
- `align-content` — 줄바꿈으로 생긴 **여러 줄(line) 전체**를 교차축 방향으로 정렬한다(줄 사이 여백 배분).

`align-items`(또는 `align-self`)가 쓸 수 있는 값에는 `flex-start`·`flex-end`·`center`·`stretch` 외에 `baseline`도 있다. `baseline`은 각 아이템 안의 텍스트가 **글자를 쓰는 기준선(baseline)**끼리 나란히 맞도록 정렬한다 — 아이템마다 글자 크기나 내용 높이가 달라도, 글자가 앉는 줄만큼은 시각적으로 일렬로 맞춰야 할 때 쓴다.

`align-content`가 쓸 수 있는 값도 `flex-start`·`flex-end`·`center`·`space-between`·`space-around`·`stretch`로 `justify-content`와 거의 동일하다 — 다만 대상이 개별 아이템이 아니라 "줄 전체"라는 점만 다르다. 예를 들어 5~6개 아이템이 두 줄로 줄바꿈된 상태에서 컨테이너 세로 공간이 남는다면, `align-content: space-between`은 첫 줄을 맨 위에, 마지막 줄을 맨 아래에 붙이고 그 사이 여백을 줄 사이에만 나눠 준다.

## 5. align-self — 이 아이템만 다르게 정렬하기

`flex-order.css`는 컨테이너에 `align-items: center`를 주면서도, 개별 아이템에는 다른 값을 덮어씌운다.

```css
div:nth-child(2) {
    background-color: green;
    align-self: self-start;
}

div:nth-child(3) {
    background-color: blue;
    align-self: stretch;
}

div:nth-child(4) {
    background-color: yellow;
    align-self: flex-end
}
```

`align-items`가 컨테이너에 주는 "모두에게 적용되는 기본 정렬값"이라면, `align-self`는 **그 아이템 하나만** 그 기본값을 무시하고 다른 교차축 정렬을 갖도록 한다. 위 코드에서 2번째 아이템은 나머지가 `center`로 정렬돼 있어도 혼자 `self-start`(줄 시작 쪽)로, 4번째는 혼자 `flex-end`(줄 끝 쪽)로 붙는다.

다만 `align-self`도 결국 "정렬은 여백이 있어야 동작한다"는 원칙을 그대로 따른다 — 여기서 여백은 컨테이너 전체가 아니라 **그 아이템이 속한 줄(line)의 교차축 크기** 안에서의 여백이다. 그런데 4절 코드처럼 `align-content: center`가 켜져 있으면 얘기가 달라진다. `align-content: center`는 줄의 교차축 크기를 콘텐츠 높이에 딱 맞게 줄인 뒤, 그렇게 압축된 줄(들)을 컨테이너 세로 공간의 가운데로 몰아넣는다. 이렇게 줄 자체가 이미 콘텐츠 크기만큼만 차지하고 남는 여백이 없는 상태에서는, 그 줄 안에 있는 개별 아이템에 `align-self`를 아무리 다르게 줘도 움직일 공간이 없어 적용된 티가 나지 않는다 — "패킹된 줄 안에서는 개별 정렬이 안 먹는다"는 게 바로 이 원리다.

아이템별 `align-self`가 실제로 움직이는 걸 눈으로 확인하려면, `align-content`를 `stretch`로 바꾸거나 아예 지정하지 않아야 한다. 그러면 줄이 컨테이너의 세로 공간 전체로 늘어나면서 줄 안에 여유 공간이 남고, 그 여백 안에서 `flex-start`/`center`/`flex-end`/`stretch` 같은 아이템별 값이 실제로 다르게 자리 잡는 걸 볼 수 있다.

## 6. order — 마크업 순서를 바꾸지 않고 화면 순서만 바꾸기

플렉스 아이템은 기본적으로 마크업에 적힌 순서대로 배치되지만, `order` 값을 주면 그 순서를 화면에서만 바꿀 수 있다. `order`는 정수(`<integer>`)를 받고, 기본값은 모든 아이템이 `0`이며 값이 작을수록 앞으로 간다.

다섯 개의 아이템(1, 2, 3, 4, 5 순서로 작성)이 모두 `order: 0`이라 마크업 순서 그대로 배치돼 있다고 하자. 여기서 세 번째 아이템에만 `order: -1`을 주면, 나머지 넷은 `0`으로 그대로 있고 `-1`인 아이템만 `0`보다 앞서므로 배치가 `3, 1, 2, 4, 5` 순서로 바뀐다 — 모든 아이템에 번호를 새로 매길 필요 없이, 옮기고 싶은 아이템 하나에만 음수 `order`를 주는 것이 실전에서 가장 자주 쓰는 방식이다.

여러 아이템을 원하는 순서로 재배치하고 싶다면, 아예 각 아이템에 원하는 최종 순서 번호를 하나씩 부여할 수도 있다 — 위 예에서 `3`번 아이템에 `order: 1`, `1`번에 `order: 2`, `2`번에 `order: 3`, `4`번에 `order: 4`, `5`번에 `order: 5`를 주면 `3, 2, 1, 4, 5` 순서가 된다. 다만 이 방법은 아이템이 추가·삭제될 때마다 번호를 다시 매겨야 해서 번거로우므로, 앞으로 보내고 싶은 소수의 아이템에만 음수를 주는 쪽이 유지보수하기 쉽다. `order` 값이 같은 아이템끼리는 원래 마크업 순서(먼저 나온 것이 앞)가 그대로 유지된다.

## 7. box-sizing — width가 가리키는 게 콘텐츠냐 박스냐

`.aside { width: 250px; }`처럼 크기를 지정할 때, 그 값이 정확히 무엇의 크기인지는 `box-sizing` 값에 따라 달라진다.

- **`box-sizing: content-box`(기본값)**: `width`는 **콘텐츠 영역만**의 크기다. 여기에 패딩과 경계선을 추가하면, 그만큼이 지정한 크기 위에 **더해져서** 박스 전체 크기가 커진다. 예를 들어 `width: 250px`인 박스에 `padding: 10px`과 `border: 10px solid`를 좌우로 주면, 실제 박스 너비는 `250 + (10+10)×2 = 290px`가 된다 — "250px를 줬는데 패딩·경계선을 추가했더니 갑자기 커졌다"는 문제가 이래서 생긴다.
- **`box-sizing: border-box`**: `width`가 **패딩과 경계선까지 포함한 박스 전체**의 크기가 된다. 이 경우 패딩이나 경계선을 나중에 추가해도 박스 전체 크기(`250px`)는 그대로 유지되고, 대신 그만큼 콘텐츠가 차지하는 실제 공간이 줄어든다.

즉 콘텐츠 크기를 고정하고 싶다면 `content-box`(기본값)를 그대로 두면 되고, **박스 전체 크기를 고정하고 그 안에서 패딩·경계선을 자유롭게 조절하고 싶다면 `border-box`로 바꿔야 한다.** 실무에서는 후자가 예측하기 쉬워서, `* { box-sizing: border-box; }`처럼 문서 전체에 미리 깔아두고 시작하는 경우가 많다.

## 8. 배경 이미지로 꾸미기 — background-image·repeat·position

`flex-line.css`의 아이템에는 배경 이미지도 붙어 있다.

```css
div {
    flex: 0 0 100px;
    background-image: url(arrow.png);
    background-repeat: no-repeat;
    /* background-repeat: repeat-x; */
    /* background-repeat: repeat-y; */
    background-position: 10px top;
    /* background-position: 10px 0; */
    /* background-position: center bottom; */
}
```

`background-image`로 이미지를 넣는 것은 벽에 벽지를 바르는 것과 같다 — 기본값은 작은 이미지를 가로세로로 **반복(`repeat`)**해서 채우는 것이다. `background-repeat: no-repeat`는 이 반복을 끄고 이미지를 한 번만 그리며, `repeat-x`/`repeat-y`를 쓰면 가로 또는 세로 방향으로만 반복한다. `background-position`은 반복하지 않을 때 이미지를 박스 안 어디에 둘지 정한다 — `10px top`처럼 좌표를 픽셀로 줄 수도 있고, `center bottom`처럼 키워드 조합으로 줄 수도 있다.

`background-position`에 값을 두 개 줄 때는 **항상 첫 번째가 가로(수평) 위치, 두 번째가 세로(수직) 위치**다. `10px top`이라면 이미지를 박스 왼쪽에서 오른쪽으로 `10px`만큼 들어간 자리에, 세로로는 위쪽(`top`)에 붙인다는 뜻이다. 키워드도 이 순서를 따른다 — `left`/`center`/`right`는 가로 위치, `top`/`center`/`bottom`은 세로 위치를 가리키므로, `center bottom`은 "가로로는 가운데, 세로로는 맨 아래"에 이미지를 놓으라는 뜻이 된다. 픽셀 값도 마찬가지로 "왼쪽 기준 X만큼, 위쪽 기준 Y만큼"으로 읽으면 된다 — 값 하나만 주면 그 값은 가로 위치가 되고 세로는 `center`가 기본으로 채워진다.
