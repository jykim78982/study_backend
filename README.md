# 2026-07-29 · 배열과 참조, 메모리 구조

## 1. 변수의 두 종류 — 값 변수와 참조 변수

자바의 변수에는 딱 두 종류만 있다.

| 타입 종류 | 변수 안에 들어있는 것 |
|---|---|
| 기본형 8개 (`int`, `double`, `char`, `boolean` 등) | **값 그 자체** (3, 51.8, 'A'...) |
| 참조형 (배열, `String`, 모든 객체) | **주소** (실제 데이터는 힙에) |

- 자바의 모든 대입은 **"상자 안의 내용물을 복사"**하는 것
- 내용물이 값이냐 주소냐가 타입에 따라 다를 뿐
- 참조형은 복사 후에도 같은 대상을 가리키니 "연결된 것처럼" 보이고, 기본형은 숫자만 넘어가니 "연결이 끊긴 것처럼" 보인다

### 주소 변수(포인터) vs 참조 변수

"주소를 담는 변수"에도 두 종류가 있다. 담는 내용물은 같지만 **주소를 얼마나 직접 다룰 수 있느냐**가 다르다.

| 구분 | 언어 | 할 수 있는 것 |
|---|---|---|
| **주소 변수 (포인터)** | C, C++ | 주소를 **직접 보고, 바꾸고, 연산**할 수 있다 (`p + 1`처럼 주소에 덧셈 가능) |
| **참조 변수** | 자바 | 주소가 들어있지만 **주소 자체는 볼 수도 만질 수도 없다** — 오직 `.`이나 `[i]`로 대상에 **접근만** 가능 |

- 자바의 참조 변수도 내부적으로는 주소를 담고 있다. 그래서 동작 원리를 이해할 때는 "주소가 든 변수"로 생각하면 된다 (이 노트의 `#77` 그림들처럼).
- 다만 자바는 그 주소를 **숫자로 꺼내거나 연산하는 것을 금지**한다. 포인터 연산 실수(엉뚱한 메모리를 건드리는 버그, 보안 취약점)를 언어 차원에서 원천 차단한 것.
- 그래서 자바에서는 "포인터"라는 말 대신 **"참조(reference)"**라고 부른다 — "주소를 아는 게 아니라, 대상을 **가리킬** 줄만 안다"는 뉘앙스.
- 7번 섹션의 `배열 시작 주소 + (i × 4바이트)` 같은 주소 계산은 **JVM이 대신 해주는 것**이고, 우리는 `nums[i]`라는 안전한 문법만 쓴다.

## 2. 1차원 배열의 메모리 구조

```java
int[] nums = { 10, 20, 30 };
```

```
스택                          힙
┌──────────────┐             ┌─────────────────────────┐
│ nums = #77   │ ──────────→ │ #77 배열 덩어리          │
└──────────────┘             │  0번칸  1번칸  2번칸     │
  주소만 들고 있음            │ [ 10 ] [ 20 ] [ 30 ]    │
                             └─────────────────────────┘
                               값이 직접 들어있음
```

- **`nums`** = 배열 덩어리가 어디 있는지 적힌 **주소** (덩어리 자체가 아님)
- **`nums[0]`** = 그 주소로 찾아간 덩어리 안의 **0번 공간** (값이 직접 들어있는 칸)
- 기본형 배열은 칸 안에 **값이 직접** 들어있다 (칸마다 또 주소가 있는 게 아님)

### 배열 생성의 3단계

1. **힙에 공간 확보** — 크기는 이 순간 고정되고 영원히 못 바꿈
2. **값 채우기** — `{...}`면 각 항목을 평가한 값을 복사, `new int[5]`만 쓰면 기본값으로 자동 초기화
3. **주소를 변수에 저장** — 변수는 배열 자체가 아니라 "위치를 적은 쪽지"

### 배열 자동 초기화 기본값

| 배열 타입 | 기본값 |
|---|---|
| `int[]`, `long[]` 등 정수 | `0` |
| `double[]`, `float[]` | `0.0` |
| `boolean[]` | `false` |
| `String[]` 등 참조형 | `null` |

※ 지역변수는 초기화 없이 못 쓰지만, 배열 칸은 예외적으로 자동 초기화된다.

### 중괄호 초기화는 "만들 때"만 가능

```java
int[] nums = { 1, 2, 3, 4, 5 };      // ✅ 만들면서 초기값을 넣는 것은 가능

int[] nums2;
nums2 = { 1, 2, 3, 4, 5 };           // ❌ 이미 만들어진 변수에 나중에 중괄호만 대입은 불가능
nums2 = new int[]{ 1, 2, 3, 4, 5 };  // ✅ 나중에 넣으려면 new를 붙여야 한다
```

- `{ ... }` 단독 표기는 **선언과 동시에 쓸 때만** 허용되는 축약형이다. 선언 이후에는 `new int[]{ ... }`로 "새 배열을 만든다"는 것을 명시해야 한다.

## 3. 배열 초기화에 변수를 넣으면 — 값 복사

```java
int num = 3;
int[] row = { 1, num, 2, 1, 6, 8 };   // num의 "값" 3이 복사됨

num = 4;                    // num만 바뀜, 배열과는 아무 연결 없음
System.out.println(row[1]);  // 여전히 3
```

- 배열 생성 시점에 `num` 상자를 열어 **그 순간의 값**을 꺼내 복사한다
- 이후 `num`을 바꿔도 배열은 무관 — 기본형 변수를 "참조로 연결"하는 방법은 자바에 없다

## 4. 배열 대입은 주소 복사

```java
int[][] rows = new int[5][];
rows[0] = row;            // 배열 통째 복사가 아니라 "주소" 복사

row[1] = 5;
System.out.println(rows[0][1]);  // 5 — 같은 배열을 가리키므로 반영됨
```

```
row     ──┐
          ├──→ #77 [1][3][2][1][6][8]   (힙에 있는 하나의 배열)
rows[0] ──┘
```

- `row`로 고치든 `rows[0]`으로 고치든 **같은 칸**을 고치는 것

## 5. 2차원 배열 = "배열을 가리키는 배열"

```java
int[] a = { 1, 2, 3 };
int[] b = { 4, 5 };
int[] c = { 6, 7, 8, 9 };

int[][] rows = { a, b, c };   // 1차원 배열들을 나열해서 만들 수 있다!
```

- `int[]`가 **값들을 저장**하기 위한 공간이라면, `int[][]`는 **배열 여러 개를 일괄 처리**하기 위한 공간이다
- `rows`는 **"int[] 참조를 담는 1차원 배열"** — `{ rows[0], rows[1], rows[2] }` 느낌이 정확함
- 각 칸이 서로 다른 크기의 배열을 가리켜도 됨 (가변 배열, jagged array)
- `new int[3][]`은 바깥 배열만 생성, 안쪽 칸은 전부 `null`
- 크기 N이면 인덱스는 0 ~ N-1 (`new int[2][]`면 `rows[0]`, `rows[1]`만 존재)

### 다차원 배열을 만드는 두 가지 방법

```java
int[][] rows = new int[3][6];   // ① 동일한 격자 크기 — 3행 6열 공간을 미리 다 만든다
int[][] rows = new int[3][];    // ② 톱니형 격자 크기 — 바깥 3칸만 만들고, 안쪽 공간은 아직 없다
```

| 방식 | 격자 모양 | 안쪽 배열 |
|---|---|---|
| `new int[3][6]` | 동일한 크기 (직사각형) | 6칸짜리 배열 3개가 **미리** 만들어짐 |
| `new int[3][]` | 톱니형 (jagged) | **아직 없음** (`null`) — 나중에 행마다 다른 크기로 채운다 |

- 모든 행의 크기가 같다면 ①, 행마다 크기가 다르거나 만들어둔 배열을 나중에 붙일 거라면 ②를 쓴다.

### 2차원 접근은 1차원 접근 두 번

```java
rows[1][3]
= (rows[1]) [3]   // ① rows의 1번 칸에서 참조를 꺼냄 → 어떤 int[]
                    // ② 그 배열의 3번 칸 값을 읽음
```

### 주소를 따라가는 횟수로 구분

| 형태 | 구조 | 주소 따라가는 횟수 |
|---|---|---|
| `int[]` | 변수 → **[값, 값, 값]** | 1번 |
| `String[]` | 변수 → [주소, 주소] → 각 객체 | 2번 |
| `int[][]` | 변수 → [주소, 주소] → 각 [값, 값, 값] | 2번 |

※ `int[][]`와 `String[]`은 사실 같은 구조 — 칸에 주소가 들어있는 배열.

## 6. 참조를 덮어쓰면 이전 배열은 어떻게 되는가

```java
rows[0] = new int[]{ 9, 9, 9 };   // 새 배열로 교체
```

**경우 1 — 다른 참조가 남아있으면: 멀쩡히 살아있음**

```
교체 후:  row ────→ #77 [1][3][2][1][6][8]   ← row로 여전히 접근 가능
          rows[0] → #88 [9][9][9]            ← 새 배열
```

**경우 2 — 마지막 참조였으면: 고아(garbage)가 됨**

```
#77 [1][3][2]   ← 아무도 안 가리킴 = 접근할 방법이 영원히 없음 → GC 수거 대상
```

- 대입은 **쪽지를 바꿔 적는 것**일 뿐, 원래 대상을 지우는 동작이 아님
- 자바에 "삭제" 개념은 없다 — 아무도 안 가리키면 가비지 컬렉터가 알아서 회수
- 잃어버린 주소를 되찾는 기능도 없다 — 값을 보존하려면 덮어쓰기 **전에** 참조를 남겨야 함

```java
int[] backup = rows[0];           // 덮어쓰기 전에 쪽지를 하나 더
rows[0] = new int[]{ 9, 9, 9 };
System.out.println(backup[0]);      // 이전 배열에 여전히 접근 가능
```

## 7. 인덱스 접근의 실제 원리

`nums[i]`는 "변수를 잘라 쓰는 것"이 아니라 **주소를 따라간 뒤 → 인덱스만큼 이동해서 칸을 짚는 것**.

```
nums[i]의 실제 위치 = 배열 시작 주소 + (i × 4바이트)   ※ int는 4바이트

nums[0] → #77 + 0  = #77
nums[1] → #77 + 4  = #81
nums[2] → #77 + 8  = #85
```

- 인덱스가 0부터 시작하는 이유: 첫 칸은 시작 주소에서 **0칸 이동**한 곳
- 몇 번 칸이든 곱셈 한 번으로 위치가 계산되므로 `nums[9999]`도 `nums[0]`만큼 빠르다

## 8. 배열 칸 = 번호로 부르는 변수

- `nums[1]`은 `int` 변수 하나와 완전히 동일하게 사용 가능 (`nums[1] = 99`, `nums[1]++`, ...)
- 칸의 값을 변수로 꺼내면(`int temp = nums[1]`) 그 순간 **연결이 끊긴 복사본**
- 원본을 바꾸려면 반드시 `nums[i] = ...` 형태로 칸에 직접 대입
- 이름 대신 **번호**라서 반복문의 `i`와 결합 가능 — 이것이 배열의 진짜 강점

```java
for (int i = 0; i < nums.length; i++)
    nums[i] = nums[i] * 2;    // 모든 칸을 한 번에 처리
```

## 9. 프로세스와 메모리 영역

**프로그램을 메모리에 올리면 프로세스가 된다.** 프로그램 하나가 **여러 프로세스**를 실행할 수도 있다 (예: 같은 실행 파일을 여러 번 실행).

프로세스의 메모리는 크게 **Text 영역**과 **Data 영역**으로 나뉜다.

| 영역 | 담는 것 |
|---|---|
| **Text** | 실행될 코드를 가리키는 **명령어 집합**(instruction). 코드 자체는 여기 있을 뿐, 값을 담는 공간이 아니다 |
| **Data** | 변수를 담는 공간. 이 안이 다시 **Stack**과 **Heap**으로 나뉜다 |

Java 코드를 실행하면 **`main` 블록이 실행**되면서 이 구조가 만들어진다.

### 변수는 실행 전에 미리 마련된다

블록이 실행되기 전에 그 블록에 필요한 변수 공간이 먼저 준비된다.

- 그런데 디버거로 확인해보면 아직 안 쓰인 변수가 안 보이는 경우가 있다 — 이건 **디버거가 "아직 사용되지 않은 변수"를 화면에 미리 띄우지 않는 것뿐**이다.
- 실제 런타임에서는 **준비물(변수 공간)이 미리 마련**되어 있다. 디버거 표시 여부와 실제 메모리 할당 여부는 별개다.

## 10. 스택 프레임 — 개별이 아니라 통째로 올라간다

블록 안에 변수가 여러 개 있을 때, **하나씩 개별적으로 스택에 올라가는 게 아니다.**

> **비유 — 엘리베이터**: 여러 사람이 각자 계단으로 한 명씩 올라가는 게 아니라, **엘리베이터 한 대(프레임)에 다 같이 타고 올라간다.** `main`에 필요한 변수들은 개별로 올라가는 게 아니라, **하나의 프레임에 감싸여서** 한 번에 스택에 실린다.

> **비유 — 창고**: 창고에 물건을 들여놓을 때 안쪽 벽부터 **차곡차곡** 채워나간다. 스택도 이런 식으로 정해진 방향으로 순서대로 쌓인다.

### 스택 vs 힙 — 쌓이는 방향과 시점이 다르다

물리적으로 공간이 딱 나뉘어 있는 건 아니지만, 개념적으로 이렇게 정리된다.

| 구분 | 무엇이 여기 쌓이나 | 방향 | 성격 |
|---|---|---|---|
| **스택(Stack)** | **선언**에 의해 만들어진 것 — 블록이 실행될 때마다 준비물로 예약되어 올라감 | 아래서부터 쌓아 올라감 | **정적 메모리 할당** — 실행되기 전에 미리 크기가 정해져 할당됨 |
| **힙(Heap)** | **실행**되면서(`new` 등) 만들어진 것 — 동적으로 실행해봐야 크기를 아는 것 | 위에서부터 쌓아 내려감 | **동적 메모리 할당** — 실행 중에 필요한 만큼 그때그때 할당됨 |

> 정리: **선언된 것은 Stack**에, **`new`처럼 실행된 뒤 연산되는 것은 Heap**에 들어간다. (이 "정적/동적" 구분은 [[07-28_break 라벨과 do-while, 배열과 정렬]]의 "정적 vs 동적"에서 다룬 개념이 메모리 영역 이름 자체에도 그대로 쓰인 것이다.)

## 11. 함수 호출과 스택 프레임

함수는 **호출되기 전까지 실행되지 않는다.** 호출을 해야 비로소 그 함수가 실행된다.

호출하면서 값을 넘겨주면(**매개값**) 그 값이 매개체(함수)에게 전달되고, 함수 안에서는 **매개변수**로 저장되어 쓰인다.

### 예시 — `total` 함수를 호출한다면

```java
public class Calc {
    public static void main(String[] args) {
        int a = 3, b = 4;
        int result = total(a, b);   // ← main 안에서 total을 "호출"
        System.out.println(result);
    }

    static int total(int x, int y) {   // ← total의 실제 코드는 main 밖, 별도 메서드로 정의
        int sum = x + y;
        return sum;
    }
}
```

- `total`의 **코드(정의)**는 `main`과 나란히 있는 **별개의 메서드**다.
- `main`이 실행되다가 `total(a, b)` 줄을 만나면, 그 순간 `total`을 **호출**해서 `total`용 스택 프레임이 `main`의 프레임 위에 새로 쌓인다.
- 두 메서드는 **서로 다른 프레임**을 갖는다 — `main`의 지역변수(`a`, `b`, `result`)와 `total`의 지역변수(`x`, `y`, `sum`)는 완전히 별개의 공간에 있다.

1. `total`의 코드가 실행되기 전에, **`total` 함수를 위한 스택 프레임이 먼저 마련**되어야 한다.
2. 이 프레임은 **`main`의 스택 프레임 위에 쌓인다** — 마치 짐을 쌓아 올리듯, 호출된 함수의 프레임이 호출한 함수의 프레임 위에 적재되는 형태.
3. `total` 함수가 **반환값을 남기고 종료**하면, 호출했던 줄(line)로 돌아가고 그 반환값이 `result` 변수에 저장된다.
4. `total` 함수가 끝났으므로, 스택에 있던 **`total` 전용 프레임은 사라진다.**

> 우리가 짐을 쌓아 올렸다가 위에서부터 빼서 쓰듯이, 스택도 **쌓은 순서의 역순으로, 위에서부터 사라지는 방식(LIFO)**으로 운용된다. 함수 호출마다 준비물(변수 공간)을 쌓아두는 공간이 바로 이 스택이다.

### 함수는 데이터가 아니다

Java를 비롯한 대부분의 언어에서 **함수 자체는 데이터가 아니다.** 그래서 함수를 매개변수로 그냥 넘기는 것이 불가능하고, 함수는 어디까지나 **실행 위치로 이동하기 위한 용도**로 쓰인다.

실제로 함수가 번역된 결과를 보면, 내부적으로는 **`JMP`(점프) 명령어**로 실행되고 있다.

## 12. 가비지 컬렉션 — 힙에 남겨진 객체는 어떻게 될까

`main` 블록이 다 끝나면, 그 블록의 스택에 마련됐던 변수들도 **함께 사라진다.**

**Q. 힙에 있는 공간을 가리키던 변수(스택의 참조 변수)가 사라지면, 힙에 남은 객체는 어떻게 되나요?**

**A. 참조하던 이가 사라지면, 힙에 있던 객체는 갈 곳을 잃고 "가비지(garbage)"가 되어 메모리 누수를 유발한다.**

이건 C++에서 흔히 발생했던 문제다 — 개발자가 예기치 않게, 아무도 쓰지 않는 공간을 만들어놓고 못 지워서 메모리가 서서히 잠식되는 현상.

Java는 이 문제를 근본적으로 막기 위해 **인간에게 힙을 직접 관리하는 능력을 주지 않는다.**

- 원래는 `delete` 같은 명령어로 직접 삭제하게 할 수도 있었지만, **그 명령어조차 제공하지 않기로** 했다.
- 대신 **실행 환경(JVM)이 가비지를 스스로 찾아다니며 수거**한다 — 이 역할을 하는 게 **가비지 컬렉터(GC)**다.

### GC는 정확히 언제 수거하나?

**정확히 "이 시점"이라는 건 없다.**

- GC는 **상시로 체크**하지만, **CPU가 바쁘면 체크하지 않는다.**
- 주로 **CPU는 바쁘지 않은데 메모리가 부족하다고 느껴질 때** 동작한다.
- CPU 사용률과 메모리 사용률을 함께 살피며 수거 시점을 스스로 판단한다.

> 이 노트 6번 섹션의 "참조를 덮어쓰면 이전 배열은 어떻게 되는가"에서 다룬 고아(garbage) 배열도 바로 이 GC가 수거해가는 대상이다.

## 13. 구조체 배열 — 객체를 그룹핑한 배열

배열은 **모든 형식**에 대해 만들 수 있다. `int[]`, `char[]`뿐 아니라 **사용자 정의 클래스**로 된 배열(`Exam[]`)도 전부 가능하다.

```java
Exam[] exams = new Exam[4];   // Exam 객체 4개를 담을 배열
```

### 값 변수 배열과의 차이 — 슬라이스했을 때 나오는 것이 다르다

- 앞서 다룬 `int[] scores` 같은 **값 변수 배열**을 슬라이스하면(`scores[0]`), 그 안에 들어있는 건 **값 자체**였다.
- 하지만 `exams`처럼 **객체(참조 형식) 배열**을 슬라이스하면(`exams[0]`), 그 칸 하나하나에 담긴 것은 **`Exam` 형식의 참조**다.

그래서 `exams[0]`은 **그냥 쓰면 안 된다.** 값처럼 바로 대입해서 쓸 수 없고,

- 이미 있는 `Exam` 객체를 **할당**하거나
- `new`로 **새로운 객체를 만들어서 할당**하거나

둘 중 하나로 **참조를 대입**해줘야 사용할 수 있다.

```java
exams[0] = new Exam();       // 새 객체를 만들어 0번 칸에 참조를 대입
exams[1] = existingExam;     // 이미 있는 객체의 참조를 대입
```

이렇게 객체를 배열로 묶어두면, **앞에서 다뤘던 반복 작업(순회, 필터링, 정렬 등)을 개별 변수 반복 없이 동일하게 처리**할 수 있게 된다 — [[07-28_break 라벨과 do-while, 배열과 정렬]]에서 다룬 "정적인 코드의 반복 문제"가 객체에서도 배열로 해결되는 것.

### 구조체 배열은 2차원 배열과 뼈대가 같다

`Exam[] exams`는 **5번 섹션의 2차원 배열과 구조적으로 동일**하다. 다른 점은 "안쪽 묶음"이 배열이냐 객체냐뿐이다.

```java
// 2차원 배열 버전
int[][] data = new int[10][3];
data[0][0] = 20;      // 1번째 사람의 0번 값 (번호로 구분)

// 구조체 배열 버전
Exam[] exams = new Exam[10];
exams[0].kor = 20;    // 1번째 사람의 kor 값 (이름으로 구분)
```

```
2차원 배열:                     구조체 배열(Exam[]):
data   ──→ [ 주소, 주소, ... ]   exams ──→ [ 주소, 주소, ... ]
              │                              │
              ▼                              ▼
         [20][30][40]                 Exam{ kor:20, eng:30, math:40 }
         (번호로 구분)                  (이름으로 구분)
```

**주소를 따라가는 횟수도 5번 섹션의 표와 동일하게 2번이다.**

```java
exams[0].kor
= (exams[0]) .kor    // ① exams의 0번 칸에서 Exam 참조를 꺼냄 — "배열 접근"
                     // ② 그 객체의 kor 필드 값을 읽음 — "필드 접근"
```

`exams[0]`까지가 배열 접근, `.kor`이 필드 접근이라 표현 방식만 다를 뿐, **"배열에서 하나를 꺼내고, 그 안에서 또 하나를 꺼내는" 2단계 구조는 2차원 배열과 완전히 같다.**

| | 2차원 배열 (`int[][]`) | 구조체 배열 (`Exam[]`) |
|---|---|---|
| 안쪽 묶음의 정체 | `int[]` 배열 | `Exam` 객체 |
| 안쪽 칸 구분 방법 | 번호 (`[0]`, `[1]`, `[2]`) | 이름 (`.kor`, `.eng`, `.math`) |
| 각 칸의 의미 파악 | 코드만 봐선 모름 — 직접 세어야 함 | 필드명으로 바로 알 수 있음 |

`Exam` 같은 클래스가 미리 준비되어 있다면, "몇 번째 값이 무엇을 뜻하는지" 기억할 필요가 없어지므로 2차원 배열보다 구조체 배열이 훨씬 읽기 좋은 선택이 된다.
