## 1. 구조화란 무엇인가 — 그루핑

구조적인 프로그래밍에서 가장 먼저 필요한 것은 **그루핑(grouping)**이다. 아무 그룹도 없이 줄 단위로 순서대로만 나열된 코드는, **그룹을 정하는 순간 비로소 구조가 생긴다.**

- 처음에는 코드를 그냥 위에서부터 순서로만 구분하고 있을 뿐이다 (**선형 구조**)
- 여기저기 널부러져 있는 코드 조각을 잘라서 묶으면, 그게 **구조를 만든다**는 것

### 왜 구조화가 필요한가

- 순수하게 한 줄씩 실행되는 프로그래밍은 **선형 구조**다 — 첫 줄부터 마지막 줄까지 위에서 아래로 딱 한 번씩만 지나가며, 실행 순서가 코드가 적힌 순서와 정확히 일치한다
- 여기에 `if`, `for` 같은 **제어구조**가 들어가는 순간 흐름이 **순환 구조**로 바뀐다 — 조건에 따라 같은 코드를 건너뛰거나, 같은 구간을 여러 번 되돌아가며 반복 실행하게 되므로, 더 이상 "위에서 아래로 한 번"이라는 단순한 그림으로는 흐름을 따라갈 수 없다
- 이렇게 분기와 반복이 겹겹이 쌓이면, 코드를 눈으로 읽는 것만으로 전체 흐름을 파악하기가 점점 어려워진다
- 실제로 쓸만한 프로그램은 대략 **수천 줄(예: 8,000줄)** 정도 되는데, 이 정도 규모를 아무 구분 없이 위에서 아래로 쭉 이어진 하나의 덩어리로 두면
  - 지금 보고 있는 부분이 전체에서 어떤 역할을 하는지 가늠하기 어렵고
  - 한 곳을 고치면 다른 곳에 영향을 주는지 안 주는지 매번 전체를 다시 훑어야 하며
  - 새로운 사람이 코드를 파악하는 데도 훨씬 오래 걸린다
  - 즉, **줄 수가 늘어나는 속도보다 복잡도가 체감되는 속도가 더 빠르게 느껴진다**

## 2. 한 부분을 떼어내기

복잡한 코드에서 **한 부분을 떼어내서 따로 보면** 관리가 쉬워진다.

- 수정하든 개선하든 확장하든, **떼어낸 부분만 보고 나머지는 신경 쓰지 않아도 된다**
- 메인 실행 흐름에는 "쟤가 어떤 애고, 어떤 역할을 하는 애였다"라는 **엮어내는 한 줄만** 남기면 된다
- 전체 흐름은 그대로 유지하면서, 메인 쪽에서는 좀 더 **거시적으로** 코드를 바라보게 된다
- 떨어뜨려 놓은 코드는 **이름을 명명**해두어야 한다 — 남이 불러서 쓸 수 있도록

| 용어 | 의미 |
|---|---|
| **call** | 이름 붙여둔 코드 조각을 불러내는 것 |
| **함수** | 잘라낸 코드 조각 자체 |

코딩에서는 이 **함수**라는 도구를 이용해서 코드를 잘라내고, 각 부분을 구현한다.

### 잘라내고 호출하면 뭐가 좋은가

- `sort()`처럼 함수 하나만 호출하면, "아, 정렬하는 거구나"만 알면 되고 **내부를 들여다볼 필요가 없다**
- 봐야 할 코드의 폭이 좁아지므로 **복잡도가 낮아진다**
- 물론 궁금하면 내부를 열어서 자세히 들여다볼 수도 있다
- `sort()` 함수 안이 또 복잡하면, 그 안에서 또 잘라내서 별도 함수로 만들 수 있다 — 복잡하다고 느끼는 만큼 계속 자르고 엮어서 프로그램을 만들 수 있다

이렇게 코드를 잘게 쪼개고 이름 붙여 엮어내는 과정을 **코드의 파편화**, 또는 **코드의 구조화**라고 부른다.

우리가 실제로 작성하는 `main` 코드는, 불필요한 세부 구현이 뒤섞여 있지 않고 **"내가 지금 무엇을 하고 있는지"가 명료하게 보이면서**, 원한다면 자세히 들여다볼 수 있는 상태가 되어야 한다. 코드 조각을 메인에서 밀어내는 도구가 바로 다시 한번, **함수**다.

## 3. 프로그램은 어떻게 만들어내는가 — Top-down vs Bottom-up

| 방식 | 순서 | 비유 | 특징 |
|---|---|---|---|
| **Top-down** | 큰 계획(제목·목차)부터 잡고 하나씩 세부 구현 | 책을 쓸 때 제목·목차부터 정하는 것 | 거시적인 것부터 미시적인 것까지 내려가며 구현. **경험/경력이 있어야** 처음부터 큰 그림을 잡을 수 있음 |
| **Bottom-up** | 일단 통짜로 만들고 나중에 찢어발김 | 초안을 다 쓴 뒤 장·절로 재편집 | 코딩을 처음 공부하는 입장에서 현실적인 방식. 만든 것을 나중에 함수 단위로 **추출(고도화 작업)**해나감 |

- 코딩을 배우는 단계에서는 처음부터 거시적으로 설계하고 아래로 내려갈 수 없는 게 당연하다 — 경험이 쌓이면 Top-down이 점점 가능해진다

## 4. 함수 정의하기

함수는 **수학의 함수와 용도가 똑같다.** 자바에서는 표기 방식(모양)만 다를 뿐이다.

```
수학:    f(x) = ...
자바:    반환타입 함수명(자료형 변수명) { 함수 몸통 }
```

예시:

```java
static int square(int x) {   // 반환타입 함수명(자료형 변수명)
    return x * x;             // 함수 몸통
}
```

반환값이 없을 때는 `void`를 쓴다:

```java
static void greet(String name) {   // 돌려줄 값이 없으므로 void
    System.out.println("안녕, " + name);
    // return 문이 없거나, 값 없이 return;만 써도 됨
}
```

함수의 가장 큰 목적은 **"코드를 작게 나눌 수 있다"**는 것 — 표현 방식의 차이만 있을 뿐 의미는 수학의 함수와 같다.

### 문법 규칙

| 요소 | 규칙 |
|---|---|
| 반환값 | `return`으로 돌려줌 |
| 반환 타입 | 함수 앞에 반드시 명시 (`int`, `double`, ... 반환값이 없으면 `void`) |
| `static` | 지금 단계(인스턴스 없이 `main`에서 바로 호출)에서는 무조건 붙임 |
| 함수명 | **행위명** — `기능+재료명()` 형태로, 이름만 봐도 무슨 역할인지 알 수 있어야 함 |
| 표기법 | 자바는 **카멜 케이스(camelCase)** 사용. `_`(스네이크)는 쓸 수 있지만 `-`(케밥)는 자바 식별자 규칙상 사용 불가 |

- 함수를 "잘라낸다"는 건 **다른 파일로 분리한다는 뜻이 아니다** — `main` 함수 바깥, `main`과 동급인 위치로 옮기는 것을 뜻한다 (다른 파일로 분리하는 것도 가능하지만, 지금 단계에서는 `main` 아래로 "분가"시키는 정도)
- `main`에서 넘겨줄 데이터가 있으면 **매개변수**로 전달해야 한다 — 수학 함수에 `x` 값을 넣어주듯, 어떤 값을 어떤 형식으로 넘길지 결정해야 함

## 5. 예시 — 두 수를 더해서 출력하는 함수로 분리하기

값을 초기화하고, 합을 구하고, 그 결과를 출력하는 흐름에서 **"출력" 부분만 함수로 떼어낸** 예시.

```java
public class Code {
    public static void main(String[] args) {
        int x, y, sum;

        // 값을 초기화하고
        x = 3;
        y = 4;

        // 합을 구한 뒤
        sum = x + y;

        // 결과를 출력하는 부분만 함수로 분리
        printSum(sum);
    }

    // public static 반환타입(없으면 void) 함수명(매개변수) { ... }
    public static void printSum(int sum) {
        System.out.printf("sum is %d\n", sum);
        // 매개변수 이름은 자유지만, sum 값을 담으니 sum으로 맞춰주는 게 읽기 좋다
    }
}
```

- `main`에는 "합을 구한 뒤 `printSum`을 호출한다"는 흐름만 남고, **출력 방식의 세부사항은 `printSum` 안으로 숨겨진다**
- `printSum(int sum)`처럼 함수명 자체가 "합을 출력하는 함수"라는 역할을 그대로 드러낸다 (행위명 + 재료명)
- 매개변수 `int sum`에서 `int`처럼 **자료형을 반드시 함께 선언**해야 한다 — 자바는 매개변수마다 어떤 타입의 값을 받을지 미리 정해두는 **정적 타입 언어**라서, `printSum(sum)`처럼 타입 없이 이름만 쓰면 컴파일 에러가 난다. 호출하는 쪽(`printSum(sum)`)에서 넘기는 값의 타입과 이 선언된 타입이 일치해야 한다
- 이후 출력 형식을 바꾸고 싶으면 `main`을 건드릴 필요 없이 `printSum` 내부만 수정하면 된다 — 이것이 앞서 말한 "복잡도가 낮아진다"는 것의 실제 예시
