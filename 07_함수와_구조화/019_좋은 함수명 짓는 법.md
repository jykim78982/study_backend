# 좋은 함수명(메서드명) 짓는 법

## 1. 기본 형식 — 동사로 시작 + 카멜케이스

함수(메서드)는 **"무언가를 하는 행동"**이므로, 이름도 동사로 시작하는 게 자연스럽다.

- **카멜케이스(camelCase)**: 첫 단어는 소문자로 시작하고, 이후 단어의 첫 글자만 대문자로

```java
power(int x)            // ❌ 명사라서 뭘 하는 함수인지 모름
calculatePower(int x)   // ✅ "power를 계산한다"가 바로 보임
```

## 2. 자주 쓰는 동사 접두어 표

이 패턴을 알아두면 남의 코드를 읽을 때도 이름만 보고 짐작할 수 있고, 내가 지을 때도 편해진다.

| 접두어 | 의미 | 예시 |
|---|---|---|
| `get` | 값을 꺼내온다 (반환) | `getName()`, `getSum()` |
| `set` | 값을 설정/변경한다 | `setName(String n)` |
| `is` / `has` | true/false를 반환한다 (질문형) | `isEven(int x)`, `hasError()` |
| `calculate` / `compute` | 계산해서 결과를 만든다 | `calculateArea()`, `computeTotal()` |
| `print` | 화면에 출력한다 (보통 `void`) | `printResult(int x)` |
| `make` / `create` | 새로운 걸 만들어낸다 | `createExam()`, `makeReport()` |
| `add` / `remove` | 추가하거나 제거한다 | `addItem()`, `removeUser()` |
| `find` / `search` | 뭔가를 찾아서 돌려준다 | `findMax(int[] arr)` |
| `convert` / `to` | 형태를 바꾼다 | `convertToInt()`, `toUpperCase()` |
| `check` / `validate` | 조건을 검사한다 | `checkValid()`, `validateInput()` |
| `update` | 기존 값을 갱신한다 | `updateScore()` |

> **핵심**: 함수명은 다른 사람(그리고 3개월 뒤의 나)이 읽었을 때, 이름만 보고도 뭘 하는 함수인지 알 수 있어야 한다.

## 3. 예시

```java
power(int x)              // ❌ 명사라서 "계산해라"는 행동이 안 보임
calculatePower(int x)     // ✅

func1();
test2();                  // ❌ 무슨 일을 하는지 전혀 알 수 없음

printReceipt();
validateEmail();          // ✅

doStuff();                 // ❌ 너무 애매하고 포괄적임

sendEmail();
saveFile();                // ✅

// ❌ 이름 하나에 너무 많은 역할이 들어감 (함수가 너무 많은 일을 함)
getUserInfoAndSaveToDbAndSendEmail();

// ✅ 역할별로 쪼개기
getUserInfo();
saveToDb();
sendEmail();

int n(int x) { ... }       // ❌ 함수 이름으로는 의미 없음 (매개변수 이름이면 괜찮음)
int calculateAge(int x) { ... }   // ✅
```

## 4. 문법적으로 반드시 지켜야 하는 규칙 (안 지키면 컴파일 에러)

- 반환 타입이 `boolean`인 함수는 이름이 **질문 형태**가 되도록 짓는 게 관례다. 특히 `is` / `has`는 꼭 지키는 게 좋다.

  ```java
  boolean isEven(int x) { ... }   // "이게 짝수인가?" → 자연스러움
  boolean even(int x) { ... }     // ❌ 뭘 묻는 건지 애매함
  ```

  boolean처럼 **반환 타입이 이름 형태를 결정**하는 경우가 몇 가지 더 있다. 아래는 컴파일 강제 규칙은 아니지만, 자바 표준 라이브러리 전반에서 널리 지켜지는 관례들이다.

  - **`Comparable<T>`의 `compareTo()`**: 두 객체의 대소를 비교해서 `int`(음수/0/양수)를 반환하는 메서드는, `Comparable` 인터페이스를 구현할 때 이름 자체가 `compareTo()`로 고정된다(인터페이스 규약). 이름만 보면 "비교해서 정수를 준다"는 의미가 바로 안 드러나지만, 자바 생태계 전체가 이 이름을 약속으로 쓰기 때문에 `int compareTo(Object o)`를 보면 다들 "정렬 기준값을 반환하는구나"라고 이해한다.

    ```java
    class Student implements Comparable<Student> {
        int score;
        @Override
        public int compareTo(Student other) {
            return this.score - other.score;   // 음수면 작음, 0이면 같음, 양수면 큼
        }
    }
    ```

  - **`equals()`, `hashCode()`, `toString()`**: 자바에는 모든 클래스가 기본으로 물려받는 몇 가지 "미리 이름이 정해진 기능"이 있다 — "이 객체를 글자로 보여줘"(`toString`), "이 둘이 같은 값인지 비교해줘"(`equals`) 같은 것들이다. 문제는 그 기본 기능이 마음에 안 들 때인데, 이럴 때 **이름을 반드시 똑같이 맞춰서** 내 방식대로 다시 작성해야(=오버라이드) 자바가 "아, 이게 그 기능을 대신하는 거구나"라고 알아챈다. 예를 들어 `System.out.println(student)`를 실행하면 자바는 내부적으로 딱 `toString()`이라는 이름을 찾아서 호출한다. 그래서 `equals()`가 `boolean`을 반환한다고 해서 이름을 `isEqual()`처럼 바꿔버리면, 자바 입장에선 "내가 알던 그 기능"이 아니라 그냥 아무 상관 없는 새 함수를 만든 것이 되어버려서 원래 기대한 대로 동작하지 않는다.

    ```java
    @Override
    public boolean equals(Object o) { ... }   // ✅ 이 이름이어야 "같은 값인지 비교" 기능으로 인정됨
    public boolean isEqual(Object o) { ... }  // ❌ 이름이 다르면 그냥 별개의 새 함수일 뿐
    ```

  - **`of()`, `from()`, `valueOf()`**: `new`를 안 쓰고도 객체를 하나 만들어서 건네주는 함수들에 자주 붙는 이름이다. 마치 "이 재료들로 하나 만들어 주는" 자판기 같은 함수라고 생각하면 된다. `create`라고 지어도 틀린 건 아니지만, 최근 자바 코드에서는 관례적으로 `of`(여러 값을 모아서 하나로), `from`(다른 형태에서 바꿔서), `valueOf`(문자열 등에서 값으로) 중 상황에 맞는 걸 골라 쓴다.

    ```java
    List<String> names = List.of("kim", "lee");     // of: 값 여러 개를 모아서 만들어줌
    LocalDate date = LocalDate.from(temporal);        // from: 다른 걸 이 형태로 바꿔서 만들어줌
    Integer num = Integer.valueOf("42");              // valueOf: 문자열 같은 걸 값으로 바꿔서 만들어줌
    ```

  - **`Optional<T>` 반환 (`find`, `tryParse`류)**: 찾는 게 항상 있으리라는 보장이 없을 때 쓰는 패턴이다. 예를 들어 학생 명단에서 특정 ID로 찾을 때, 그 ID가 없는 학생일 수도 있다. 이럴 때 그냥 `getById()`라고 지으면 "당연히 있다"는 뉘앙스라, 없을 경우 프로그램이 갑자기 에러로 멈춰버릴 수 있다. 대신 `find`나 `try`를 붙이면 "찾아봤는데 없을 수도 있어요"라는 의미가 이름에서부터 전달돼서, 이 함수를 쓰는 사람이 "없는 경우"도 미리 대비하게 만들어준다.

    ```java
    Optional<Student> findById(int id) { ... }   // 없으면 "찾았지만 없음" 상태(Optional.empty())를 돌려줌
    Optional<Integer> tryParseInt(String s) { ... }  // 숫자로 못 바꾸면 에러 대신 "없음" 상태를 돌려줌
    ```

- 숫자로 시작할 수 없음 (`1power` ❌, `power1` ✅)
- 공백이나 특수문자(`-`, `@`, `!` 등) 사용 불가 (`_`, `$`만 예외적으로 허용)
- 자바 예약어(`class`, `int`, `return`, `if` 등) 사용 불가

이 규칙은 **강제 사항**이고, 앞서 다룬 "동사로 시작", "카멜케이스" 등은 **관례**(강제는 아니지만 다들 지키는 약속)다.

## 5. 한 줄 요약

> 함수 이름만 읽고도 "이 함수가 뭘 하는지" 유추할 수 있어야 한다. 그러려면 (1) 동사로 시작하고 (2) 구체적으로 짓고 (3) 함수가 하는 일을 하나로 압축할 수 있을 만큼 함수 자체도 단순하게 유지하는 게 좋다. 이름 짓기가 어렵다면, 오히려 **"이 함수가 너무 많은 일을 하고 있어서 한 마디로 표현이 안 되는 건 아닌지"** 의심해보는 것도 좋은 신호다.
